# Các Phạm Vi Truy Cập: public Và private

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: vì sao cần giới hạn quyền truy cập vào thuộc tính và phương thức của một lớp — bảo vệ dữ liệu khỏi bị sửa đổi sai cách từ bên ngoài.
- Nắm vững cú pháp: `public` (truy cập được từ bên ngoài lớp) và `private` (chỉ truy cập được từ bên trong lớp).
- Hiểu được điều quan trọng: các phương thức bên trong lớp luôn có thể truy cập tự do vào thuộc tính `private` của chính lớp đó.
- Ứng dụng được `private` để kiểm soát dữ liệu hợp lệ, ngăn chặn việc gán giá trị sai cách trực tiếp từ bên ngoài.

## 2. Giới Thiệu

Ở các bài trước, mọi thuộc tính bạn khai báo đều nằm dưới từ khóa `public:` — có nghĩa là bất kỳ đoạn code nào bên ngoài lớp cũng có thể tự do đọc và sửa chúng, không có bất kỳ ràng buộc gì. Nhưng điều này tiềm ẩn một rủi ro lớn: điều gì sẽ xảy ra nếu ai đó (hoặc chính bạn, trong một lúc sơ suất) gán một giá trị vô lý cho thuộc tính — ví dụ đặt số dư tài khoản thành một số âm?

Đây chính là lúc từ khóa `private` phát huy tác dụng: nó cho phép bạn "khóa" một số thuộc tính hoặc phương thức, chỉ cho phép các phương thức **bên trong chính lớp đó** truy cập, còn thế giới bên ngoài hoàn toàn không thể chạm vào trực tiếp. Đây là bước đệm quan trọng để tiến tới khái niệm **Tính đóng gói (Encapsulation)** — một trong bốn trụ cột của lập trình hướng đối tượng, sẽ được học kỹ ở bài tiếp theo.

## 3. Khái Niệm

- `public`: từ khóa đánh dấu các thành viên (thuộc tính, phương thức) có thể được truy cập **tự do** từ bất kỳ đâu, kể cả từ bên ngoài lớp.
- `private`: từ khóa đánh dấu các thành viên chỉ có thể được truy cập từ **bên trong chính lớp đó** (các phương thức của lớp) — hoàn toàn không thể truy cập trực tiếp từ bên ngoài.
- **Phạm vi truy cập mặc định**: nếu không ghi rõ `public:` hay `private:`, một `class` sẽ mặc định coi mọi thành viên là `private`; ngược lại, `struct` (một cấu trúc gần giống `class`) mặc định coi mọi thành viên là `public`.

## 4. Giải Thích

### 4.1. Truy Cập Thuộc Tính public

```cpp
class HocSinh {
public:
    string ten;
    int tuoi;
};

HocSinh hs;
hs.ten = "An";   // OK - vì ten là public
```

### 4.2. Giới Hạn Truy Cập Với private

```cpp
class HocSinh {
private:
    string ten;
    int tuoi;
};

HocSinh hs;
hs.ten = "An";   // LỖI - ten là private, không thể truy cập từ bên ngoài
```

### 4.3. Phương Thức Bên Trong Lớp Vẫn Truy Cập Được private

Điều quan trọng cần hiểu: giới hạn `private` chỉ áp dụng cho code **bên ngoài** lớp — các phương thức được định nghĩa **bên trong** chính lớp đó (dù được khai báo `public`) vẫn có quyền truy cập đầy đủ vào mọi thuộc tính `private`, không bị hạn chế gì cả.

## 5. Ví Dụ

Các output và thông báo lỗi dưới đây được lấy từ lần biên dịch, chạy thử thực tế (thông báo lỗi theo g++). Ở các ví dụ có dùng `string`, `cout`, chương trình đầy đủ cần thêm `#include <iostream>`, `#include <string>` và `using namespace std;` ở đầu.

### Ví dụ 1: Truy cập thuộc tính public từ bên ngoài (Mục tiêu: ôn lại hành vi đã quen thuộc)

```cpp
#include <iostream>
#include <string>
using namespace std;

class HocSinh {
public:
    string ten;
    int tuoi;
};

int main() {
    HocSinh hs;
    hs.ten = "An";
    hs.tuoi = 16;
    cout << hs.ten << ", " << hs.tuoi << endl;
    return 0;
}
```

**Output đã kiểm chứng:**

```
An, 16
```

### Ví dụ 2: Lỗi khi cố truy cập thuộc tính private từ bên ngoài (Mục tiêu: hiểu rõ giới hạn của private)

```cpp
#include <iostream>
#include <string>
using namespace std;

class HocSinh {
private:
    string ten;
    int tuoi;
};

int main() {
    HocSinh hs;
    hs.ten = "An";   // Cố truy cập thuộc tính private
    return 0;
}
```

**Thông báo lỗi biên dịch thực tế:**

```
error: 'std::string HocSinh::ten' is private within this context
```

### Ví dụ 3: Phương thức bên trong lớp vẫn truy cập được thuộc tính private (Mục tiêu: hiểu giới hạn chỉ áp dụng từ bên ngoài)

```cpp
#include <iostream>
#include <string>
using namespace std;

class HocSinh {
private:
    string ten;
    int tuoi;

public:
    void ganTen(string t) {
        ten = t;   // Phương thức bên trong lớp vẫn truy cập được thuộc tính private
    }
    void ganTuoi(int t) {
        tuoi = t;
    }
    void inThongTin() {
        cout << "Ten: " << ten << ", Tuoi: " << tuoi << endl;
    }
};

int main() {
    HocSinh hs;
    hs.ganTen("Nguyen Van An");
    hs.ganTuoi(16);
    hs.inThongTin();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Ten: Nguyen Van An, Tuoi: 16
```

Dù `ten` và `tuoi` là `private`, các phương thức `ganTen()`, `ganTuoi()`, `inThongTin()` (được khai báo `public`, nhưng nằm **bên trong** lớp `HocSinh`) vẫn hoàn toàn tự do đọc/ghi chúng — người dùng bên ngoài chỉ có thể tương tác với dữ liệu này **thông qua** các phương thức `public` này, không thể "chạm" trực tiếp vào `ten` hay `tuoi`.

### Ví dụ 4: Lợi ích thực tế của private — kiểm soát dữ liệu hợp lệ (Mục tiêu: thấy giá trị thực sự của việc giới hạn truy cập)

```cpp
#include <iostream>
using namespace std;

class TaiKhoan {
private:
    double soDu;

public:
    void ganSoDu(double giaTri) {
        if (giaTri < 0) {
            cout << "Loi: So du khong the am! Tu dong dat ve 0." << endl;
            soDu = 0;
        } else {
            soDu = giaTri;
        }
    }
    double laySoDu() {
        return soDu;
    }
};

int main() {
    TaiKhoan tk;
    tk.ganSoDu(-500000);
    cout << "So du hien tai: " << tk.laySoDu() << endl;

    tk.ganSoDu(100000);
    cout << "So du hien tai: " << tk.laySoDu() << endl;
    return 0;
}
```

**Output đã kiểm chứng:**

```
Loi: So du khong the am! Tu dong dat ve 0.
So du hien tai: 0
So du hien tai: 100000
```

Vì `soDu` là `private`, không ai có thể gán trực tiếp `tk.soDu = -500000;` từ bên ngoài (trình biên dịch sẽ báo `error: 'double TaiKhoan::soDu' is private within this context`) — mọi thay đổi **buộc phải** đi qua phương thức `ganSoDu()`, nơi có logic kiểm tra và ngăn chặn giá trị âm vô lý. Nếu `soDu` là `public`, hoàn toàn không có cách nào ngăn được việc gán một giá trị âm trực tiếp.

### Ví dụ 5: Phạm vi truy cập mặc định — class khác struct (Mục tiêu: hiểu quy tắc mặc định khi không ghi rõ)

```cpp
class ViDu {
    int giaTri;   // KHÔNG ghi rõ public/private -> mặc định là PRIVATE trong class
};

int main() {
    ViDu vd1;
    vd1.giaTri = 10;   // Thử truy cập
    return 0;
}
```

**Thông báo lỗi biên dịch thực tế:**

```
error: 'int ViDu::giaTri' is private within this context
```

Nếu đổi `class` thành `struct` (một cấu trúc dữ liệu tương tự `class`, thường dùng cho dữ liệu đơn giản), cùng đoạn code sẽ biên dịch được, vì thành viên của `struct` mặc định là `public`:

```cpp
struct ViDu {
    int giaTri;   // Không ghi rõ -> mặc định là PUBLIC trong struct
};

int main() {
    ViDu vd1;
    vd1.giaTri = 10;   // OK
    return 0;
}
```

Đây là một quy tắc dễ bị bỏ qua: nếu không ghi rõ `public:` hay `private:` ngay sau khi mở `class`, mọi thành viên sẽ **tự động** được coi là `private`.

### Xem phạm vi truy cập từng bước

Mô phỏng dưới đây vẽ mỗi lớp thành hai phòng (`private` có ổ khóa, `public` có cửa mở) và hiện kết quả của từng lần truy cập. Bấm **Bước tiếp** để chạy từng dòng code và để ý những điều mà chữ khó diễn tả:

- Tab **Ai vào được private?**: mỗi lần truy cập có một thẻ riêng, đỏ "bị chặn" hoặc xanh "được phép". Dòng `hs.ten = "An";` từ `main()` bị chặn ngay lúc biên dịch nên chưa có dòng nào chạy. Còn khi `main()` nhờ `ganTen()` làm giúp, có hai thẻ xanh nối nhau: `main()` vào cửa public, rồi `ganTen()` vào `ten` từ bên trong lớp.
- Tab **private ép đi qua kiểm tra**: trạm kiểm tra là một cái đèn nằm trong `ganSoDu()`. Gán thẳng `tk.soDu` thì bị chặn trước khi tới trạm, còn `-500000` đi qua cửa public thì đèn đỏ và `soDu` về 0. Không có đường nào vòng qua đèn.
- Tab **class và struct**: cùng cách gán `giaTri = 10`, phòng của `class` đỏ (private) còn phòng của `struct` xanh (public).

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Quên khai báo `public:` cho các phương thức cần dùng từ bên ngoài**: nếu vô tình để tất cả nằm dưới `private:` (hoặc quên hẳn không ghi từ khóa nào, mặc định thành private), người dùng bên ngoài sẽ không thể gọi bất kỳ phương thức nào của đối tượng — kể cả những phương thức nên công khai.
- **Nhầm lẫn phạm vi mặc định giữa `class` và `struct`**: đây là lỗi rất dễ mắc khi mới học (xem lại Ví dụ 5) — nếu bạn dùng `class` mà quên ghi `public:`, mọi thứ sẽ mặc định `private`, khác với thói quen có thể đã quen từ việc dùng `struct`.
- **Đặt tất cả thuộc tính là `public` chỉ vì tiện lợi khi viết code**: dù `public` giúp code nhanh gọn hơn khi viết (không cần thêm phương thức truy cập), nó bỏ lỡ hoàn toàn lợi ích kiểm soát dữ liệu đã minh chứng ở Ví dụ 4 — đây là lý do bài tiếp theo sẽ giới thiệu mẫu thiết kế Getter/Setter, kết hợp cả tính an toàn của `private` và sự tiện lợi khi truy cập dữ liệu.
- **Nghĩ rằng `private` ngăn cả các phương thức trong cùng lớp truy cập thuộc tính**: đây là hiểu lầm phổ biến — giới hạn `private` chỉ áp dụng với code **bên ngoài** lớp, các phương thức bên trong lớp (như Ví dụ 3) luôn có quyền truy cập đầy đủ.
- **Đặt các thành viên private ở vị trí không hợp lý trong lớp**: dù về mặt kỹ thuật, C++ cho phép đặt nhiều khối `public:`/`private:` xen kẽ nhau trong một lớp, quy ước phổ biến và dễ đọc hơn là gom các thuộc tính `private` lại trước, rồi đặt các phương thức `public` sau (hoặc ngược lại), giúp người đọc dễ nắm được cấu trúc tổng thể của lớp.
