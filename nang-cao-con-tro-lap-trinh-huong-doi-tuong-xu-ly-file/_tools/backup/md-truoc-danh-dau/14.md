# Tại Sao Cần Kế Thừa? Tư Duy Tái Sử Dụng Trong OOP

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: nhận diện vấn đề lặp code khi có nhiều lớp mang nhiều điểm chung với nhau.
- Thấy được giải pháp: **Kế thừa (Inheritance)** cho phép một lớp tái sử dụng thuộc tính và phương thức đã có sẵn từ một lớp khác.
- Nắm vững khái niệm: **lớp cha (Base Class / Parent Class)** và **lớp con (Derived Class / Child Class)**.
- Hiểu được lợi ích cốt lõi: sửa một chỗ duy nhất ở lớp cha, mọi lớp con đều tự động được cập nhật — đúng tinh thần DRY đã học ở phần Hàm.

## 2. Giới Thiệu

Hãy tưởng tượng bạn cần quản lý cả **Học sinh** và **Sinh viên** trong cùng một chương trình. Cả hai đều có tên, tuổi, và đều cần một phương thức để tự giới thiệu bản thân — sự khác biệt duy nhất chỉ là Học sinh có "trường cấp 3", còn Sinh viên có "trường đại học". Nếu viết hai lớp hoàn toàn độc lập, bạn sẽ phải viết lại `ten`, `tuoi`, và phương thức `gioiThieu()` đến **hai lần** — một sự lặp lại không cần thiết, và nếu sau này cần sửa logic giới thiệu, bạn phải nhớ sửa ở **cả hai nơi**.

Đây chính là vấn đề mà **Kế thừa (Inheritance)** ra đời để giải quyết — một trong bốn trụ cột quan trọng của lập trình hướng đối tượng. Ý tưởng cốt lõi: hãy gom những gì **chung** vào một lớp "cha", rồi để các lớp "con" **tự động thừa hưởng** toàn bộ những gì đã có ở lớp cha, chỉ cần bổ sung thêm những gì thực sự riêng biệt của chúng.

## 3. Khái Niệm

- **Kế thừa (Inheritance)**: cơ chế cho phép một lớp (lớp con) tự động có được toàn bộ thuộc tính và phương thức của một lớp khác (lớp cha), mà không cần viết lại.
- **Lớp cha (Base Class / Parent Class)**: lớp chứa những thuộc tính và phương thức **chung**, được thiết kế để các lớp khác kế thừa từ nó.
- **Lớp con (Derived Class / Child Class)**: lớp được tạo ra bằng cách kế thừa từ một lớp cha — tự động có đầy đủ mọi thứ từ lớp cha, và có thể bổ sung thêm thuộc tính/phương thức riêng của chính nó.

## 4. Giải Thích

### 4.1. Vấn Đề: Lặp Code Giữa Các Lớp Có Nhiều Điểm Chung

Khi hai lớp (như `HocSinh` và `SinhVien`) có nhiều thuộc tính và phương thức giống hệt nhau, viết chúng như hai lớp hoàn toàn độc lập sẽ dẫn đến việc lặp lại code không cần thiết — vi phạm đúng nguyên tắc DRY đã học ở phần Hàm.

### 4.2. Giải Pháp: Gom Cái Chung Vào Lớp Cha

Thay vì viết `ten`, `tuoi`, `gioiThieu()` ở cả hai lớp, ta tạo một lớp cha (ví dụ `NguoiHoc`) chứa những thứ chung này, rồi để `HocSinh` và `SinhVien` **kế thừa** từ nó. Cú pháp cơ bản nhất (sẽ học chi tiết ở bài tiếp theo):

```cpp
class SinhVien : public NguoiHoc {
    // Chỉ cần viết thêm những gì RIÊNG của SinhVien
};
```

Kế thừa thể hiện quan hệ **"là một"**: `SinhVien` là một `NguoiHoc`, nên việc để `SinhVien` kế thừa từ `NguoiHoc` là hợp lý.

### 4.3. Lợi Ích: Sửa Một Chỗ, Cập Nhật Mọi Nơi

Vì `HocSinh` và `SinhVien` đều kế thừa `gioiThieu()` từ `NguoiHoc`, nếu bạn cần cải tiến lời giới thiệu, bạn chỉ cần sửa **đúng một chỗ** — bên trong lớp cha `NguoiHoc` — và cả hai lớp con đều tự động nhận được sự thay đổi đó, không cần sửa từng lớp riêng lẻ.

## 5. Ví Dụ

Các output dưới đây được lấy từ lần biên dịch, chạy thử thực tế.

### Ví dụ 1: Vấn đề — hai lớp riêng biệt lặp lại gần như toàn bộ code (Mục tiêu: nhận diện vấn đề cần giải quyết)

```cpp
#include <iostream>
#include <string>
using namespace std;

class HocSinh {
public:
    string ten;
    int tuoi;
    void gioiThieu() {
        cout << "Toi ten la " << ten << ", " << tuoi << " tuoi." << endl;
    }
};

class SinhVien {   // LẶP LẠI gần như y hệt code của HocSinh!
public:
    string ten;
    int tuoi;
    void gioiThieu() {
        cout << "Toi ten la " << ten << ", " << tuoi << " tuoi." << endl;
    }
    string truongDaiHoc;   // Chỉ có thêm 1 thuộc tính riêng
};

int main() {
    HocSinh hs;
    hs.ten = "An";
    hs.tuoi = 16;
    hs.gioiThieu();

    SinhVien sv;
    sv.ten = "Binh";
    sv.tuoi = 20;
    sv.gioiThieu();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Toi ten la An, 16 tuoi.
Toi ten la Binh, 20 tuoi.
```

Dù chương trình vẫn chạy đúng, cấu trúc code này chứa sự lặp lại rõ ràng — cả `ten`, `tuoi`, lẫn toàn bộ nội dung của `gioiThieu()` đều được viết lại y hệt ở `SinhVien`, dù nó gần như giống hoàn toàn `HocSinh`.

### Ví dụ 2: Giải pháp — dùng kế thừa để loại bỏ trùng lặp (Mục tiêu: thấy rõ giải pháp hoạt động)

```cpp
#include <iostream>
#include <string>
using namespace std;

class NguoiHoc {
public:
    string ten;
    int tuoi;
    void gioiThieu() {
        cout << "Toi ten la " << ten << ", " << tuoi << " tuoi." << endl;
    }
};

class SinhVien : public NguoiHoc {   // KẾ THỪA từ NguoiHoc
public:
    string truongDaiHoc;   // Chỉ cần thêm phần RIÊNG của SinhVien
};

int main() {
    SinhVien sv;
    sv.ten = "Binh";
    sv.tuoi = 20;
    sv.truongDaiHoc = "Bach Khoa";

    sv.gioiThieu();   // Kế thừa phương thức từ NguoiHoc
    return 0;
}
```

**Output đã kiểm chứng:**

```
Toi ten la Binh, 20 tuoi.
```

Dù `SinhVien` không hề tự viết `ten`, `tuoi`, hay `gioiThieu()`, nó vẫn sử dụng được đầy đủ — nhờ kế thừa từ `NguoiHoc`. Lớp `SinhVien` chỉ cần tập trung khai báo phần thực sự riêng của nó: `truongDaiHoc`.

### Ví dụ 3: Lợi ích cốt lõi — sửa một chỗ ở lớp cha, mọi lớp con tự động cập nhật (Mục tiêu: thấy rõ giá trị thực sự của kế thừa)

```cpp
#include <iostream>
#include <string>
using namespace std;

class NguoiHoc {
public:
    string ten;
    int tuoi;
    // Cải tiến lời giới thiệu - CHỈ SỬA DUY NHẤT Ở ĐÂY
    void gioiThieu() {
        cout << "Xin chao! Toi ten " << ten << ", nam nay " << tuoi << " tuoi." << endl;
    }
};

class HocSinh : public NguoiHoc {
public:
    string truongCap3;
};

class SinhVien : public NguoiHoc {
public:
    string truongDaiHoc;
};

int main() {
    HocSinh hs;
    hs.ten = "An"; hs.tuoi = 16;
    hs.gioiThieu();

    SinhVien sv;
    sv.ten = "Binh"; sv.tuoi = 20;
    sv.gioiThieu();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Xin chao! Toi ten An, nam nay 16 tuoi.
Xin chao! Toi ten Binh, nam nay 20 tuoi.
```

Cả `HocSinh` và `SinhVien` đều tự động dùng lời giới thiệu **mới** (`"Xin chao! Toi ten..."`) mà không cần sửa bất kỳ dòng code nào trong hai lớp con — chỉ cần cập nhật đúng một chỗ duy nhất tại lớp cha `NguoiHoc`. Đây chính là bằng chứng rõ ràng nhất cho lợi ích "sửa một chỗ, cập nhật mọi nơi" của kế thừa.

### Ví dụ 4: Lớp con vẫn có thể bổ sung thêm phương thức hoàn toàn riêng (Mục tiêu: hiểu kế thừa không giới hạn khả năng mở rộng)

```cpp
#include <iostream>
#include <string>
using namespace std;

class NguoiHoc {
public:
    string ten;
    int tuoi;
    void gioiThieu() {
        cout << "Toi ten la " << ten << ", " << tuoi << " tuoi." << endl;
    }
};

class SinhVien : public NguoiHoc {
public:
    string truongDaiHoc;

    // Phương thức RIÊNG, chỉ SinhVien có, HocSinh sẽ KHÔNG có
    void thongBaoTotNghiep() {
        cout << ten << " sap tot nghiep truong " << truongDaiHoc << "!" << endl;
    }
};

int main() {
    SinhVien sv;
    sv.ten = "Binh"; sv.tuoi = 22; sv.truongDaiHoc = "Bach Khoa";

    sv.gioiThieu();            // Kế thừa từ NguoiHoc
    sv.thongBaoTotNghiep();    // Riêng của SinhVien
    return 0;
}
```

**Output đã kiểm chứng:**

```
Toi ten la Binh, 22 tuoi.
Binh sap tot nghiep truong Bach Khoa!
```

`SinhVien` không chỉ "thừa hưởng" từ `NguoiHoc` mà còn có thể **mở rộng thêm** những khả năng hoàn toàn mới của riêng nó (`thongBaoTotNghiep()`) — kế thừa không hề giới hạn lớp con chỉ được dùng những gì lớp cha đã có.

### Xem việc gom lớp cha từng bước

Mô phỏng dưới đây vẽ các lớp thành sơ đồ, mũi tên tam giác rỗng chỉ từ lớp con lên lớp cha, kèm bộ đếm số dòng lặp. Bấm **Bước tiếp** để chạy từng dòng code và để ý những điều mà chữ khó diễn tả:

- Tab **Viết lặp ở hai lớp**: các dòng `ten`, `tuoi`, `gioiThieu()` của hai hộp lớp được tô vàng giống nhau, và bộ đếm báo 6 dòng trùng lặp, 2 bản `gioiThieu()`.
- Tab **Gom lên lớp cha**: lớp `NguoiHoc` xuất hiện ở trên, hai mũi tên kế thừa chỉ lên nó, và bộ đếm giảm còn 1 bản, 0 dòng lặp. Khi gọi `sv.gioiThieu()`, kính lúp tìm ở `SinhVien` không thấy, rồi đi lên `NguoiHoc` thì thấy.
- Tab **Sửa một chỗ ở lớp cha**: sau khi đổi câu trong `NguoiHoc`, cả `hs.gioiThieu()` lẫn `sv.gioiThieu()` đều đi lên lớp cha và in câu mới. Bộ đếm cuối so sánh: không kế thừa phải sửa 2 nơi, có kế thừa chỉ sửa 1 nơi.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Viết nhiều lớp riêng biệt dù chúng có rất nhiều điểm chung**: đây chính là "mùi code" (code smell) cần chú ý — nếu bạn thấy mình đang sao chép gần như nguyên vẹn thuộc tính/phương thức từ lớp này sang lớp khác, đó là dấu hiệu rõ ràng nên cân nhắc dùng kế thừa.
- **Nhầm lẫn thứ tự lớp cha - lớp con**: lớp cha nên chứa những gì **tổng quát, chung nhất** (ví dụ `NguoiHoc`), còn lớp con chứa những gì **cụ thể, đặc thù hơn** (ví dụ `SinhVien`, `HocSinh`) — viết ngược lại (lớp con lại tổng quát hơn lớp cha) là một lỗi thiết kế phổ biến.
- **Cố nhét mọi thứ vào lớp cha, kể cả những gì chỉ một lớp con cần dùng**: chỉ nên đưa vào lớp cha những thuộc tính/phương thức **thực sự chung** cho tất cả lớp con — những gì đặc thù riêng (như `truongDaiHoc` chỉ `SinhVien` cần) nên để lại đúng trong lớp con tương ứng.
- **Đánh giá thấp lợi ích bảo trì lâu dài của kế thừa**: giống như lợi ích của hàm và Getter/Setter đã học trước đó, giá trị thực sự của kế thừa thể hiện rõ nhất khi chương trình phát triển lớn hơn — càng nhiều lớp con dùng chung một lớp cha, việc sửa lỗi hoặc cải tiến tại một điểm duy nhất càng tiết kiệm công sức hơn nhiều lần.
- **Nghĩ rằng kế thừa chỉ đơn thuần là "sao chép" code từ lớp cha sang lớp con**: về bản chất, lớp con không hề "sao chép" code — đối tượng của lớp con chứa một "phần cha" bên trong và dùng chung cùng một định nghĩa với lớp cha; khi lớp cha thay đổi, mọi lớp con đều nhận thay đổi đó (như đã minh chứng ở Ví dụ 3). Lưu ý chương trình vẫn cần được biên dịch lại sau khi sửa, nhưng bạn chỉ phải sửa code ở một chỗ.
