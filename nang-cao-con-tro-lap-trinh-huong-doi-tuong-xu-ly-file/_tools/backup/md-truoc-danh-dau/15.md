# Cú Pháp Kế Thừa Trong C++

## 1. Mục Tiêu Bài Học

- Hiểu bản chất và nắm vững cú pháp cơ bản để khai báo một lớp kế thừa từ lớp khác: `class LopCon : public LopCha`.
- Hiểu được cách Constructor của lớp con liên kết với Constructor của lớp cha, cả tự động và khi cần gọi tường minh.
- Tránh được lỗi phổ biến: quên gọi tường minh Constructor của lớp cha khi lớp cha không có Constructor mặc định.
- Ứng dụng được vào việc tạo nhiều lớp con khác nhau từ cùng một lớp cha.
- Quan sát đối tượng lớp con được dựng thành hai phần (phần cha, phần con) bằng hoạt động mô phỏng.

## 2. Giới Thiệu

Ở bài trước, bạn đã hiểu **vì sao** cần kế thừa: để tránh lặp code giữa các lớp có nhiều điểm chung. Bài này đi vào chi tiết **cách viết** cú pháp kế thừa trong C++, cùng với một chi tiết quan trọng thường bị bỏ qua: khi lớp con được tạo ra, Constructor của lớp cha được xử lý như thế nào?

Đây là điểm cần đặc biệt lưu ý, vì nó liên quan trực tiếp đến kiến thức Constructor đã học ở phần Lớp & Đối tượng. Nếu không hiểu rõ, bạn rất dễ gặp những lỗi biên dịch khó hiểu khi bắt đầu viết các lớp kế thừa có Constructor tùy chỉnh.

## 3. Khái Niệm

- **Cú pháp kế thừa**: `class LopCon : public LopCha { ... };`. Dấu `:` theo sau bởi `public` và tên lớp cha, đặt ngay sau tên lớp con.
- **Gọi tường minh Constructor lớp cha**: cú pháp `LopCon(tham_so) : LopCha(tham_so_tuong_ung) { ... }`, chủ động chỉ định Constructor nào của lớp cha sẽ được gọi trước.
- **Thứ tự khởi tạo**: khi một đối tượng lớp con được tạo, Constructor của lớp cha **luôn được gọi trước**, rồi mới đến Constructor của lớp con.

## 4. Giải Thích

### 4.1. Cú Pháp Kế Thừa Cơ Bản

```cpp
class DongVat {
public:
    string ten;
    void an() { cout << ten << " dang an." << endl; }
};

class Cho : public DongVat {   // Cho KE THUA tu DongVat
public:
    void sua() { cout << ten << " sua: Gau gau!" << endl; }
};
```

Một đối tượng `Cho` gồm hai phần: phần của `DongVat` (`ten`, `an()`) và phần riêng của `Cho` (`giong`, `sua()`).

### 4.2. Constructor Tự Động Liên Kết Khi Lớp Cha Có Constructor Không Tham Số

Nếu lớp cha có Constructor không tham số (hoặc không viết Constructor nào, để C++ tự tạo Constructor mặc định), lớp con **không cần làm gì đặc biệt**: Constructor của lớp cha sẽ tự động được gọi trước Constructor của lớp con.

### 4.3. Gọi Tường Minh Constructor Của Lớp Cha

Nếu lớp cha **chỉ có** Constructor có tham số (không có Constructor không tham số), lớp con **bắt buộc** phải gọi tường minh đến đúng Constructor đó, bằng cú pháp:

```cpp
Cho(string tenBanDau, string giongBanDau) : DongVat(tenBanDau) {
    giong = giongBanDau;
}
```

Phần `: DongVat(tenBanDau)` chỉ định rõ Constructor nào của lớp cha sẽ được dùng, và giá trị nào sẽ được truyền vào đó.

## 5. Ví Dụ

Các output và thông báo lỗi dưới đây được lấy từ lần biên dịch và chạy thực tế.

### Ví dụ 1: Cú pháp kế thừa cơ bản (Mục tiêu: nắm cú pháp cơ bản nhất)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    string ten;
    void an() { cout << ten << " dang an." << endl; }
};

class Cho : public DongVat {
public:
    void sua() { cout << ten << " sua: Gau gau!" << endl; }
};

int main() {
    Cho c;
    c.ten = "Mi Lu";
    c.an();
    c.sua();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Mi Lu dang an.
Mi Lu sua: Gau gau!
```

### Ví dụ 2: Constructor lớp con tự động gọi Constructor mặc định của lớp cha (Mục tiêu: hiểu liên kết Constructor cơ bản)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    DongVat() { cout << "Constructor cua DongVat duoc goi" << endl; }
};

class Cho : public DongVat {
public:
    Cho() { cout << "Constructor cua Cho duoc goi" << endl; }
};

int main() {
    cout << "Bat dau tao doi tuong Cho..." << endl;
    Cho c;
    return 0;
}
```

**Output đã kiểm chứng:**

```
Bat dau tao doi tuong Cho...
Constructor cua DongVat duoc goi
Constructor cua Cho duoc goi
```

Dù không hề viết gì đặc biệt để "gọi" Constructor của `DongVat`, nó vẫn tự động chạy **trước** Constructor của `Cho`. Đây là hành vi mặc định của C++ khi lớp cha có Constructor không tham số.

### Ví dụ 3: Gọi tường minh Constructor có tham số của lớp cha (Mục tiêu: nắm cú pháp gọi tường minh)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    string ten;
    DongVat(string tenBanDau) {
        ten = tenBanDau;
        cout << "Da tao dong vat ten: " << ten << endl;
    }
};

class Cho : public DongVat {
public:
    string giong;
    Cho(string tenBanDau, string giongBanDau) : DongVat(tenBanDau) {
        giong = giongBanDau;
        cout << "Da tao cho giong: " << giong << endl;
    }
};

int main() {
    Cho c("Mi Lu", "Poodle");
    cout << "Ten: " << c.ten << ", Giong: " << c.giong << endl;
    return 0;
}
```

**Output đã kiểm chứng:**

```
Da tao dong vat ten: Mi Lu
Da tao cho giong: Poodle
Ten: Mi Lu, Giong: Poodle
```

Nhờ cú pháp `: DongVat(tenBanDau)`, Constructor của `Cho` chủ động truyền `tenBanDau` cho Constructor của `DongVat`, đảm bảo `ten` được khởi tạo đúng trước khi `Cho` xử lý phần riêng của nó (`giong`).

### Ví dụ 4: Lỗi, quên gọi tường minh khi lớp cha không có Constructor mặc định (Mục tiêu: tránh lỗi phổ biến nhất)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    string ten;
    DongVat(string tenBanDau) {   // CHI CO constructor co tham so
        ten = tenBanDau;
    }
};

class Cho : public DongVat {
public:
    string giong;
    Cho(string giongBanDau) {   // LOI: khong goi tuong minh DongVat(...)
        giong = giongBanDau;
    }
};

int main() {
    Cho c("Poodle");
    return 0;
}
```

**Thông báo lỗi biên dịch (g++):**

```
error: no matching function for call to 'DongVat::DongVat()'
note: candidate: 'DongVat::DongVat(std::string)'
note:   candidate expects 1 argument, 0 provided
```

Vì `Cho` không chỉ định gọi Constructor nào của `DongVat`, C++ tự động thử gọi Constructor **không tham số** của `DongVat`. Nhưng lớp này không có Constructor như vậy (chỉ có phiên bản nhận 1 tham số `string`), nên báo lỗi biên dịch. Đây chính là lý do bắt buộc phải gọi tường minh như Ví dụ 3.

### Ví dụ 5: Nhiều lớp con từ cùng một lớp cha (Mục tiêu: ứng dụng thực tế, mở rộng theo nhiều hướng)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    string ten;
    void an() { cout << ten << " dang an." << endl; }
};

class Cho : public DongVat {
public:
    void sua() { cout << ten << " sua: Gau gau!" << endl; }
};

class Meo : public DongVat {
public:
    void keu() { cout << ten << " keu: Meo meo!" << endl; }
};

int main() {
    Cho c;
    c.ten = "Mi Lu";
    c.an();
    c.sua();

    Meo m;
    m.ten = "Mun";
    m.an();
    m.keu();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Mi Lu dang an.
Mi Lu sua: Gau gau!
Mun dang an.
Mun keu: Meo meo!
```

Cả `Cho` và `Meo` đều kế thừa `ten` và `an()` từ `DongVat`, nhưng mỗi lớp mở rộng theo hướng riêng (`sua()` cho `Cho`, `keu()` cho `Meo`). Một lớp cha có thể là nền tảng cho nhiều lớp con khác nhau.

### Xem lớp con được dựng từng bước

Mô phỏng dưới đây vẽ đối tượng lớp con thành các **tầng**: tầng dưới là phần của lớp cha, tầng trên là phần của lớp con. Bấm **Bước tiếp** để chạy từng dòng code:

- Tab **Constructor cha chạy trước**: dòng `Cho c;` không nhắc tới `DongVat`, nhưng tầng `DongVat` vẫn được dựng trước, rồi mới tới tầng `Cho`.
- Tab **Gọi tường minh : DongVat(ten)**: giá trị `"Mi Lu"` đi qua lời gọi `: DongVat(tenBanDau)` xuống tầng dưới, `ten` được gán trước, rồi thân `Cho` mới gán `giong`.
- Tab **Lỗi thiếu gọi tường minh**: bảng cho thấy `DongVat` chỉ có `DongVat(string)` mà không có `DongVat()`, nên lời gọi tự động của C++ không tìm thấy gì và báo lỗi.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Quên gọi tường minh Constructor của lớp cha khi lớp cha không có Constructor mặc định**: đây là lỗi biên dịch phổ biến nhất khi mới học kế thừa có Constructor tùy chỉnh (xem lại Ví dụ 4). Hãy kiểm tra lớp cha có Constructor không tham số hay không trước khi quyết định có cần gọi tường minh.
- **Quên từ khóa `public` trong cú pháp kế thừa**: viết `class Cho : DongVat` (thiếu `public`) sẽ mặc định thành kế thừa `private`, khiến code bên ngoài không gọi được các thành viên thừa hưởng từ lớp cha (ví dụ `c.an()` trong `main()` báo lỗi truy cập).
- **Nhầm lẫn thứ tự gọi Constructor**: Constructor của lớp cha chạy **trước**, của lớp con chạy **sau** (như Ví dụ 2). Thứ tự này không thể đảo ngược, và sẽ được phân tích kỹ hơn ở bài về thứ tự Constructor trong kế thừa.
- **Viết sai vị trí lời gọi Constructor lớp cha**: `: TenLopCha(...)` phải đặt ngay sau danh sách tham số của Constructor lớp con, trước dấu `{`. Nếu viết `DongVat(t);` trong thân hàm, nó chỉ tạo một đối tượng tạm, không khởi tạo phần cha.
- **Nghĩ rằng lớp con phải truyền y hệt tham số cho Constructor lớp cha**: bạn hoàn toàn có thể xử lý, tính toán trước khi truyền, miễn là kiểu dữ liệu cuối cùng khớp với Constructor của lớp cha.
