# Ghi Đè Phương Thức (Method Overriding)

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: **Ghi đè phương thức (Method Overriding)** là lớp con định nghĩa lại một phương thức đã có ở lớp cha, với nội dung khác.
- Nắm vững cú pháp: định nghĩa lại phương thức cùng tên, cùng tham số trong lớp con.
- Ứng dụng kỹ thuật gọi lại phiên bản gốc của lớp cha khi cần, bằng cú pháp `TenLopCha::tenPhuongThuc()`.
- Hiểu một giới hạn quan trọng: ghi đè cơ bản (chưa dùng `virtual`) chỉ hoạt động đúng khi gọi trực tiếp qua đối tượng lớp con, không như mong đợi khi gọi qua con trỏ hoặc tham chiếu kiểu lớp cha.
- Quan sát cách C++ tìm và chọn phiên bản phương thức bằng hoạt động mô phỏng.

## 2. Giới Thiệu

Ở các bài trước, lớp con luôn kế thừa và dùng **y hệt** phương thức của lớp cha. Nhưng đôi khi lớp con cần một hành vi **khác** cho cùng một hành động. Ví dụ, mọi động vật đều "kêu", nhưng tiếng kêu của chó ("Gâu gâu") khác tiếng kêu chung chung của một động vật bất kỳ.

Đây là lúc **ghi đè phương thức** phát huy tác dụng: lớp con "viết lại" một phương thức đã kế thừa, thay nội dung cũ bằng logic riêng, mà vẫn giữ nguyên tên và cách gọi.

## 3. Khái Niệm

- **Ghi đè phương thức (Method Overriding)**: lớp con định nghĩa lại một phương thức có **cùng tên, cùng tham số** với phương thức ở lớp cha, thay thế hành vi cũ.
- **Gọi lại phiên bản của lớp cha**: cú pháp `TenLopCha::tenPhuongThuc();` cho phép lớp con, dù đã ghi đè, vẫn "gọi nhờ" bản gốc của lớp cha khi cần.

## 4. Giải Thích

### 4.1. Cú Pháp Ghi Đè Cơ Bản

```cpp
class DongVat {
public:
    string ten;
    void keu() {
        cout << ten << " keu mot am thanh chung chung." << endl;
    }
};

class Cho : public DongVat {
public:
    void keu() {   // GHI DE: cung ten, cung tham so (khong co), noi dung khac
        cout << ten << " sua: Gau gau!" << endl;
    }
};
```

Khi gọi `c.keu()` với `c` là đối tượng `Cho`, C++ tìm `keu()` bắt đầu từ lớp `Cho`, thấy ngay nên dùng bản đã ghi đè và bỏ qua bản gốc của `DongVat`.

### 4.2. Gọi Lại Phiên Bản Của Lớp Cha

```cpp
void keu() {
    DongVat::keu();   // Goi ban goc truoc
    cout << ten << " (them) sua: Gau gau!" << endl;   // Roi bo sung them
}
```

Cú pháp `DongVat::keu()` cho phép "mượn" lại logic có sẵn ở lớp cha, tránh viết lại từ đầu nếu chỉ cần bổ sung một chút.

### 4.3. Giới Hạn Quan Trọng Của Ghi Đè Cơ Bản

Nếu gọi phương thức **qua con trỏ hoặc tham chiếu kiểu lớp cha** (dù nó đang trỏ tới đối tượng lớp con), C++ **không** tự dùng bản đã ghi đè: nó chọn theo **kiểu của con trỏ**, nên vẫn dùng bản của lớp cha. Để C++ chọn theo **đối tượng thật**, cần thêm từ khóa `virtual` vào phương thức ở lớp cha. Đây là nền tảng của **Đa hình (Polymorphism)**, một chủ đề riêng và sâu hơn.

## 5. Ví Dụ

Các output dưới đây được lấy từ lần biên dịch và chạy thực tế.

### Ví dụ 1: Ghi đè phương thức cơ bản (Mục tiêu: nắm cú pháp cơ bản nhất)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    string ten;
    void keu() {
        cout << ten << " keu mot am thanh chung chung." << endl;
    }
};

class Cho : public DongVat {
public:
    void keu() {
        cout << ten << " sua: Gau gau!" << endl;
    }
};

int main() {
    DongVat dv;
    dv.ten = "Dong vat";
    dv.keu();

    Cho c;
    c.ten = "Mi Lu";
    c.keu();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Dong vat keu mot am thanh chung chung.
Mi Lu sua: Gau gau!
```

Khi gọi `dv.keu()` (đối tượng `DongVat`), kết quả dùng bản gốc. Khi gọi `c.keu()` (đối tượng `Cho`), kết quả dùng bản **đã ghi đè** trong `Cho`, dù cả hai cùng gọi phương thức tên `keu()`.

### Ví dụ 2: Gọi lại phiên bản của lớp cha từ trong phương thức đã ghi đè (Mục tiêu: tái sử dụng logic cũ)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    string ten;
    void keu() {
        cout << ten << " keu mot am thanh chung chung." << endl;
    }
};

class Cho : public DongVat {
public:
    void keu() {
        DongVat::keu();   // Goi phien ban CU cua lop cha truoc
        cout << ten << " (them) sua: Gau gau!" << endl;
    }
};

int main() {
    Cho c;
    c.ten = "Mi Lu";
    c.keu();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Mi Lu keu mot am thanh chung chung.
Mi Lu (them) sua: Gau gau!
```

Phương thức `keu()` của `Cho` vẫn "mượn" lại `DongVat::keu()` (in dòng đầu), rồi bổ sung hành vi riêng (dòng thứ hai).

### Ví dụ 3: Giới hạn quan trọng, gọi qua con trỏ lớp cha không dùng bản đã ghi đè (Mục tiêu: hiểu giới hạn của ghi đè cơ bản)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    string ten;
    void keu() {
        cout << ten << " keu mot am thanh chung chung." << endl;
    }
};

class Cho : public DongVat {
public:
    void keu() {
        cout << ten << " sua: Gau gau!" << endl;
    }
};

int main() {
    Cho c;
    c.ten = "Mi Lu";

    cout << "-- Goi truc tiep qua doi tuong Cho --" << endl;
    c.keu();

    cout << "-- Goi qua CON TRO kieu DongVat, tro toi doi tuong Cho --" << endl;
    DongVat *p = &c;   // Con tro KIEU DongVat, nhung tro toi doi tuong Cho
    p->keu();
    return 0;
}
```

**Output đã kiểm chứng:**

```
-- Goi truc tiep qua doi tuong Cho --
Mi Lu sua: Gau gau!
-- Goi qua CON TRO kieu DongVat, tro toi doi tuong Cho --
Mi Lu keu mot am thanh chung chung.
```

Điểm rất bất ngờ: dù `p` đang trỏ tới một đối tượng `Cho`, lệnh `p->keu()` vẫn in câu của `DongVat`, **không phải** câu đã ghi đè của `Cho`. Nguyên nhân: khi không có `virtual`, C++ chọn phiên bản theo **kiểu của con trỏ** (`DongVat*`), không theo đối tượng thật nó trỏ tới.

### Ví dụ 4 (Mở rộng, chỉ để tham khảo): Thêm virtual sẽ khắc phục vấn đề này

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    string ten;
    virtual void keu() {   // Them tu khoa virtual
        cout << ten << " keu mot am thanh chung chung." << endl;
    }
};

class Cho : public DongVat {
public:
    void keu() override {   // override: nho trinh bien dich kiem tra chu ky
        cout << ten << " sua: Gau gau!" << endl;
    }
};

int main() {
    Cho c;
    c.ten = "Mi Lu";
    DongVat *p = &c;
    p->keu();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Mi Lu sua: Gau gau!
```

Chỉ cần thêm `virtual` vào phương thức ở lớp cha, `p->keu()` đã gọi **đúng** bản ghi đè của `Cho`. Từ khóa `override` ở lớp con không bắt buộc, nhưng nên viết: nếu bạn gõ sai tham số, trình biên dịch sẽ báo lỗi thay vì lặng lẽ tạo một phương thức mới.

### Xem C++ chọn phiên bản nào

Mô phỏng dưới đây vẽ cách C++ **tìm** phương thức: bắt đầu từ lớp của đối tượng, thấy thì dừng, bản bị che sẽ mờ đi. Bấm **Bước tiếp** để chạy từng dòng:

- Tab **Ghi đè cơ bản**: `dv.keu()` tìm thấy ngay ở `DongVat`; `c.keu()` bắt đầu ở `Cho`, thấy `keu()` của `Cho` nên bản của `DongVat` bị che mờ.
- Tab **Gọi lại DongVat::keu()**: dòng `DongVat::keu();` chỉ thẳng vào bản của `DongVat`, không phải tìm dần, rồi dòng kế tiếp của `Cho` chạy.
- Tab **Con trỏ lớp cha**: con trỏ `p` có kiểu `DongVat*` nhưng trỏ vào đối tượng `Cho`. Khi không có `virtual`, `p->keu()` chỉ nhìn kiểu `DongVat*` nên in câu chung chung.
- Tab **Thêm virtual**: cùng chương trình, chỉ thêm `virtual` và `override`. Lúc này `p->keu()` đi theo mũi tên tới đối tượng thật và ra tiếng sủa. Bảng cuối tab đặt hai kết quả cạnh nhau.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Viết sai tham số khi ghi đè, tưởng đã ghi đè thành công**: nếu phương thức ở lớp con có tên giống nhưng **tham số khác**, đó không phải ghi đè. Phương thức mới còn **che khuất** (name hiding) mọi phương thức cùng tên của lớp cha: ví dụ lớp con chỉ khai báo `keu(int lan)` thì `c.keu()` báo lỗi, vì C++ chỉ thấy `keu(int)` của lớp con. Viết `override` ở lớp con sẽ giúp trình biên dịch bắt lỗi kiểu này.
- **Ngạc nhiên khi gọi qua con trỏ hoặc tham chiếu lớp cha mà không ra kết quả mong đợi**: đây là giới hạn quan trọng nhất của bài (xem lại Ví dụ 3). Muốn ghi đè đúng khi gọi qua con trỏ lớp cha, thêm `virtual` ở lớp cha.
- **Không biết cách "mượn" lại logic cũ của lớp cha**: đừng viết lại toàn bộ từ đầu nếu chỉ cần bổ sung. Hãy dùng `TenLopCha::tenPhuongThuc()` như Ví dụ 2.
- **Nhầm ghi đè phương thức với ghi đè thuộc tính**: "ghi đè" chỉ áp dụng cho **phương thức**. Nếu lớp con khai báo thuộc tính cùng tên với lớp cha, đó là tình huống khác (gọi là "ẩn" thuộc tính), ít gặp và không thuộc bài này.
- **Chưa cần lo về `virtual` khi chỉ gọi trực tiếp qua đối tượng**: nếu chương trình chỉ gọi phương thức qua đối tượng (như Ví dụ 1 và 2), ghi đè cơ bản vẫn đúng hoàn toàn. Chỉ cần nhớ giới hạn này khi làm việc với con trỏ hoặc tham chiếu kiểu lớp cha.
