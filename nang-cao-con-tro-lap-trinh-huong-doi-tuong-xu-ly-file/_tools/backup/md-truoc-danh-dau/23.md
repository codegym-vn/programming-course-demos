# Các Chế Độ Mở File (File Modes): ios::in, ios::out, ios::app

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: **chế độ mở file (File Mode)** là gì — quy định cách file sẽ được mở và xử lý (đọc, ghi, ghi tiếp...).
- Nắm vững ba chế độ cơ bản nhất: `ios::in` (đọc), `ios::out` (ghi), và `ios::app` (ghi tiếp vào cuối file).
- Nhận diện được cảnh báo quan trọng: `ios::out` mặc định sẽ **xóa sạch toàn bộ nội dung cũ** của file ngay khi mở để ghi.
- Ứng dụng được kỹ thuật kết hợp nhiều chế độ cùng lúc bằng toán tử `|` (OR theo bit).
- Quan sát tệp thay đổi theo từng chế độ bằng hoạt động mô phỏng.

## 2. Giới Thiệu

Ở các bài trước, mỗi khi mở file để ghi (`ofstream`), bạn có thể chưa để ý đến một điều quan trọng: nếu file đó **đã có sẵn nội dung** từ trước, điều gì sẽ xảy ra? Nó sẽ bị xóa sạch để ghi nội dung mới, hay nội dung mới sẽ được thêm vào phía sau nội dung cũ?

Câu trả lời phụ thuộc vào **chế độ mở file (File Mode)** mà bạn chỉ định — và nếu không hiểu rõ điều này, bạn có thể vô tình xóa mất dữ liệu quan trọng chỉ vì mở file theo chế độ mặc định. Bài học này sẽ giúp bạn nắm vững các chế độ phổ biến nhất và tránh được sai lầm tốn kém này.

## 3. Khái Niệm

- **Chế độ mở file (File Mode)**: tham số thứ hai (tùy chọn) khi mở file, quy định chính xác cách file sẽ được truy cập.
- `ios::in`: chế độ mở file để **đọc** — đây là chế độ mặc định khi dùng `ifstream`.
- `ios::out`: chế độ mở file để **ghi** — đây là chế độ mặc định khi dùng `ofstream`. **Cảnh báo quan trọng:** mặc định, chế độ này sẽ **xóa sạch** toàn bộ nội dung cũ của file (nếu file đã tồn tại) ngay khi mở, trước khi ghi nội dung mới.
- `ios::app` (viết tắt của "append"): chế độ mở file để ghi **thêm vào cuối** file — giữ nguyên toàn bộ nội dung cũ, chỉ bổ sung thêm nội dung mới vào phía sau.

## 4. Giải Thích

### 4.1. ios::out Mặc Định — Xóa Sạch Nội Dung Cũ

```cpp
ofstream f("nhatky.txt");   // Tương đương ofstream f("nhatky.txt", ios::out);
```

Nếu `nhatky.txt` đã có sẵn nội dung từ trước, dòng lệnh này sẽ **xóa sạch** toàn bộ nội dung đó ngay khi mở file, dù bạn chưa hề ghi thêm bất kỳ dòng nào.

### 4.2. ios::app — Giữ Nguyên Nội Dung Cũ, Chỉ Thêm Vào Cuối

```cpp
ofstream f("nhatky.txt", ios::app);
```

Với chế độ này, mọi nội dung đã có trong file được **giữ nguyên vẹn** — dữ liệu mới ghi vào sẽ luôn được nối vào **cuối** những gì đã có, không bao giờ ghi đè lên nội dung cũ.

### 4.3. Kết Hợp Nhiều Chế Độ Bằng Toán Tử |

```cpp
fstream f("nhatky.txt", ios::in | ios::app);   // Vừa đọc được, vừa ghi thêm (không xóa)
```

Toán tử `|` cho phép kết hợp nhiều chế độ cùng lúc — ví dụ vừa muốn đọc file, vừa muốn có khả năng ghi thêm vào cuối mà không làm mất dữ liệu cũ.

## 5. Ví Dụ

Các output dưới đây được lấy từ lần chạy thực tế (biên dịch bằng trình biên dịch C++17). Các ví dụ đều bắt đầu từ một file `nhatky.txt` có sẵn 2 dòng: `"Dong 1: Hom nay troi dep."` và `"Dong 2: Toi di hoc."`. Lưu ý: Ví dụ 4 dùng file `nhatky.txt` đã có thêm dòng 3 từ Ví dụ 2, nên cần chạy lần lượt theo thứ tự.

### Ví dụ 1: ios::out mặc định — xóa sạch nội dung cũ (Mục tiêu: nhận diện cảnh báo quan trọng nhất)

```cpp
#include <iostream>
#include <fstream>
using namespace std;

int main() {
    ofstream f("nhatky.txt");   // Mac dinh la ios::out
    f << "Dong moi duy nhat." << endl;
    f.close();
    return 0;
}
```

**Nội dung file `nhatky.txt` SAU KHI chạy:**

```
Dong moi duy nhat.
```

Hai dòng cũ (`"Dong 1..."`, `"Dong 2..."`) đã **biến mất hoàn toàn** — chỉ còn lại đúng một dòng vừa ghi. Thực ra chúng đã mất ngay ở dòng `ofstream f("nhatky.txt");`, trước cả khi dòng mới được ghi. Đây chính là hành vi mặc định đầy rủi ro của `ios::out` mà bạn cần luôn ghi nhớ.

### Ví dụ 2: ios::app — giữ nguyên nội dung cũ, chỉ thêm vào cuối (Mục tiêu: nắm giải pháp an toàn hơn)

*(Bắt đầu lại với file gốc có 2 dòng)*

```cpp
#include <iostream>
#include <fstream>
using namespace std;

int main() {
    ofstream f("nhatky.txt", ios::app);
    f << "Dong 3: Buoi toi toi doc sach." << endl;
    f.close();
    return 0;
}
```

**Nội dung file `nhatky.txt` SAU KHI ghi thêm bằng `ios::app`:**

```
Dong 1: Hom nay troi dep.
Dong 2: Toi di hoc.
Dong 3: Buoi toi toi doc sach.
```

Lần này, cả 2 dòng cũ vẫn còn nguyên vẹn, và dòng mới được thêm vào **đúng vị trí cuối cùng** — không có dữ liệu nào bị mất.

### Ví dụ 3: So sánh trực tiếp ios::out và ios::app trong cùng một chương trình (Mục tiêu: khắc sâu sự khác biệt)

```cpp
#include <iostream>
#include <fstream>
#include <string>
using namespace std;

void inFile(string ten) {
    ifstream f(ten);
    string dong;
    while (getline(f, dong)) {
        cout << "  " << dong << endl;
    }
}

int main() {
    ofstream f2("test_out.txt", ios::out);
    f2 << "Dong thay the" << endl;
    f2.close();
    cout << "Sau khi mo lai bang ios::out:" << endl;
    inFile("test_out.txt");

    ofstream f3("test_out.txt", ios::app);
    f3 << "Dong them vao" << endl;
    f3.close();
    cout << "Sau khi mo lai bang ios::app:" << endl;
    inFile("test_out.txt");
    return 0;
}
```

**Output đã kiểm chứng:**

```
Sau khi mo lai bang ios::out:
  Dong thay the
Sau khi mo lai bang ios::app:
  Dong thay the
  Dong them vao
```

Đặt cạnh nhau, sự khác biệt càng rõ ràng: `ios::out` chỉ để lại đúng dòng vừa ghi (xóa hết mọi thứ trước đó), trong khi `ios::app` giữ lại toàn bộ và chỉ bổ sung thêm. (Hàm `inFile` dùng vòng lặp `while (getline(...))` chỉ để in nội dung file, sẽ học kỹ ở Bài 4.5.)

### Ví dụ 4: Kết hợp nhiều chế độ bằng toán tử | (Mục tiêu: ứng dụng nâng cao hơn, vừa đọc vừa ghi thêm)

*(File `nhatky.txt` lúc này đang có 3 dòng, sau Ví dụ 2)*

```cpp
#include <iostream>
#include <fstream>
#include <string>
using namespace std;

int main() {
    fstream f("nhatky.txt", ios::in | ios::app);

    f.seekg(0);            // Dua vi tri doc ve dau file cho chac chan
    string dongDau;
    getline(f, dongDau);   // Doc duoc du lieu, nho co ios::in
    cout << "Doc duoc dong dau: " << dongDau << endl;

    f << "Dong moi them vao (van con dong cu)." << endl;   // Ghi them, nho co ios::app
    f.close();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Doc duoc dong dau: Dong 1: Hom nay troi dep.
```

**Và nội dung file sau đó:**

```
Dong 1: Hom nay troi dep.
Dong 2: Toi di hoc.
Dong 3: Buoi toi toi doc sach.
Dong moi them vao (van con dong cu).
```

Nhờ kết hợp `ios::in | ios::app`, chương trình vừa đọc được dòng đầu tiên của file, vừa ghi thêm một dòng mới vào cuối — mà không hề làm mất bất kỳ nội dung nào đã có từ trước.

Lưu ý về dòng `f.seekg(0);`: khi mở với `ios::app`, có trình biên dịch đặt vị trí đọc ban đầu ở đầu file, có trình biên dịch đặt ở cuối file (khi đó `getline` không đọc được gì). `seekg(0)` đưa vị trí đọc về đầu file nên chương trình chạy giống nhau trên mọi máy. Việc ghi vẫn luôn nối vào cuối file nhờ `ios::app`.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Vô tình xóa sạch dữ liệu quan trọng vì dùng `ofstream` mặc định**: đây là lỗi tai hại nhất trong chủ đề File I/O (xem lại Ví dụ 1) — trước khi mở file để ghi, luôn tự hỏi: "file này đã có dữ liệu quan trọng chưa? Mình có thực sự muốn xóa nó đi không?"
- **Muốn ghi thêm nhưng lại quên chỉ định `ios::app`**: nếu ý định của bạn là bổ sung dữ liệu mới vào một file nhật ký, danh sách, hay log đang có sẵn, luôn nhớ thêm `ios::app` — quên nó sẽ khiến toàn bộ lịch sử trước đó bị xóa mất mỗi khi chương trình chạy lại.
- **Nghĩ rằng phải kết hợp `ios::out | ios::app`**: với `ofstream`, chỉ dùng `ios::app` một mình là đã đủ để vừa ghi vừa giữ nguyên nội dung cũ. Cờ thực sự có tác dụng xóa nội dung là `ios::trunc`, còn `ios::app` thì không xóa.
- **Không chỉ định chế độ phù hợp khi dùng `fstream`**: vì `fstream` không tự suy ra được bạn muốn đọc hay ghi, luôn cần chỉ định tường minh chế độ mong muốn (`ios::in`, `ios::out`, `ios::app`, hoặc kết hợp) khi dùng lớp này.
- **Không thử nghiệm trước với dữ liệu không quan trọng**: khi mới làm quen với các chế độ mở file, nên thử nghiệm trên các file thử nghiệm không chứa dữ liệu quan trọng trước, để tránh những mất mát dữ liệu ngoài ý muốn tương tự Ví dụ 1 trong quá trình học tập.
