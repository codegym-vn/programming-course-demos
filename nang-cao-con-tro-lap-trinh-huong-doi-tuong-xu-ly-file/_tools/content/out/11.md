# Hàm huỷ (Destructor) và vòng đời đối tượng

## 1. Mục Tiêu Bài Học

Sau bài đọc này, bạn sẽ:

- Hiểu hàm huỷ (destructor) là gì và viết đúng cú pháp `~TenLop()`.
- Mô tả được **vòng đời** của một đối tượng: được tạo ra khi nào, bị huỷ khi nào.
- Dự đoán chính xác thứ tự gọi constructor và destructor của nhiều đối tượng.
- Biết khi nào cần tự viết hàm huỷ để giải phóng tài nguyên (bộ nhớ cấp phát động, file đang mở…).

## 2. Hàm Huỷ Là Gì?

Ở bài trước, bạn đã biết **hàm khởi tạo (constructor)** được gọi tự động khi một đối tượng *ra đời*. Hàm huỷ là "người anh em" đối xứng của nó: một phương thức đặc biệt được gọi **tự động** ngay trước khi đối tượng *bị xoá khỏi bộ nhớ*.

Hãy hình dung một phòng họp: constructor giống việc bật đèn, bật máy chiếu khi có người vào; destructor giống việc tắt đèn, tắt máy chiếu khi người cuối cùng ra về. Nếu không ai "dọn dẹp", điện vẫn cháy suốt đêm — trong lập trình, đó chính là **rò rỉ tài nguyên**.

### 2.1. Cú pháp

```cpp
class TenLop {
public:
    TenLop() {      // hàm khởi tạo
        // ...
    }

    ~TenLop() {     // hàm huỷ: dấu ~ + tên lớp
        // dọn dẹp tài nguyên
    }
};
```

Quy tắc của hàm huỷ:

| Đặc điểm | Hàm khởi tạo | Hàm huỷ |
| --- | --- | --- |
| Tên | TenLop | ~TenLop |
| Kiểu trả về | Không có (kể cả void) | Không có (kể cả void) |
| Tham số | Có thể có | Không được có |
| Số lượng trong một lớp | Nhiều (nạp chồng) | Đúng một |
| Thời điểm gọi | Khi đối tượng được tạo | Khi đối tượng bị huỷ |

Nếu bạn không viết hàm huỷ, trình biên dịch tự sinh một hàm huỷ mặc định "không làm gì đặc biệt". Điều đó hoàn toàn ổn với các lớp chỉ chứa `int`, `double`, `string`… vì chúng tự dọn dẹp được.

## 3. Vòng Đời Của Đối Tượng

Khi nào một đối tượng bị huỷ? Câu trả lời phụ thuộc vào **cách nó được tạo ra**:

| Loại đối tượng | Được tạo khi | Bị huỷ khi |
| --- | --- | --- |
| Đối tượng cục bộ trong một khối { } | Chương trình chạy tới dòng khai báo | Chương trình ra khỏi khối { } chứa nó |
| Đối tượng cục bộ trong hàm | Mỗi lần hàm được gọi và chạy tới dòng khai báo | Mỗi lần hàm kết thúc |
| Đối tượng trong main | Chạy tới dòng khai báo | main kết thúc |
| Đối tượng cấp phát động bằng new | Lệnh new thực thi | Chỉ khi gọi delete |

### 3.1. Ví dụ: theo dõi vòng đời bằng lớp Den

Ta viết một lớp in ra thông báo trong cả constructor lẫn destructor để "nhìn thấy" vòng đời đối tượng:

```cpp
#include <iostream>
#include <string>
using namespace std;

class Den {
private:
    string ten;
public:
    Den(string t) {
        ten = t;
        cout << "Bat den " << ten << endl;
    }
    ~Den() {
        cout << "Tat den " << ten << endl;
    }
};

void diQuaHanhLang() {
    Den d("Hanh lang");
    cout << "Dang di qua hanh lang" << endl;
}

int main() {
    cout << "Bat dau main" << endl;
    Den a("Phong khach");
    {
        Den b("Phong ngu");
        cout << "Trong khoi lenh" << endl;
    }
    diQuaHanhLang();
    Den c("Nha bep");
    Den *p = new Den("Ban cong");
    delete p;
    cout << "Ket thuc main" << endl;
    return 0;
}
```

**Kết quả chạy chương trình:**

```
Bat dau main
Bat den Phong khach
Bat den Phong ngu
Trong khoi lenh
Tat den Phong ngu
Bat den Hanh lang
Dang di qua hanh lang
Tat den Hanh lang
Bat den Nha bep
Bat den Ban cong
Tat den Ban cong
Ket thuc main
Tat den Nha bep
Tat den Phong khach
```

### 3.2. Phân tích từng bước

1. **Đối tượng `b`** nằm trong khối `{ }` riêng nên bị huỷ ngay khi chương trình ra khỏi khối — trước cả khi `c` được tạo.
2. **Đối tượng `d`** là biến cục bộ của hàm `diQuaHanhLang`: nó sinh ra khi hàm chạy và bị huỷ khi hàm kết thúc. Nếu gọi hàm 3 lần, bạn sẽ thấy 3 cặp "Bat den / Tat den".
3. **Đối tượng `*p`** được tạo bằng `new`, nên nó chỉ bị huỷ đúng tại dòng `delete p;`.
4. **Đối tượng `a` và `c`** sống đến cuối `main`. Lưu ý: `c` được tạo *sau* `a` nhưng lại bị huỷ *trước* `a`.

### 3.3. Quy tắc "vào sau – ra trước"

Các đối tượng cục bộ trong cùng một phạm vi bị huỷ theo thứ tự **ngược lại** với thứ tự tạo ra (giống một chồng đĩa: đĩa đặt lên sau cùng được lấy ra đầu tiên). Lý do: đối tượng tạo sau có thể đang dùng đối tượng tạo trước, nên phải huỷ đối tượng "phụ thuộc" trước.

## 4. Khi Nào Cần Tự Viết Hàm Huỷ?

In thông báo như lớp `Den` chỉ để học. Trong thực tế, hàm huỷ dùng để **trả lại tài nguyên** mà đối tượng đã "mượn" trong quá trình sống:

- Bộ nhớ cấp phát động bằng `new` / `new[]` → giải phóng bằng `delete` / `delete[]`.
- File đang mở → đóng file (bạn sẽ học ở Module 4).
- Kết nối mạng, kết nối cơ sở dữ liệu… → ngắt kết nối.

### 4.1. Ví dụ: lớp BangDiem cấp phát mảng động

Số môn học chỉ biết khi chạy chương trình, nên ta cấp phát mảng điểm bằng `new int[soMon]` trong constructor và giải phóng trong destructor:

```cpp
#include <iostream>
using namespace std;

class BangDiem {
private:
    int *diem;
    int soMon;
public:
    BangDiem(int n) {
        soMon = n;
        diem = new int[soMon];          // mượn bộ nhớ
        for (int i = 0; i < soMon; i++) {
            diem[i] = 0;
        }
        cout << "Da cap phat bang diem " << soMon << " mon" << endl;
    }

    ~BangDiem() {
        delete[] diem;                  // trả lại bộ nhớ
        cout << "Da giai phong bang diem" << endl;
    }

    void nhapDiem(int viTri, int giaTri) {
        if (viTri >= 0 && viTri < soMon) {
            diem[viTri] = giaTri;
        }
    }

    double tinhTrungBinh() {
        int tong = 0;
        for (int i = 0; i < soMon; i++) {
            tong += diem[i];
        }
        return (double)tong / soMon;
    }
};

int main() {
    BangDiem bd(3);
    bd.nhapDiem(0, 8);
    bd.nhapDiem(1, 7);
    bd.nhapDiem(2, 9);
    cout << "Diem trung binh: " << bd.tinhTrungBinh() << endl;
    return 0;
}
```

**Kết quả:**

```
Da cap phat bang diem 3 mon
Diem trung binh: 8
Da giai phong bang diem
```

Người dùng lớp `BangDiem` không cần nhớ phải giải phóng bộ nhớ: chỉ cần đối tượng `bd` hết phạm vi, destructor tự làm việc đó. Đây là một ý tưởng nền tảng của C++: **gắn việc thu hồi tài nguyên với vòng đời đối tượng**.

*Ghi chú:* `new` và `delete` là cú pháp cấp phát bộ nhớ động. Ở đây bạn chỉ cần hiểu ý tưởng "mượn – trả"; quy tắc chi tiết sẽ được bổ sung khi bạn làm việc nhiều hơn với con trỏ. Một điều cần biết thêm: nếu chương trình kết thúc mà bạn chưa `delete`, hệ điều hành vẫn thu hồi bộ nhớ, nhưng destructor của đối tượng đó **không** chạy — nên mọi việc "dọn dẹp" khác trong destructor (như in thông báo, đóng file) sẽ không được thực hiện.

## 5. Phần Chú Ý: Lỗi Thường Gặp

| Lỗi | Hậu quả | Cách đúng |
| --- | --- | --- |
| Khai báo tham số hoặc kiểu trả về cho hàm huỷ, ví dụ void ~Den(int x) | Lỗi biên dịch | ~Den() — không tham số, không kiểu trả về |
| Tạo đối tượng bằng new nhưng quên delete | Destructor không bao giờ chạy → rò rỉ bộ nhớ | Mỗi new phải đi kèm một delete |
| Cấp phát bằng new[] nhưng giải phóng bằng delete | Hành vi không xác định | new ↔ delete, new[] ↔ delete[] |
| Tự gọi bd.~BangDiem(); trong main | Destructor chạy hai lần → giải phóng bộ nhớ hai lần, chương trình có thể bị dừng đột ngột | Để C++ tự gọi destructor |
| Nghĩ rằng đối tượng tạo trước sẽ bị huỷ trước | Dự đoán sai output | Nhớ quy tắc "vào sau – ra trước" |

## 6. Tổng Kết

- Hàm huỷ có dạng `~TenLop()`: không tham số, không kiểu trả về, mỗi lớp chỉ có một.
- Hàm huỷ được gọi **tự động** khi đối tượng hết phạm vi, khi hàm kết thúc, hoặc khi gọi `delete` với đối tượng tạo bằng `new`.
- Các đối tượng trong cùng phạm vi bị huỷ theo thứ tự ngược với thứ tự tạo.
- Tự viết hàm huỷ khi đối tượng giữ tài nguyên cần trả lại (bộ nhớ động, file…).

**Tự kiểm tra:** trong ví dụ lớp `Den`, nếu xoá dòng `delete p;` thì output thay đổi thế nào? Nếu gọi `diQuaHanhLang()` hai lần liên tiếp thì sao? Hãy dự đoán trước, rồi chạy thử để kiểm chứng (tab "Quên delete: rò rỉ" ở mô phỏng trên cho bạn xem trường hợp thứ nhất).
