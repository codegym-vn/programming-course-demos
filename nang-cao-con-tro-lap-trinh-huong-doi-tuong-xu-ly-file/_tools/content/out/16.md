# Phạm Vi Truy Cập protected (Khác Gì Với private?)

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: `protected` là gì. Nó giống `private` ở việc ẩn khỏi thế giới bên ngoài, nhưng khác ở chỗ cho phép **lớp con** truy cập.
- Nắm vững cú pháp: khai báo `protected:` trong lớp cha.
- Hiểu lý do cần `protected`: khi lớp con cần truy cập trực tiếp dữ liệu của lớp cha, nhưng vẫn muốn ẩn dữ liệu đó khỏi thế giới bên ngoài.
- Phân biệt rõ ba mức truy cập `public`, `protected`, `private` qua một ví dụ so sánh trực tiếp.
- Quan sát ai vào được phòng nào bằng hoạt động mô phỏng.

## 2. Giới Thiệu

Ở bài "Các phạm vi truy cập: public vs private" trong phần Lớp & Đối tượng, bạn đã biết `private` giúp bảo vệ dữ liệu, chỉ cho phép các phương thức **bên trong chính lớp đó** truy cập. Nhưng khi đã học kế thừa, một câu hỏi mới xuất hiện: điều gì xảy ra nếu lớp con cần truy cập trực tiếp một thuộc tính của lớp cha?

Nếu thuộc tính đó là `private`, câu trả lời đáng ngạc nhiên là: **lớp con cũng không truy cập được**, dù nó kế thừa từ chính lớp cha đó. Đây là lúc `protected` xuất hiện: nó hoạt động giống `private` khi nhìn từ bên ngoài (vẫn bị chặn hoàn toàn), nhưng "mở cửa" cho riêng các lớp con.

## 3. Khái Niệm

- **`protected`**: từ khóa đánh dấu phạm vi truy cập trung gian giữa `public` và `private`. Nó cho phép các **lớp con** truy cập trực tiếp, nhưng vẫn **chặn hoàn toàn** truy cập từ bên ngoài (không thuộc quan hệ kế thừa).
- **Khác biệt với `private`**: `private` chặn truy cập từ mọi nơi ngoài chính lớp đó, **kể cả lớp con**; `protected` vẫn chặn từ bên ngoài, nhưng **cho phép lớp con** truy cập.

## 4. Giải Thích

### 4.1. Vấn Đề: private Chặn Cả Lớp Con

Đây là điểm gây bất ngờ nhất cho người mới học kế thừa: một thuộc tính `private` trong lớp cha **không thể** được truy cập trực tiếp từ lớp con, dù lớp con kế thừa toàn bộ lớp cha đó.

### 4.2. Giải Pháp: Dùng protected Thay Cho private

```cpp
class DongVat {
protected:      // Thay vi private
    string ten;
};
```

Với `protected`, các phương thức trong lớp con (như `Cho`, `Meo`) truy cập trực tiếp được `ten`, trong khi code bên ngoài (như trong `main()`) vẫn hoàn toàn không thể, giống hệt `private` khi nhìn từ bên ngoài.

Lưu ý: thành viên `private` của lớp cha vẫn **tồn tại** bên trong đối tượng con (vẫn chiếm bộ nhớ, và các hàm của cha như `setTen()` vẫn sửa được). Lớp con chỉ không gọi thẳng tên của nó được mà thôi.

### 4.3. Bảng So Sánh Ba Mức Truy Cập

| Truy cập từ | public | protected | private |
| --- | --- | --- | --- |
| Bên trong chính lớp đó | Được | Được | Được |
| Từ lớp con (kế thừa) | Được | Được | Không được |
| Từ bên ngoài (không kế thừa) | Được | Không được | Không được |

## 5. Ví Dụ

Các output và thông báo lỗi dưới đây được lấy từ lần biên dịch và chạy thực tế (thông báo lỗi ghi theo g++).

### Ví dụ 1: Lỗi, private không cho lớp con truy cập (Mục tiêu: thấy rõ vấn đề cần giải quyết)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
private:
    string ten;   // PRIVATE
public:
    void setTen(string t) { ten = t; }
};

class Cho : public DongVat {
public:
    void inTen() {
        cout << "Ten: " << ten << endl;   // Co truy cap
    }
};

int main() {
    Cho c;
    c.setTen("Mi Lu");
    c.inTen();
    return 0;
}
```

**Thông báo lỗi biên dịch:**

```
error: 'std::string DongVat::ten' is private within this context
```

Dù `Cho` kế thừa toàn bộ từ `DongVat`, nó vẫn **không thể** truy cập trực tiếp `ten`. Đây là hạn chế của `private` trong kế thừa.

### Ví dụ 2: Giải pháp, protected cho phép lớp con truy cập (Mục tiêu: thấy rõ giải pháp hoạt động)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
protected:
    string ten;   // PROTECTED thay vi private
public:
    void setTen(string t) { ten = t; }
};

class Cho : public DongVat {
public:
    void inTen() {
        cout << "Ten: " << ten << endl;   // OK! Lop con truy cap duoc
    }
};

int main() {
    Cho c;
    c.setTen("Mi Lu");
    c.inTen();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Ten: Mi Lu
```

Chỉ cần đổi `private` thành `protected`, lớp con `Cho` truy cập trực tiếp được `ten` bên trong phương thức `inTen()` của chính nó.

### Ví dụ 3: protected vẫn chặn truy cập từ bên ngoài, giống private (Mục tiêu: hiểu rõ protected không phải là public)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
protected:
    string ten;
public:
    void setTen(string t) { ten = t; }
};

int main() {
    DongVat dv;
    dv.setTen("Mi Lu");
    dv.ten = "Thu";   // Co truy cap truc tiep tu ben ngoai
    return 0;
}
```

**Thông báo lỗi biên dịch:**

```
error: 'std::string DongVat::ten' is protected within this context
```

Đây là bằng chứng quan trọng: `protected` **không** biến thuộc tính thành `public`. Nó vẫn bị chặn khi truy cập trực tiếp từ code không thuộc quan hệ kế thừa (như `main()` ở đây).

### Ví dụ 4: So sánh trực tiếp cả ba mức truy cập (Mục tiêu: tổng hợp và khắc sâu sự khác biệt)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    string loai;         // PUBLIC
protected:
    string ten;          // PROTECTED
private:
    int maSoBiMat;       // PRIVATE

public:
    void thietLap(string t, int ma) {
        ten = t;
        maSoBiMat = ma;
    }
};

class Cho : public DongVat {
public:
    void inThongTin() {
        cout << "Loai (public): " << loai << endl;
        cout << "Ten (protected): " << ten << endl;
        // maSoBiMat khong the truy cap o day, se loi neu bo comment
    }
};

int main() {
    Cho c;
    c.loai = "Cho";
    c.thietLap("Mi Lu", 123);
    c.inThongTin();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Loai (public): Cho
Ten (protected): Mi Lu
```

`loai` (public) truy cập được cả từ bên ngoài (`c.loai = "Cho";`) và từ lớp con. `ten` (protected) chỉ truy cập được từ lớp con (`inThongTin()`), không truy cập trực tiếp được từ `main()`. Nếu bỏ comment để in `maSoBiMat` (private) ngay trong `Cho::inThongTin()`, chương trình báo lỗi `error: 'int DongVat::maSoBiMat' is private within this context`. Vậy chỉ `private` mới chặn cả lớp con, còn `protected` thì không.

### Xem ai vào được phòng nào

Mô phỏng dưới đây vẽ lớp `DongVat` thành các **phòng** (`public`, `protected`, `private`), và ghi lại mỗi lần ai đó thử vào phòng. Bấm **Bước tiếp** để chạy từng bước:

- Tab **private chặn cả lớp con**: `Cho::inTen()` thử đọc `ten` khi nó còn `private`, bị chặn, trong khi `setTen()` của chính `DongVat` vào được.
- Tab **Đổi sang protected**: `ten` chuyển sang phòng `protected`, `Cho::inTen()` vào được, còn `main()` thử `dv.ten = "Thu";` vẫn bị chặn. Vì có lỗi biên dịch, console chỉ hiện lỗi.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Dùng `private` cho những thuộc tính lớp con thực sự cần truy cập**: đây là lỗi thiết kế phổ biến khi mới học kế thừa (xem lại Ví dụ 1). Nếu biết chắc lớp con cần truy cập trực tiếp một thuộc tính của lớp cha, hãy dùng `protected`.
- **Nghĩ rằng `protected` giống `public` đối với mọi nơi**: lớp con truy cập được, nhưng thế giới bên ngoài vẫn bị chặn (xem lại Ví dụ 3).
- **Dùng `protected` cho mọi thuộc tính "để cho chắc"**: chỉ nên dùng khi có kế hoạch cho lớp con truy cập trực tiếp. Nếu không, `private` vẫn an toàn hơn và giữ đóng gói chặt chẽ nhất.
- **Quên rằng `protected` không thay được Getter/Setter**: lớp con truy cập thẳng thuộc tính `protected` sẽ bỏ qua các bước kiểm tra hợp lệ mà Setter có thể cung cấp.
- **Nhầm "kế thừa `public`" với "phạm vi truy cập `protected`"**: `class Cho : public DongVat` (bài trước) quyết định cách kế thừa; còn `protected:` (bài này) quyết định phạm vi truy cập của từng thành viên trong lớp cha.
