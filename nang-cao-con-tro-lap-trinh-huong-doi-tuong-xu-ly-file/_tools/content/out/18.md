# Thứ Tự Gọi Constructor Trong Kế Thừa

## 1. Mục Tiêu Bài Học

- Nắm chắc quy tắc quan trọng nhất: khi tạo một đối tượng lớp con, **Constructor của lớp cha luôn chạy trước**, rồi mới đến Constructor của lớp con.
- Hiểu quy tắc này áp dụng nhất quán ở **mọi cấp độ kế thừa**, kể cả khi có nhiều tầng lớp cha, lớp con nối tiếp nhau.
- Hiểu vì sao quy tắc này hợp lý: dữ liệu nền tảng từ lớp cha đã sẵn sàng trước khi lớp con xử lý phần của riêng nó.
- Biết Destructor chạy theo thứ tự **ngược lại**: lớp con trước, lớp cha sau.
- Quan sát thứ tự này bằng hoạt động mô phỏng.

## 2. Giới Thiệu

Ở bài "Cú pháp kế thừa", bạn đã thấy thoáng qua rằng Constructor của lớp cha được gọi trước Constructor của lớp con. Bài này khắc sâu quy tắc đó và mở rộng ra tình huống **nhiều tầng kế thừa**: ví dụ lớp "Chó" kế thừa "Động vật", rồi "Chó nghiệp vụ" kế thừa tiếp từ "Chó".

Câu trả lời rất nhất quán và dễ nhớ: Constructor luôn chạy từ **tổ tiên xa nhất** đến **lớp con cụ thể nhất**, giống xây nhà: móng (lớp cha) xong trước, rồi tầng trệt, rồi tầng trên. Không thể xây tầng trên khi móng chưa xong.

## 3. Khái Niệm

- **Thứ tự khởi tạo (Construction Order)**: quy tắc xác định trình tự các Constructor được gọi khi tạo một đối tượng thuộc chuỗi kế thừa, luôn đi từ lớp cha (tổ tiên) đến lớp con (hậu duệ).
- **Kế thừa nhiều tầng (Multi-level Inheritance)**: một lớp con lại là lớp cha của lớp khác, tạo thành chuỗi nhiều lớp nối tiếp (ví dụ `DongVat` → `Cho` → `ChoNghiepVu`).
- **Thứ tự hủy (Destruction Order)**: Destructor (hàm hủy, chạy khi đối tượng bị gỡ khỏi bộ nhớ) chạy theo chiều **ngược lại** với Constructor.

## 4. Giải Thích

### 4.1. Quy Tắc Cốt Lõi

Khi một đối tượng lớp con được tạo, C++ luôn làm theo trình tự:

1. Constructor của lớp cha xa nhất trong chuỗi kế thừa chạy **trước tiên**.
2. Lần lượt đến Constructor của các lớp trung gian (nếu có), từ trên xuống.
3. Constructor của lớp con cụ thể (lớp đang thực sự được tạo đối tượng) chạy **sau cùng**.

Thứ tự này cố định, không phụ thuộc cách bạn viết danh sách khởi tạo. Các thuộc tính của một lớp được khởi tạo sau phần lớp cha và trước thân Constructor của chính lớp đó.

### 4.2. Vì Sao Thứ Tự Này Hợp Lý?

Lớp con thường cần **dựa vào** dữ liệu đã được lớp cha khởi tạo (ví dụ thuộc tính `protected` đã học ở bài trước). Nếu Constructor của lớp con chạy trước, nó sẽ dùng những dữ liệu **chưa tồn tại** từ lớp cha, điều này vô lý và nguy hiểm. Vì vậy C++ đảm bảo lớp cha "chuẩn bị xong" trước, để lớp con yên tâm xây tiếp.

### 4.3. Thứ Tự Hủy Ngược Lại

Khi đối tượng hết thời hạn sống (ví dụ tới dấu `}` kết thúc hàm), C++ gỡ nó theo chiều ngược lại: Destructor của lớp con chạy trước, rồi đến lớp cha, cuối cùng là tổ tiên xa nhất. Giống dỡ nhà từ mái xuống móng, cùng quy tắc "vào sau ra trước" ở bài về Destructor. Destructor của lớp cha được gọi **tự động**, không cần (và không được) gọi tường minh.

## 5. Ví Dụ

Các output dưới đây được lấy từ lần biên dịch và chạy thực tế.

### Ví dụ 1: Thứ tự cơ bản với hai lớp (Mục tiêu: nắm quy tắc cốt lõi nhất)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    DongVat() { cout << "1. Constructor DongVat chay" << endl; }
};

class Cho : public DongVat {
public:
    Cho() { cout << "2. Constructor Cho chay" << endl; }
};

int main() {
    cout << "Bat dau tao doi tuong Cho:" << endl;
    Cho c;
    return 0;
}
```

**Output đã kiểm chứng:**

```
Bat dau tao doi tuong Cho:
1. Constructor DongVat chay
2. Constructor Cho chay
```

Dù `main()` chỉ có một dòng `Cho c;`, **hai** Constructor đã được gọi theo đúng thứ tự: `DongVat` trước, `Cho` sau.

### Ví dụ 2: Thứ tự trong kế thừa nhiều tầng (Mục tiêu: hiểu quy tắc mở rộng cho chuỗi dài hơn)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    DongVat() { cout << "1. DongVat chay" << endl; }
};

class Cho : public DongVat {
public:
    Cho() { cout << "2. Cho chay" << endl; }
};

class ChoConGiong : public Cho {
public:
    ChoConGiong() {
        cout << "3. ChoConGiong chay"
             << endl;
    }
};

int main() {
    ChoConGiong c;
    return 0;
}
```

**Output đã kiểm chứng:**

```
1. DongVat chay
2. Cho chay
3. ChoConGiong chay
```

Với ba tầng (`DongVat` → `Cho` → `ChoConGiong`), thứ tự vẫn đi từ tổ tiên xa nhất đến lớp con cụ thể nhất, bất kể chuỗi kế thừa dài bao nhiêu tầng.

### Ví dụ 3: Lớp con dùng ngay dữ liệu đã được lớp cha khởi tạo (Mục tiêu: hiểu lý do thứ tự này hợp lý)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
protected:
    string ten;
public:
    DongVat(string t) {
        ten = t;
        cout << "Constructor DongVat: da gan ten = " << ten << endl;
    }
};

class Cho : public DongVat {
public:
    Cho(string t) : DongVat(t) {
        // Constructor DongVat da chay TRUOC, nen 'ten' o day CHAC CHAN da co gia tri
        cout << "Constructor Cho: co the dung ngay ten = " << ten << endl;
    }
};

int main() {
    Cho c("Mi Lu");
    return 0;
}
```

**Output đã kiểm chứng:**

```
Constructor DongVat: da gan ten = Mi Lu
Constructor Cho: co the dung ngay ten = Mi Lu
```

`ten` (thuộc tính `protected` kế thừa từ `DongVat`) đã được khởi tạo xong **trước khi** thân Constructor của `Cho` chạy, nên `Cho` dùng ngay giá trị đó mà không lo nó còn rỗng hay chưa xác định.

### Ví dụ 4: Tổng hợp, ba tầng kết hợp gọi tường minh Constructor (Mục tiêu: thấy bức tranh toàn diện)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
protected:
    string ten;
public:
    DongVat(string t) {
        ten = t;
        cout << "[DongVat] ten = "
             << ten << endl;
    }
};

class Cho : public DongVat {
protected:
    string giong;
public:
    Cho(string t, string g) : DongVat(t) {   // Goi tuong minh (bai truoc)
        giong = g;
        cout << "[Cho] giong = "
             << giong << endl;
    }
};

class ChoNghiepVu : public Cho {
public:
    ChoNghiepVu(string t, string g)
        : Cho(t, g) {
        cout << "[ChoNghiepVu] " << ten
             << " " << giong << endl;
    }
};

int main() {
    ChoNghiepVu c("Rex", "Berger");
    return 0;
}
```

**Output đã kiểm chứng:**

```
[DongVat] ten = Rex
[Cho] giong = Berger
[ChoNghiepVu] Rex Berger
```

`ChoNghiepVu` gọi tường minh `Cho(t, g)`, và `Cho` lại gọi tường minh `DongVat(t)`: một "dây chuyền" gọi ngược lên tận gốc. Nhưng thứ tự **chạy thực tế** vẫn đi từ gốc xuống ngọn. Nhờ vậy, khi `ChoNghiepVu` dùng `ten` và `giong`, cả hai đều đã sẵn sàng.

### Ví dụ 5: Destructor chạy ngược lại (Mục tiêu: thấy thứ tự hủy)

```cpp
#include <iostream>
#include <string>
using namespace std;

class DongVat {
public:
    DongVat() { cout << "dung DongVat\n"; }
    ~DongVat() { cout << "go DongVat\n"; }
};

class Cho : public DongVat {
public:
    Cho() { cout << "dung Cho\n"; }
    ~Cho() { cout << "go Cho\n"; }
};

class ChoNghiepVu : public Cho {
public:
    ChoNghiepVu() { cout << "dung CNV\n"; }
    ~ChoNghiepVu() { cout << "go CNV\n"; }
};

int main() {
    ChoNghiepVu c;
    return 0;
}   // toi day, c bi go
```

**Output đã kiểm chứng:**

```
dung DongVat
dung Cho
dung CNV
go CNV
go Cho
go DongVat
```

Ba dòng "dung" đi từ `DongVat` lên `ChoNghiepVu`, ba dòng "go" đi ngược từ `ChoNghiepVu` xuống `DongVat`.

### Xem tháp được xây và dỡ

Mô phỏng dưới đây vẽ đối tượng thành một **tháp** các tầng (móng ở dưới), xây lên và dỡ xuống theo từng dòng code. Bấm **Bước tiếp** để chạy:

- Tab **3 tầng: DongVat, Cho, ChoConGiong**: dòng `ChoConGiong c;` chỉ có một lệnh, nhưng ba tầng lần lượt sáng lên từ móng lên mái, kèm các dòng in số 1, 2, 3.
- Tab **Danh sách khởi tạo: ChoNghiepVu**: dữ liệu `("Rex", "Berger")` được chuyển từ con lên cha qua các lời gọi `: Cho(t, g)` và `: DongVat(t)`, rồi thân các Constructor mới chạy từ cha xuống con. Hai ô `ten` và `giong` lần lượt đầy lên trong hình.
- Tab **Hủy đối tượng: destructor ngược lại**: tới dấu `}` của `main()`, tháp bị dỡ từ mái xuống móng, kèm đường thời gian vòng đời của `c`.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Nghĩ rằng có thể thay đổi thứ tự gọi Constructor**: thứ tự "lớp cha trước, lớp con sau" là quy tắc **cố định** của C++, dù bạn viết code theo thứ tự nào.
- **Cố dùng dữ liệu của lớp cha trước khi nó được khởi tạo**: nhờ đúng thứ tự này, tình huống đó không xảy ra trong C++ (như Ví dụ 3). Hiểu rõ nguyên do giúp bạn biết chắc dữ liệu nào đã sẵn sàng ở từng giai đoạn.
- **Nhầm giữa "thứ tự viết lời gọi" và "thứ tự Constructor thực sự chạy"**: như Ví dụ 4, `ChoNghiepVu` "gọi" `Cho`, `Cho` "gọi" `DongVat` (từ ngọn xuống gốc trong cú pháp), nhưng thứ tự **chạy** lại đi từ gốc (`DongVat`) xuống ngọn (`ChoNghiepVu`).
- **Quên rằng quy tắc áp dụng cho MỌI cấp độ kế thừa**: dù chuỗi kế thừa có 2 tầng hay 10 tầng, "tổ tiên trước, hậu duệ sau" luôn được giữ nguyên (xem Ví dụ 2).
- **Quên Destructor chạy ngược lại**: Destructor của lớp con chạy trước, rồi mới tới lớp cha (xem Ví dụ 5). Destructor của lớp cha tự động được gọi, bạn không cần và không được gọi tường minh.
- **Không tận dụng thứ tự này khi thiết kế lớp**: hãy để lớp cha tự hoàn tất việc khởi tạo dữ liệu nền tảng của nó trong Constructor, để các lớp con yên tâm xây thêm mà không lo dữ liệu kế thừa bị thiếu.
