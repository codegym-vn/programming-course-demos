# Thuộc Tính (Attribute) Và Phương Thức (Method)

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: **Thuộc tính (Attribute)** là dữ liệu mô tả một đối tượng, còn **Phương thức (Method)** là hành động mà đối tượng đó có thể thực hiện.
- Nắm vững cú pháp: cách khai báo thuộc tính, cách khai báo và gọi một phương thức.
- Hiểu được điều đặc biệt quan trọng: một phương thức có thể **truy cập trực tiếp** vào thuộc tính của chính đối tượng đang gọi nó, mà không cần truyền qua tham số hay dùng biến toàn cục.
- Ứng dụng được vào việc viết phương thức có tham số (thay đổi thuộc tính), và phương thức gọi lẫn nhau trong cùng một lớp.

## 2. Giới Thiệu

Ở bài trước, bạn đã thấy thoáng qua cả thuộc tính (`ten`, `tuoi`) và phương thức (`gioiThieu()`) trong cùng một lớp `HocSinh`. Bài này sẽ đi sâu vào phân tích rõ ràng hai thành phần cốt lõi này của một lớp.

Nếu thuộc tính là "những gì một đối tượng **có**" (dữ liệu), thì phương thức là "những gì một đối tượng **có thể làm**" (hành động). Điều đặc biệt thú vị của lập trình hướng đối tượng: một phương thức không cần được "cho biết" nó đang làm việc với đối tượng nào — nó tự động biết và thao tác trên đúng dữ liệu của đối tượng đã gọi nó, không cần truyền thêm bất kỳ tham số nào để "chỉ định" đối tượng đó. Đây chính là điểm khác biệt lớn nhất so với các hàm thông thường đã học ở phần Hàm.

## 3. Khái Niệm

- **Thuộc tính (Attribute)**: biến được khai báo bên trong một lớp, đại diện cho dữ liệu mà mỗi đối tượng của lớp đó sẽ có riêng.
- **Phương thức (Method)**: hàm được khai báo bên trong một lớp, đại diện cho một hành động mà đối tượng có thể thực hiện — có thể truy cập trực tiếp vào các thuộc tính của chính đối tượng đó.
- **Phương thức trả về giá trị**: giống hàm thông thường, một phương thức có thể dùng `return` để trả về kết quả tính toán dựa trên thuộc tính của đối tượng.
- **Phương thức có tham số**: một phương thức có thể nhận thêm dữ liệu từ bên ngoài (qua tham số), rồi dùng nó để thay đổi thuộc tính của đối tượng.

## 4. Giải Thích

### 4.1. Phân Biệt Thuộc Tính Và Phương Thức Trong Một Lớp

```cpp
class HocSinh {
public:
    string ten;          // THUỘC TÍNH - dữ liệu
    int diemToan;        // THUỘC TÍNH - dữ liệu
    int diemVan;         // THUỘC TÍNH - dữ liệu

    void inThongTin() {  // PHƯƠNG THỨC - hành động
        cout << "Hoc sinh: " << ten << ", Toan: " << diemToan << ", Van: " << diemVan << endl;
    }
};
```

Bên trong `inThongTin()`, các thuộc tính `ten`, `diemToan`, `diemVan` được sử dụng **trực tiếp**, không cần truyền chúng làm tham số — phương thức tự động "biết" đây là dữ liệu của đối tượng đang gọi nó. (Thực chất, C++ ngầm đưa cho phương thức một con trỏ tên `this` trỏ tới đối tượng đang gọi; bạn sẽ gặp lại nó ở bài Hàm khởi tạo.)

### 4.2. Phương Thức Trả Về Giá Trị Dựa Trên Thuộc Tính

```cpp
double tinhDiemTrungBinh() {
    return (diemToan + diemVan) / 2.0;
}
```

Phương thức này hoạt động giống hệt một hàm bình thường có `return`, chỉ khác là nó lấy dữ liệu trực tiếp từ thuộc tính của đối tượng, không cần nhận `diemToan`, `diemVan` làm tham số. Chia cho `2.0` (số thực) để ra kết quả có phần lẻ; nếu viết `/ 2` thì phép chia nguyên sẽ cắt phần lẻ.

### 4.3. Phương Thức Có Tham Số — Thay Đổi Thuộc Tính

```cpp
void napTien(double soTien) {
    soDu = soDu + soTien;   // soDu la THUOC TINH, soTien la THAM SO truyen vao
}
```

Phương thức này nhận thêm một tham số bên ngoài (`soTien`), rồi kết hợp nó với thuộc tính hiện có (`soDu`) để cập nhật lại giá trị thuộc tính đó.

## 5. Ví Dụ

Toàn bộ output dưới đây đã được biên dịch và chạy thử thực tế bằng g++ để đảm bảo tính chính xác.

### Ví dụ 1: Phân biệt thuộc tính và phương thức (Mục tiêu: nắm cấu trúc cơ bản của một lớp)

```cpp
#include <iostream>
#include <string>
using namespace std;

class HocSinh {
public:
    string ten;
    int diemToan;
    int diemVan;

    void inThongTin() {
        cout << "Hoc sinh: " << ten << ", Toan: " << diemToan << ", Van: " << diemVan << endl;
    }
};

int main() {
    HocSinh hs;
    hs.ten = "Nguyen Van An";
    hs.diemToan = 8;
    hs.diemVan = 7;

    hs.inThongTin();
    return 0;
}
```

**Output đã kiểm chứng:**

```
Hoc sinh: Nguyen Van An, Toan: 8, Van: 7
```

`ten`, `diemToan`, `diemVan` là thuộc tính — bạn gán giá trị cho chúng từ bên ngoài (`hs.ten = ...`). `inThongTin()` là phương thức — bạn gọi nó (`hs.inThongTin()`), và bên trong nó tự động dùng đúng dữ liệu của `hs`.

### Ví dụ 2: Phương thức trả về giá trị tính toán từ thuộc tính (Mục tiêu: nắm cách viết phương thức có return)

```cpp
#include <iostream>
#include <string>
using namespace std;

class HocSinh {
public:
    string ten;
    int diemToan;
    int diemVan;

    double tinhDiemTrungBinh() {
        return (diemToan + diemVan) / 2.0;
    }
};

int main() {
    HocSinh hs;
    hs.ten = "An";
    hs.diemToan = 8;
    hs.diemVan = 7;

    cout << "Diem trung binh cua " << hs.ten << ": " << hs.tinhDiemTrungBinh() << endl;
    return 0;
}
```

**Output đã kiểm chứng:**

```
Diem trung binh cua An: 7.5
```

Phương thức `tinhDiemTrungBinh()` không cần nhận `diemToan` hay `diemVan` làm tham số — nó tự động truy cập vào thuộc tính của đối tượng `hs` đang gọi nó, tính ra `(8 + 7) / 2.0 = 7.5`.

### Ví dụ 3: Phương thức có tham số làm thay đổi thuộc tính (Mục tiêu: ứng dụng thực tế, kết hợp tham số và thuộc tính)

```cpp
#include <iostream>
#include <string>
using namespace std;

class TaiKhoan {
public:
    string chuTaiKhoan;
    double soDu;

    void napTien(double soTien) {
        soDu = soDu + soTien;
        cout << "Da nap " << soTien << ". So du hien tai: " << soDu << endl;
    }

    void rutTien(double soTien) {
        if (soTien > soDu) {
            cout << "Khong du tien de rut!" << endl;
        } else {
            soDu = soDu - soTien;
            cout << "Da rut " << soTien << ". So du hien tai: " << soDu << endl;
        }
    }
};

int main() {
    TaiKhoan tk;
    tk.chuTaiKhoan = "Nguyen Van An";
    tk.soDu = 100000;

    tk.napTien(50000);
    tk.rutTien(30000);
    tk.rutTien(200000);
    return 0;
}
```

**Output đã kiểm chứng:**

```
Da nap 50000. So du hien tai: 150000
Da rut 30000. So du hien tai: 120000
Khong du tien de rut!
```

`napTien()` và `rutTien()` đều nhận tham số `soTien` từ bên ngoài, rồi kết hợp với thuộc tính `soDu` hiện có của đối tượng để tính ra kết quả mới — `rutTien(200000)` bị từ chối đúng như logic đã viết, vì số dư hiện tại (`120000`) không đủ.

### Ví dụ 4: Nhiều phương thức trong một lớp gọi lẫn nhau (Mục tiêu: thấy sự phối hợp giữa các phương thức)

```cpp
#include <iostream>
#include <string>
using namespace std;

class HocSinh {
public:
    string ten;
    int diemToan;
    int diemVan;

    double tinhDiemTrungBinh() {
        return (diemToan + diemVan) / 2.0;
    }

    string xepLoai() {
        double dtb = tinhDiemTrungBinh();   // Gọi một phương thức khác trong cùng lớp
        if (dtb >= 8.0) return "Gioi";
        else if (dtb >= 6.5) return "Kha";
        else return "Trung binh";
    }

    void inKetQua() {
        cout << ten << " co diem trung binh " << tinhDiemTrungBinh()
             << ", xep loai: " << xepLoai() << endl;
    }
};

int main() {
    HocSinh hs;
    hs.ten = "An";
    hs.diemToan = 9;
    hs.diemVan = 8;

    hs.inKetQua();
    return 0;
}
```

**Output đã kiểm chứng:**

```
An co diem trung binh 8.5, xep loai: Gioi
```

`inKetQua()` gọi cả `tinhDiemTrungBinh()` lẫn `xepLoai()`, và bản thân `xepLoai()` cũng gọi `tinhDiemTrungBinh()` bên trong nó — các phương thức trong cùng một lớp hoàn toàn có thể gọi lẫn nhau, giúp tổ chức code gọn gàng, tránh lặp lại logic tính toán.

### Xem thuộc tính và phương thức hoạt động từng bước

Bấm **Bước tiếp** để xem thẻ đối tượng và các khung phương thức, và để ý những điều mà chữ khó diễn tả:

- Tab **Nạp/rút tiền**: khi gọi `napTien(50000)`, một khung nhỏ mở ra chứa tham số `soTien` từ bên ngoài, còn `soDu` lấy thẳng từ thẻ `tk`; gọi xong, khung biến mất nhưng `soDu` giữ giá trị mới. Ở `rutTien`, hai đèn xanh/đỏ cho thấy phép kiểm tra `soTien > soDu` quyết định có trừ tiền hay không.
- Tab **Phương thức gọi phương thức**: các khung phương thức chồng lên nhau như một chồng nhỏ, và bộ đếm cho thấy `tinhDiemTrungBinh()` bị gọi 2 lần (một lần từ `inKetQua()`, một lần từ `xepLoai()`).

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Nhầm lẫn thuộc tính và phương thức**: thuộc tính là **danh từ** (dữ liệu mô tả đối tượng — tên, tuổi, số dư...), còn phương thức là **động từ** (hành động đối tượng thực hiện — in thông tin, nạp tiền, tính điểm...). Nếu bạn thấy mình đang cố "gán giá trị" cho một thứ có dấu ngoặc đơn `()`, có thể bạn đang nhầm phương thức với thuộc tính.
- **Nghĩ rằng phương thức cần được truyền thuộc tính làm tham số**: đây là khác biệt lớn nhất so với hàm thông thường — phương thức **tự động** có quyền truy cập vào thuộc tính của đối tượng đang gọi nó, không cần truyền `ten`, `diemToan`... làm tham số như một hàm độc lập.
- **Quên rằng mỗi đối tượng gọi phương thức sẽ dùng đúng dữ liệu của chính nó**: nếu có nhiều đối tượng cùng lớp, gọi cùng một phương thức trên các đối tượng khác nhau sẽ cho ra kết quả khác nhau, vì mỗi đối tượng có thuộc tính riêng (đã minh chứng ở bài trước).
- **Không kiểm tra điều kiện hợp lệ trước khi thay đổi thuộc tính qua phương thức**: như Ví dụ 3, phương thức `rutTien()` chủ động kiểm tra `soTien > soDu` trước khi trừ tiền — nếu bỏ qua bước kiểm tra này, số dư có thể trở thành âm một cách vô lý.
- **Viết phương thức quá dài, ôm đồm quá nhiều logic**: như Ví dụ 4, nên chia nhỏ logic thành nhiều phương thức chuyên biệt (`tinhDiemTrungBinh()`, `xepLoai()`) rồi kết hợp chúng lại trong một phương thức tổng hợp (`inKetQua()`) — giúp code dễ đọc, dễ bảo trì, và tái sử dụng được từng phần riêng lẻ khi cần.
