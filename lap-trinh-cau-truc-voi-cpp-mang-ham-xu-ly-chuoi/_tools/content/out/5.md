# Sắp Xếp Mảng (Bubble Sort, Selection Sort)

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: sắp xếp (Sorting) là gì, và tại sao đây là một trong những bài toán quan trọng nhất khi làm việc với mảng.
- Nắm vững thuật toán **Bubble Sort (nổi bọt)**: cách hoạt động, cách cài đặt, và cách tối ưu để dừng sớm khi mảng đã được sắp xếp xong.
- Nắm vững thuật toán **Selection Sort (chọn)**: cách hoạt động và cách cài đặt.
- So sánh được hai thuật toán: điểm giống, điểm khác, và khi nào nên cân nhắc dùng thuật toán nào.
- Quan sát từng lần so sánh và đổi chỗ của hai thuật toán bằng hoạt động mô phỏng.

## 2. Giới Thiệu

Ở các bài trước, bạn đã học cách tính tổng, tìm max/min, đếm số phần tử thỏa điều kiện trên mảng. Nhưng có một bài toán còn phổ biến và quan trọng hơn thế: sắp xếp lại toàn bộ mảng theo thứ tự tăng dần hoặc giảm dần.

Hãy nghĩ đến bảng xếp hạng học sinh theo điểm số, danh sách sản phẩm theo giá tiền, hay danh bạ điện thoại theo tên — tất cả đều cần dữ liệu được **sắp xếp** thì mới dễ đọc, dễ tìm kiếm. Trong bài này, bạn sẽ học hai thuật toán sắp xếp kinh điển nhất, thường là bài học đầu tiên của bất kỳ ai bắt đầu tìm hiểu về thuật toán: **Bubble Sort** (nổi bọt) và **Selection Sort** (chọn).

## 3. Khái Niệm

- **Sắp xếp (Sorting)**: quá trình sắp xếp lại vị trí các phần tử trong mảng theo một thứ tự nhất định (thường là tăng dần hoặc giảm dần).
- **Hoán đổi (Swap)**: thao tác đổi chỗ giá trị của hai phần tử trong mảng, thường cần một biến tạm (`temp`) để không làm mất dữ liệu trong quá trình đổi chỗ.
- **Bubble Sort (Sắp xếp nổi bọt)**: thuật toán so sánh hai phần tử liền kề nhau, hoán đổi nếu chúng sai thứ tự — lặp lại nhiều lượt cho đến khi cả mảng được sắp xếp. Tên gọi "nổi bọt" xuất phát từ việc phần tử lớn nhất sẽ dần "nổi" lên cuối mảng sau mỗi lượt, giống bọt khí nổi lên mặt nước.
- **Selection Sort (Sắp xếp chọn)**: thuật toán tìm phần tử nhỏ nhất trong phần mảng chưa sắp xếp, rồi đưa nó về đúng vị trí — lặp lại cho đến khi toàn bộ mảng được sắp xếp.

## 4. Giải Thích

### 4.1. Thuật Toán Bubble Sort

**Ý tưởng:** so sánh từng cặp phần tử liền kề nhau (`arr[j]` và `arr[j+1]`); nếu `arr[j] > arr[j+1]` (sai thứ tự), hoán đổi chúng. Lặp lại việc này nhiều lượt — sau mỗi lượt, phần tử lớn nhất còn lại sẽ được đẩy về đúng vị trí cuối cùng của nó.

```cpp
int arr[6] = {5, 2, 9, 1, 7, 3};
int n = 6;

for (int i = 0; i < n - 1; i++) {
    for (int j = 0; j < n - 1 - i; j++) {
        if (arr[j] > arr[j + 1]) {
            int temp = arr[j];
            arr[j] = arr[j + 1];
            arr[j + 1] = temp;
        }
    }
}
```

Vòng lặp ngoài (`i`) quyết định số lượt cần chạy, còn vòng lặp trong (`j`) thực hiện việc so sánh và hoán đổi từng cặp liền kề. Phần `n - 1 - i` giúp thu hẹp dần phạm vi so sánh, vì sau mỗi lượt, phần tử lớn nhất đã "nổi" đúng vị trí và không cần xét lại.

### 4.2. Thuật Toán Selection Sort

**Ý tưởng:** ở mỗi lượt, tìm phần tử **nhỏ nhất** trong đoạn mảng còn lại chưa sắp xếp, rồi hoán đổi nó với phần tử đầu tiên của đoạn đó.

```cpp
int arr[6] = {5, 2, 9, 1, 7, 3};
int n = 6;

for (int i = 0; i < n - 1; i++) {
    int viTriNhoNhat = i;
    for (int j = i + 1; j < n; j++) {
        if (arr[j] < arr[viTriNhoNhat]) {
            viTriNhoNhat = j;
        }
    }
    if (viTriNhoNhat != i) {
        int temp = arr[i];
        arr[i] = arr[viTriNhoNhat];
        arr[viTriNhoNhat] = temp;
    }
}
```

Khác với Bubble Sort (hoán đổi liên tục các cặp liền kề), Selection Sort chỉ hoán đổi **đúng một lần** ở cuối mỗi lượt — sau khi đã "chọn" ra được vị trí phần tử nhỏ nhất.

## 5. Ví Dụ

Toàn bộ output dưới đây đã được biên dịch và chạy thử thực tế để đảm bảo tính chính xác. Các ví dụ in mảng bằng một vòng `for` nhỏ (đặt trong chương trình đầy đủ) nên bạn có thể tự chép về máy và chạy lại.

### Ví dụ 1: Bubble Sort — theo dõi từng bước để thấy "bọt nổi lên" (Mục tiêu: hiểu cơ chế hoạt động của Bubble Sort)

```cpp
#include <iostream>
using namespace std;

int main() {
    int arr[6] = {5, 2, 9, 1, 7, 3};
    int n = 6;

    cout << "Ban dau: ";
    for (int k = 0; k < n; k++) {
        cout << arr[k] << " ";
    }
    cout << endl;

    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
        // In mảng sau mỗi lượt
        cout << "Luot " << i + 1 << ": ";
        for (int k = 0; k < n; k++) {
            cout << arr[k] << " ";
        }
        cout << endl;
    }
    return 0;
}
```

**Output đã kiểm chứng, in ra mảng sau mỗi lượt lặp:**

```
Ban dau: 5 2 9 1 7 3 
Luot 1: 2 5 1 7 3 9 
Luot 2: 2 1 5 3 7 9 
Luot 3: 1 2 3 5 7 9 
Luot 4: 1 2 3 5 7 9 
Luot 5: 1 2 3 5 7 9 
```

Quan sát kỹ: sau lượt 1, số `9` (lớn nhất) đã "nổi" hẳn về vị trí cuối cùng. Sau lượt 2, số lớn thứ nhì cũng vào đúng vị trí. Điều thú vị là mảng đã **hoàn toàn sắp xếp xong ngay từ lượt 3**, nhưng thuật toán cơ bản vẫn tiếp tục chạy thêm 2 lượt nữa (4 và 5) một cách lãng phí — đây chính là vấn đề sẽ được giải quyết ở Ví dụ 2.

### Ví dụ 2: Bubble Sort tối ưu — dừng sớm khi không còn hoán đổi (Mục tiêu: hiểu cách tối ưu thuật toán)

```cpp
#include <iostream>
using namespace std;

int main() {
    int arr[6] = {5, 2, 9, 1, 7, 3};
    int n = 6;
    int soLuot = 0;
    bool coHoanDoi;

    for (int i = 0; i < n - 1; i++) {
        soLuot++;
        coHoanDoi = false;
        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
                coHoanDoi = true;
            }
        }
        if (!coHoanDoi) {
            cout << "Khong con hoan doi nao -> dung som!" << endl;
            break;   // Không còn hoán đổi nào -> mảng đã sắp xếp xong, dừng ngay
        }
    }

    cout << "So luot chay thuc te: " << soLuot << endl;
    cout << "Mang sau khi sap xep: ";
    for (int k = 0; k < n; k++) {
        cout << arr[k] << " ";
    }
    cout << endl;
    return 0;
}
```

**Output đã kiểm chứng (trên cùng mảng `{5, 2, 9, 1, 7, 3}`):**

```
Khong con hoan doi nao -> dung som!
So luot chay thuc te: 4
Mang sau khi sap xep: 1 2 3 5 7 9 
```

Nhờ thêm biến cờ hiệu `coHoanDoi`, chương trình phát hiện ra rằng lượt thứ 4 không hề có bất kỳ hoán đổi nào xảy ra — nghĩa là mảng đã sắp xếp xong từ trước đó — và dừng lại ngay, tiết kiệm được lượt lặp cuối cùng so với phiên bản cơ bản ở Ví dụ 1.

### Ví dụ 3: Selection Sort — theo dõi từng bước "chọn" phần tử nhỏ nhất (Mục tiêu: hiểu cơ chế hoạt động của Selection Sort)

```cpp
#include <iostream>
using namespace std;

int main() {
    int arr[6] = {5, 2, 9, 1, 7, 3};
    int n = 6;

    cout << "Ban dau: ";
    for (int k = 0; k < n; k++) {
        cout << arr[k] << " ";
    }
    cout << endl;

    for (int i = 0; i < n - 1; i++) {
        int viTriNhoNhat = i;
        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[viTriNhoNhat]) {
                viTriNhoNhat = j;
            }
        }
        if (viTriNhoNhat != i) {
            int temp = arr[i];
            arr[i] = arr[viTriNhoNhat];
            arr[viTriNhoNhat] = temp;
        }
        // In mảng sau mỗi lượt
        cout << "Luot " << i + 1 << ": ";
        for (int k = 0; k < n; k++) {
            cout << arr[k] << " ";
        }
        cout << endl;
    }
    return 0;
}
```

**Output đã kiểm chứng trên cùng mảng `{5, 2, 9, 1, 7, 3}`:**

```
Ban dau: 5 2 9 1 7 3 
Luot 1: 1 2 9 5 7 3 
Luot 2: 1 2 9 5 7 3 
Luot 3: 1 2 3 5 7 9 
Luot 4: 1 2 3 5 7 9 
Luot 5: 1 2 3 5 7 9 
```

Ở lượt 1, thuật toán tìm ra `1` (số nhỏ nhất trong toàn mảng, đang ở chỉ số 3) và hoán đổi nó lên đầu. Ở lượt 2, số nhỏ nhất trong phần còn lại (`2, 9, 5, 7, 3`) chính là `2` — nhưng nó đã sẵn ở đúng vị trí, nên **không cần hoán đổi** (mảng không đổi). Đây là điểm khác biệt quan trọng so với Bubble Sort: Selection Sort chỉ hoán đổi khi thực sự cần thiết.

### Ví dụ 4: So sánh số lần hoán đổi giữa Bubble Sort và Selection Sort (Mục tiêu: so sánh hai thuật toán)

Chạy cả hai thuật toán trên cùng một mảng `{5, 2, 9, 1, 7, 3}`, mỗi thuật toán dùng một bản sao của mảng và một biến đếm số lần hoán đổi thực tế:

```cpp
#include <iostream>
using namespace std;

int main() {
    int a[6] = {5, 2, 9, 1, 7, 3};   // bản sao cho Bubble Sort
    int b[6] = {5, 2, 9, 1, 7, 3};   // bản sao cho Selection Sort
    int n = 6;
    int doiBubble = 0, doiSelection = 0;

    // Bubble Sort
    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - 1 - i; j++) {
            if (a[j] > a[j + 1]) {
                int temp = a[j];
                a[j] = a[j + 1];
                a[j + 1] = temp;
                doiBubble++;
            }
        }
    }

    // Selection Sort
    for (int i = 0; i < n - 1; i++) {
        int viTriNhoNhat = i;
        for (int j = i + 1; j < n; j++) {
            if (b[j] < b[viTriNhoNhat]) {
                viTriNhoNhat = j;
            }
        }
        if (viTriNhoNhat != i) {
            int temp = b[i];
            b[i] = b[viTriNhoNhat];
            b[viTriNhoNhat] = temp;
            doiSelection++;
        }
    }

    cout << "So lan hoan doi cua Bubble Sort: " << doiBubble << endl;
    cout << "So lan hoan doi cua Selection Sort: " << doiSelection << endl;
    return 0;
}
```

**Output đã kiểm chứng:**

```
So lan hoan doi cua Bubble Sort: 8
So lan hoan doi cua Selection Sort: 2
```

Đây là sự khác biệt cốt lõi giữa hai thuật toán: Bubble Sort hoán đổi bất kỳ khi nào phát hiện một cặp liền kề sai thứ tự (dẫn đến rất nhiều lần hoán đổi nhỏ), trong khi Selection Sort chỉ hoán đổi **đúng một lần** ở cuối mỗi lượt (sau khi đã "chọn" được vị trí chính xác). Với cùng một mảng 6 phần tử, Selection Sort chỉ cần 2 lần hoán đổi so với 8 lần của Bubble Sort — đây là lý do Selection Sort thường được ưu tiên trong các tình huống mà thao tác hoán đổi có chi phí cao (ví dụ hoán đổi các bản ghi dữ liệu lớn).

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Quên dùng biến tạm (`temp`) khi hoán đổi**: nếu viết `arr[j] = arr[j+1]; arr[j+1] = arr[j];` mà không qua biến tạm, giá trị gốc của `arr[j]` sẽ bị ghi đè và mất trước khi kịp gán cho `arr[j+1]` — kết quả là cả hai vị trí đều mang cùng một giá trị, không phải hoán đổi thực sự.
- **Sai phạm vi vòng lặp trong ở Bubble Sort**: dùng `n - 1 - i` (thu hẹp dần) chứ không phải cố định `n - 1` cho mọi lượt — nếu không thu hẹp, thuật toán vẫn sắp xếp đúng nhưng thực hiện thừa nhiều phép so sánh không cần thiết ở những vị trí đã chắc chắn đúng.
- **Quên khởi tạo lại `coHoanDoi = false` ở đầu mỗi lượt trong bản Bubble Sort tối ưu**: nếu không đặt lại giá trị này về `false` trước mỗi lượt, biến cờ hiệu sẽ giữ nguyên giá trị `true` từ lượt trước, khiến thuật toán không bao giờ nhận ra được lúc nào nên dừng sớm.
- **Nhầm lẫn dấu so sánh**: trong Selection Sort, `arr[j] < arr[viTriNhoNhat]` dùng để tìm giá trị **nhỏ nhất** — nếu lỡ đổi thành `>`, thuật toán sẽ vô tình sắp xếp mảng theo thứ tự **giảm dần** thay vì tăng dần như mong muốn. Với Bubble Sort, đổi `arr[j] > arr[j + 1]` thành `<` cũng cho kết quả giảm dần.
- **Nghĩ rằng Bubble Sort và Selection Sort luôn cho tốc độ giống nhau**: dù cả hai đều có độ phức tạp thời gian tương đương nhau về mặt lý thuyết (phải so sánh nhiều cặp phần tử), số lần hoán đổi thực tế lại khác biệt rõ rệt như đã minh chứng ở Ví dụ 4 — đây là yếu tố cần cân nhắc khi thao tác hoán đổi tốn nhiều tài nguyên hơn thao tác so sánh.
