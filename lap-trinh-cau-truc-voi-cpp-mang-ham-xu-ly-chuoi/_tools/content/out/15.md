# Nạp Chồng Hàm (Function Overloading)

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: **nạp chồng hàm (Function Overloading)** là gì — nhiều hàm cùng tên nhưng khác nhau về tham số.
- Nắm vững quy tắc: C++ phân biệt các hàm nạp chồng dựa trên **số lượng** và/hoặc **kiểu dữ liệu** của tham số — chứ không dựa vào kiểu trả về hay tên tham số.
- Ứng dụng được vào việc viết các phiên bản hàm cùng tên để xử lý nhiều loại dữ liệu hoặc số lượng đầu vào khác nhau.
- Tránh được hai lỗi phổ biến: nạp chồng không hợp lệ (chỉ khác kiểu trả về, hoặc trùng hoàn toàn danh sách tham số), và lỗi gọi hàm mơ hồ (ambiguous call).

## 2. Giới Thiệu

Ở các bài trước, mỗi hàm bạn viết đều có một cái tên riêng biệt — `tinhTong`, `tinhDienTich`, `swap`... Nhưng đôi khi, bạn muốn có nhiều phiên bản của **cùng một hành động logic**, chỉ khác nhau ở loại hoặc số lượng dữ liệu đầu vào. Ví dụ: một hàm "tính tổng" có thể cần cộng hai số nguyên, hai số thực, hoặc thậm chí nối hai chuỗi ký tự lại với nhau.

Thay vì phải đặt tên khác nhau cho từng phiên bản (`tinhTongInt`, `tinhTongDouble`, `noiChuoi`...), C++ cho phép bạn giữ nguyên **cùng một tên hàm**, miễn là danh sách tham số của chúng khác nhau. Đây gọi là **nạp chồng hàm (Function Overloading)** — trình biên dịch sẽ tự động chọn đúng phiên bản phù hợp dựa vào đối số bạn truyền vào khi gọi hàm.

## 3. Khái Niệm

- **Nạp chồng hàm (Function Overloading)**: tính năng cho phép nhiều hàm có **cùng tên**, nhưng khác nhau về số lượng tham số và/hoặc kiểu dữ liệu của tham số.
- **Chữ ký hàm (Function Signature)**: "dấu vân tay" để phân biệt các hàm nạp chồng với nhau — bao gồm tên hàm và danh sách kiểu dữ liệu của tham số (không bao gồm kiểu trả về, không bao gồm tên tham số).
- **Lỗi gọi hàm mơ hồ (Ambiguous Call)**: lỗi biên dịch xảy ra khi trình biên dịch không thể xác định chắc chắn nên gọi phiên bản nạp chồng nào, vì đối số truyền vào có thể phù hợp với nhiều phiên bản như nhau.

## 4. Giải Thích

### 4.1. Nạp Chồng Theo Số Lượng Tham Số

```
int tinhTong(int a, int b) {
    return a + b;
}

int tinhTong(int a, int b, int c) {
    return a + b + c;
}
```

Khi gọi `tinhTong(3, 4)`, trình biên dịch tự động chọn phiên bản 2 tham số; khi gọi `tinhTong(3, 4, 5)`, nó tự động chọn phiên bản 3 tham số.

### 4.2. Nạp Chồng Theo Kiểu Dữ Liệu Tham Số

Ngay cả khi số lượng tham số giống nhau, chỉ cần **kiểu dữ liệu** khác nhau, đó vẫn được coi là nạp chồng hợp lệ — ví dụ một phiên bản nhận `int`, một phiên bản nhận `double`, một phiên bản khác nhận `string`.

### 4.3. Quy Tắc Quan Trọng: Không Được Chỉ Khác Kiểu Trả Về

Đây là điểm dễ gây nhầm lẫn nhất: C++ **không** coi hai hàm là khác nhau nếu chúng chỉ khác kiểu trả về, trong khi danh sách tham số hoàn toàn giống hệt nhau — kể cả khi tên tham số khác nhau. Trình biên dịch chỉ quan tâm đến **kiểu dữ liệu** của tham số, không quan tâm đến tên gọi hay ý nghĩa của chúng — chi tiết minh chứng cụ thể ở Ví dụ 3 và 6.

### 4.4. Khi Đối Số Không Khớp Hoàn Toàn Với Phiên Bản Nào

Trình biên dịch chọn phiên bản khớp **tốt nhất**: khớp chính xác kiểu là tốt nhất, rồi đến thăng cấp kiểu (như `float` lên `double`), cuối cùng là chuyển đổi kiểu (như `int` sang `float` hoặc `double`). Nếu có đúng một phiên bản thắng rõ ràng thì nó được gọi; nếu hai phiên bản ngang hạng nhau thì đó là lỗi gọi hàm mơ hồ (Ví dụ 4).

## 5. Ví Dụ

Toàn bộ output và thông báo lỗi dưới đây đã được biên dịch, chạy thử thực tế để đảm bảo tính chính xác. Thông báo lỗi được ghi theo g++.

### Ví dụ 1: Nạp chồng theo số lượng tham số (Mục tiêu: nắm quy tắc cơ bản nhất)

```cpp
#include <iostream>
#include <string>
using namespace std;

int tinhTong(int a, int b) {
    return a + b;
}

int tinhTong(int a, int b, int c) {
    return a + b + c;
}

int main() {
    cout << "Tong 2 so: " << tinhTong(3, 4) << endl;
    cout << "Tong 3 so: " << tinhTong(3, 4, 5) << endl;
}
```

**Output đã kiểm chứng:**

```
Tong 2 so: 7
Tong 3 so: 12
```

### Ví dụ 2: Nạp chồng theo kiểu dữ liệu tham số (Mục tiêu: mở rộng quy tắc sang kiểu dữ liệu)

```cpp
#include <iostream>
#include <string>
using namespace std;

int tinhTong(int a, int b) {
    return a + b;
}

double tinhTong(double a, double b) {
    return a + b;
}

string tinhTong(string a, string b) {
    return a + b;    // Với string, dấu + có nghĩa là NỐI CHUỖI
}

int main() {
    cout << "tinhTong(3, 4) = " << tinhTong(3, 4) << endl;
    cout << "tinhTong(3.5, 4.2) = " << tinhTong(3.5, 4.2) << endl;
    cout << "tinhTong(\"Hello \", \"World\") = " << tinhTong("Hello ", "World") << endl;
}
```

**Output đã kiểm chứng:**

```
tinhTong(3, 4) = 7
tinhTong(3.5, 4.2) = 7.7
tinhTong("Hello ", "World") = Hello World
```

Cùng một tên hàm `tinhTong`, nhưng với `string`, phép `+` mang ý nghĩa hoàn toàn khác (nối chuỗi thay vì cộng số) — trình biên dịch tự động chọn đúng phiên bản dựa vào kiểu dữ liệu của đối số truyền vào. Với hai chuỗi trong ngoặc kép, chỉ có phiên bản `string` dùng được (chữ không đổi được thành số), nên trình biên dịch tự chuyển chúng thành `string` và chọn phiên bản này.

### Ví dụ 3: Lỗi — chỉ khác kiểu trả về không được coi là nạp chồng hợp lệ (Mục tiêu: tránh lỗi phổ biến)

```cpp
#include <iostream>
#include <string>
using namespace std;

int layGiaTri(int a, int b) {
    return a + b;
}

double layGiaTri(int a, int b) {   // Chỉ khác kiểu TRẢ VỀ, tham số giống hệt
    return (double)(a + b);
}

int main() {
    cout << layGiaTri(3, 4) << endl;
}
```

**Thông báo lỗi biên dịch thực tế:**

```
error: ambiguating new declaration of 'double layGiaTri(int, int)'
```

Vì hai hàm có danh sách tham số **giống hệt nhau** (`int, int`), trình biên dịch coi đây là cùng một hàm được định nghĩa hai lần — kiểu trả về khác nhau (`int` và `double`) không đủ để phân biệt chúng thành hai hàm nạp chồng riêng biệt.

### Ví dụ 4: Lỗi gọi hàm mơ hồ — ambiguous call (Mục tiêu: tránh lỗi thiết kế nạp chồng thiếu cẩn thận)

```cpp
#include <iostream>
#include <string>
using namespace std;

void inSo(float x) {
    cout << "Phien ban FLOAT: " << x << endl;
}

void inSo(double x) {
    cout << "Phien ban DOUBLE: " << x << endl;
}

int main() {
    inSo(5);   // Truyền int - không rõ nên chuyển thành float hay double!
}
```

**Thông báo lỗi biên dịch thực tế:**

```
error: call of overloaded 'inSo(int)' is ambiguous
```

Khi truyền một số nguyên `5` (kiểu `int`), C++ cần tự động chuyển đổi nó sang `float` hoặc `double` để khớp với một trong hai phiên bản — nhưng cả hai cách chuyển đổi đều "ngang sức" như nhau, khiến trình biên dịch không thể quyết định nên chọn phiên bản nào, và từ chối biên dịch hoàn toàn thay vì đoán bừa. Cách sửa: truyền đúng kiểu, ví dụ `inSo(5.0)` sẽ khớp chính xác với phiên bản `double` và in ra `Phien ban DOUBLE: 5`.

### Ví dụ 5: Ứng dụng thực tế — tính diện tích cho nhiều hình khác nhau (Mục tiêu: ứng dụng nạp chồng vào bài toán thực tế)

```cpp
#include <iostream>
#include <string>
using namespace std;

double tinhDienTich(double canh) {              // Hình vuông - 1 tham số
    return canh * canh;
}

double tinhDienTich(double dai, double rong) {  // Hình chữ nhật - 2 tham số
    return dai * rong;
}

int main() {
    cout << "Dien tich hinh vuong (canh=4): " << tinhDienTich(4) << endl;
    cout << "Dien tich hinh chu nhat (5x3): " << tinhDienTich(5, 3) << endl;
}
```

**Output đã kiểm chứng:**

```
Dien tich hinh vuong (canh=4): 16
Dien tich hinh chu nhat (5x3): 15
```

Nhờ nạp chồng theo **số lượng tham số**, cả hình vuông và hình chữ nhật đều dùng chung tên hàm `tinhDienTich`, giúp code gọi hàm trở nên trực quan và dễ nhớ hơn — không cần phải nhớ những cái tên riêng biệt như `tinhDienTichHinhVuong`, `tinhDienTichHinhChuNhat`.

### Ví dụ 6: Lỗi — không thể nạp chồng nếu danh sách tham số trùng nhau, dù ý nghĩa khác biệt (Mục tiêu: hiểu sâu giới hạn của nạp chồng hàm)

```cpp
#include <iostream>
#include <string>
using namespace std;

const double PI = 3.14159;

double tinhDienTich(double canh) {       // Dự định cho hình vuông
    return canh * canh;
}

double tinhDienTich(double banKinh) {    // Dự định cho hình tròn - CÙNG kiểu (double)!
    return PI * banKinh * banKinh;
}

int main() {
    cout << tinhDienTich(2.0) << endl;
}
```

**Thông báo lỗi biên dịch thực tế:**

```
error: redefinition of 'double tinhDienTich(double)'
```

Đây là điểm rất dễ bị bỏ qua: dù `canh` (cạnh hình vuông) và `banKinh` (bán kính hình tròn) mang ý nghĩa hoàn toàn khác nhau đối với con người, trình biên dịch **chỉ nhìn vào kiểu dữ liệu** (`double`) — với nó, hai hàm này có chữ ký giống hệt nhau, nên bị coi là định nghĩa trùng lặp. Muốn tính diện tích hình tròn, bắt buộc phải đặt một tên hàm khác (ví dụ `tinhDienTichTron`), vì không thể dựa vào "ý nghĩa" của tham số để nạp chồng.

### Xem nạp chồng hàm từng bước

Mô phỏng dưới đây vẽ mỗi phiên bản hàm thành một "cửa" có ghi chữ ký. Bấm **Bước tiếp** để chạy từng dòng code và để ý những điều mà chữ khó diễn tả:

- Tab **Chọn phiên bản**: mỗi lời gọi thử qua cả bốn cửa; cửa sai số lượng bị loại ngay, cửa khớp chính xác sáng xanh, cửa chỉ khớp nhờ đổi kiểu sáng vàng và thua cửa xanh.
- Tab **Nạp chồng không hợp lệ**: trên cửa chỉ ghi tên hàm và kiểu tham số, nên cửa thứ hai (chỉ khác kiểu trả về, hoặc chỉ khác tên tham số) chồng khít lên cửa cũ và bật đèn đỏ.
- Tab **Gọi mơ hồ**: `inSo(5.0)` có cửa `double` sáng xanh, còn `inSo(5)` làm cả hai cửa sáng vàng ngang nhau nên máy không chọn được.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Nghĩ rằng chỉ cần khác kiểu trả về là đủ để nạp chồng**: đây là lỗi phổ biến nhất (xem lại Ví dụ 3) — C++ luôn yêu cầu danh sách tham số (số lượng hoặc kiểu dữ liệu) phải khác nhau, kiểu trả về không được tính vào việc phân biệt các hàm nạp chồng.
- **Nghĩ rằng tên tham số khác nhau giúp phân biệt được các hàm nạp chồng**: như đã minh chứng ở Ví dụ 6, trình biên dịch hoàn toàn không quan tâm đến tên tham số (`canh` hay `banKinh`) — chỉ kiểu dữ liệu (`double`) mới có ý nghĩa trong việc phân biệt.
- **Thiết kế nạp chồng dễ gây mơ hồ khi gọi**: khi có nhiều phiên bản nạp chồng với các kiểu dữ liệu "gần giống nhau" (như `float` và `double`), cần cẩn trọng với các lời gọi hàm dùng kiểu dữ liệu trung gian (như `int`) có thể gây ra lỗi gọi hàm mơ hồ (xem lại Ví dụ 4).
- **Lạm dụng nạp chồng cho những hàm có ý nghĩa hoàn toàn khác nhau**: nạp chồng nên dùng cho các phiên bản của **cùng một hành động logic** (như tính diện tích, tính tổng) áp dụng cho nhiều loại dữ liệu khác nhau — nếu hai hàm có ý nghĩa hoàn toàn không liên quan đến nhau, nên đặt tên riêng biệt để tránh gây nhầm lẫn cho người đọc code, dù về mặt kỹ thuật vẫn có thể nạp chồng được (nếu tham số khác kiểu).
- **Quên rằng nạp chồng là một tính năng của biên dịch tĩnh (compile-time)**: C++ quyết định gọi phiên bản nạp chồng nào **ngay tại thời điểm biên dịch**, dựa vào kiểu dữ liệu của đối số được nhìn thấy trong code — đây là điểm khác biệt quan trọng so với các cơ chế "đa hình" (polymorphism) khác sẽ học ở các bài nâng cao hơn về lập trình hướng đối tượng.
