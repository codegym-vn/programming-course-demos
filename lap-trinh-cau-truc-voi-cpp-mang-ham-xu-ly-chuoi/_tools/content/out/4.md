# Các phép tính toán trên mảng

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: hầu hết các phép tính toán trên mảng đều dựa trên cùng một nguyên lý — dùng một biến "tích lũy" (accumulator) và cập nhật nó trong khi duyệt qua từng phần tử.
- Ứng dụng được vào việc tính tổng và trung bình cộng của toàn bộ mảng.
- Ứng dụng được vào việc tìm giá trị lớn nhất (max) và nhỏ nhất (min), cùng vị trí của chúng trong mảng.
- Ứng dụng được vào việc đếm và tính tổng theo điều kiện — ví dụ tách riêng số dương, số âm.
- Quan sát biến tích lũy thay đổi sau từng ô của mảng bằng hoạt động mô phỏng.

## 2. Giới Thiệu

Ở bài trước, bạn đã học kỹ thuật duyệt mảng — biết khi nào dừng sớm, khi nào phải duyệt hết. Bài này sẽ đưa kỹ thuật đó vào ứng dụng thực tế: **tính toán ra một kết quả cụ thể** từ toàn bộ dữ liệu trong mảng.

Điều thú vị là dù bài toán trông có vẻ khác nhau — tính tổng, tìm số lớn nhất, đếm số dương — chúng đều tuân theo cùng một khuôn mẫu chung: **khởi tạo một biến "kết quả tạm" trước vòng lặp, rồi cập nhật biến đó sau mỗi lần xét một phần tử mới.** Nắm vững khuôn mẫu này, bạn sẽ giải quyết được hầu hết các bài toán tính toán trên mảng mà không cần học thuộc lòng từng công thức riêng lẻ.

## 3. Khái Niệm

- **Biến tích lũy (Accumulator)**: biến dùng để lưu trữ kết quả tạm thời, được cập nhật liên tục sau mỗi lần xét một phần tử trong vòng lặp — ví dụ biến `tong` trong bài toán tính tổng.
- **Giá trị khởi tạo (Initial value)**: giá trị ban đầu của biến tích lũy trước khi vòng lặp bắt đầu — phải chọn đúng để không làm sai lệch kết quả cuối cùng (ví dụ `tong = 0` khi tính tổng, nhưng phải là `arr[0]` khi tìm max/min, không thể là `0`).
- **Trung bình cộng (Average)**: tổng của tất cả các phần tử, chia cho số lượng phần tử.

### 4.2. Lưu Ý Quan Trọng Khi Tìm Max/Min

Với bài toán tính tổng, giá trị khởi tạo hợp lý là `0` (vì cộng thêm 0 không làm thay đổi kết quả). Nhưng với bài toán tìm max/min, khởi tạo bằng `0` là một sai lầm phổ biến — nếu mảng toàn số âm, giá trị `0` sẽ bị nhầm là max. Cách đúng là **luôn khởi tạo bằng chính phần tử đầu tiên của mảng** (`arr[0]`), sau đó mới duyệt từ phần tử thứ hai (`i = 1`) trở đi để so sánh — chi tiết minh họa ở Ví dụ 2.

## 5. Ví Dụ

Toàn bộ output dưới đây đã được biên dịch và chạy thử thực tế để đảm bảo tính chính xác.

### Ví dụ 1: Tính tổng và trung bình cộng (Mục tiêu: nắm khuôn mẫu tích lũy cơ bản nhất)

```cpp
int arr[6] = {8, 5, 9, 3, 7, 6};
int n = 6;
int tong = 0;

for (int i = 0; i < n; i++) {
    tong += arr[i];
}

double trungBinh = (double)tong / n;

cout << "Tong: " << tong << endl;
cout << "Trung binh cong: " << trungBinh << endl;
```

**Output đã kiểm chứng:**

```
Tong: 38
Trung binh cong: 6.33333
```

Lưu ý dòng `(double)tong / n`: nếu không ép kiểu `(double)`, phép chia giữa hai số nguyên (`tong` và `n`) sẽ tự động cắt bỏ phần thập phân, cho ra kết quả sai là `6` thay vì `6.33333` — đây là lỗi rất dễ mắc phải khi tính trung bình cộng, đã được học ở bài Toán tử.

### Ví dụ 2: Tìm giá trị lớn nhất và nhỏ nhất, kèm vị trí (Mục tiêu: ứng dụng tìm max/min)

```cpp
int arr[6] = {8, 5, 9, 3, 7, 6};
int n = 6;

int maxVal = arr[0];    // Khởi tạo bằng phần tử ĐẦU TIÊN, không phải 0
int viTriMax = 0;
int minVal = arr[0];
int viTriMin = 0;

for (int i = 1; i < n; i++) {     // Bắt đầu từ i = 1, vì arr[0] đã được dùng để khởi tạo
    if (arr[i] > maxVal) {
        maxVal = arr[i];
        viTriMax = i;
    }
    if (arr[i] < minVal) {
        minVal = arr[i];
        viTriMin = i;
    }
}

cout << "Gia tri lon nhat: " << maxVal << " (tai chi so " << viTriMax << ")" << endl;
cout << "Gia tri nho nhat: " << minVal << " (tai chi so " << viTriMin << ")" << endl;
```

**Output đã kiểm chứng:**

```
Gia tri lon nhat: 9 (tai chi so 2)
Gia tri nho nhat: 3 (tai chi so 3)
```

Chương trình không chỉ tìm ra giá trị lớn nhất/nhỏ nhất, mà còn ghi nhớ luôn **vị trí (chỉ số)** của chúng — kỹ thuật này rất hữu ích khi bạn cần biết "học sinh nào có điểm cao nhất", chứ không chỉ đơn thuần "điểm cao nhất là bao nhiêu".

### Ví dụ 3: Đếm số lượng số dương, số âm, và số 0 (Mục tiêu: ứng dụng đếm theo điều kiện)

```cpp
int arr[8] = {5, -3, 8, -7, 0, 12, -1, 4};
int n = 8;
int demDuong = 0, demAm = 0, demKhong = 0;

for (int i = 0; i < n; i++) {
    if (arr[i] > 0) {
        demDuong++;
    } else if (arr[i] < 0) {
        demAm++;
    } else {
        demKhong++;
    }
}

cout << "So duong: " << demDuong << endl;
cout << "So am: " << demAm << endl;
cout << "So khong: " << demKhong << endl;
```

**Output đã kiểm chứng:**

```
So duong: 4
So am: 3
So khong: 1
```

Ví dụ này cho thấy bạn hoàn toàn có thể dùng **nhiều biến tích lũy cùng lúc** trong một vòng lặp duy nhất — không cần phải duyệt mảng ba lần riêng biệt cho ba phép đếm khác nhau.

### Ví dụ 4: Tính tổng riêng của số dương và tổng riêng của số âm (Mục tiêu: kết hợp nhiều phép tính toán trong một lần duyệt)

```cpp
int arr[8] = {5, -3, 8, -7, 0, 12, -1, 4};
int n = 8;
int tongDuong = 0, tongAm = 0;

for (int i = 0; i < n; i++) {
    if (arr[i] > 0) {
        tongDuong += arr[i];
    } else if (arr[i] < 0) {
        tongAm += arr[i];
    }
}

cout << "Tong cac so duong: " << tongDuong << endl;
cout << "Tong cac so am: " << tongAm << endl;
```

**Output đã kiểm chứng:**

```
Tong cac so duong: 29
Tong cac so am: -11
```

Đây là minh chứng rõ ràng cho sức mạnh của khuôn mẫu tích lũy: chỉ với **một lần duyệt mảng duy nhất**, chương trình đã tính ra được cả tổng số dương (`29 = 5+8+12+4`) lẫn tổng số âm (`-11 = -3-7-1`) — hiệu quả hơn nhiều so với việc viết hai vòng lặp riêng biệt cho từng phép tính.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Khởi tạo sai giá trị ban đầu khi tìm max/min**: khởi tạo `maxVal = 0` là lỗi phổ biến nhất — nếu mảng chứa toàn số âm, kết quả tìm được sẽ luôn sai là `0` (vì `0` lớn hơn mọi số âm). Luôn khởi tạo bằng `arr[0]` như đã minh họa ở Ví dụ 2.
- **Quên ép kiểu khi tính trung bình cộng**: phép chia `tong / n` giữa hai số nguyên sẽ tự động cắt bỏ phần thập phân — luôn ép kiểu ít nhất một trong hai toán hạng về `double` hoặc `float` trước khi chia, như đã minh họa ở Ví dụ 1. Lưu ý viết `(double)(tong / n)` vẫn sai, vì phép chia nguyên đã xảy ra trước khi ép kiểu; phải ép `tong` trước: `(double)tong / n`.
- **Quên khởi tạo biến tích lũy về giá trị đúng trước vòng lặp**: nếu biến `tong` hay `demDuong` không được khởi tạo rõ ràng trước khi vào vòng lặp, giá trị ban đầu sẽ là rác không xác định, khiến toàn bộ kết quả tính toán trở nên vô nghĩa.
- **Nhầm lẫn giữa "đếm số lượng" và "tính tổng"**: đây là hai phép tính khác nhau dù cấu trúc code rất giống nhau — đếm số lượng dùng `demDuong++` (tăng 1 mỗi lần), còn tính tổng dùng `tongDuong += arr[i]` (cộng dồn giá trị thực). Nhầm lẫn hai thao tác này là lỗi rất dễ mắc khi mới học.
- **Nguy cơ tràn số (overflow) khi tính tổng mảng lớn**: nếu mảng có rất nhiều phần tử với giá trị lớn, biến `tong` kiểu `int` có thể bị tràn số (vượt quá khoảng ±2,147 tỷ đã học ở bài Kiểu dữ liệu). Với các mảng dữ liệu lớn trong thực tế, nên cân nhắc dùng kiểu `long long` cho biến tích lũy để an toàn hơn.
