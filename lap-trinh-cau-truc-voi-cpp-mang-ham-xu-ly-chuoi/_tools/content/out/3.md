# Kỹ thuật duyệt mảng

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: "duyệt mảng" là gì — kỹ thuật lặp qua từng phần tử để đọc hoặc xử lý dữ liệu.
- Nắm vững hai kỹ thuật duyệt cơ bản: duyệt xuôi (từ đầu đến cuối) và duyệt ngược (từ cuối về đầu).
- Ứng dụng được vào bài toán tìm kiếm tuyến tính (Linear Search) — tìm phần tử đầu tiên thỏa điều kiện, và biết dừng sớm bằng `break` khi đã tìm thấy.
- Phân biệt được rạch ròi: khi nào nên dừng sớm khi duyệt, khi nào **bắt buộc** phải duyệt qua toàn bộ mảng (như khi đếm số phần tử thỏa điều kiện).

## 2. Giới Thiệu

Ở hai bài trước, bạn đã dùng vòng lặp `for` để nhập và xuất toàn bộ mảng — đây thực chất chính là một dạng "duyệt mảng" đơn giản nhất. Nhưng **duyệt mảng (Array Traversal)** còn là nền tảng cho rất nhiều bài toán quan trọng khác: tìm một phần tử cụ thể, đếm xem có bao nhiêu phần tử thỏa một điều kiện, hay xử lý dữ liệu theo một thứ tự khác với thứ tự lưu trữ ban đầu.

Điểm mấu chốt của bài này không chỉ là "biết cách lặp qua mảng", mà là hiểu được **khi nào nên dừng lại sớm** (tiết kiệm thời gian xử lý) và **khi nào bắt buộc phải đi hết toàn bộ mảng** (để không bỏ sót dữ liệu). Đây là một trong những quyết định quan trọng nhất khi thiết kế thuật toán xử lý mảng, và cũng là nơi người mới học rất dễ mắc lỗi logic.

## 3. Khái Niệm

- **Duyệt mảng (Array Traversal)**: kỹ thuật lặp qua lần lượt từng phần tử của mảng để đọc, kiểm tra, hoặc xử lý dữ liệu.
- **Duyệt xuôi**: duyệt mảng theo thứ tự chỉ số tăng dần, từ `0` đến `n-1`.
- **Duyệt ngược**: duyệt mảng theo thứ tự chỉ số giảm dần, từ `n-1` về `0`.
- **Tìm kiếm tuyến tính (Linear Search)**: kỹ thuật duyệt qua từng phần tử để tìm phần tử đầu tiên thỏa một điều kiện cho trước, thường kết hợp với `break` để dừng ngay khi tìm thấy.
- **Duyệt đầy đủ (Full traversal)**: trường hợp bắt buộc phải xét qua **toàn bộ** phần tử của mảng, không được dừng sớm — ví dụ khi cần đếm tổng số phần tử thỏa điều kiện.

## 4. Giải Thích

### 4.1. Duyệt Xuôi Và Duyệt Ngược

```
// Duyệt xuôi
for (int i = 0; i < n; i++) {
    // xử lý arr[i]
}

// Duyệt ngược
for (int i = n - 1; i >= 0; i--) {
    // xử lý arr[i]
}
```

Về mặt kết quả cuối cùng (ví dụ tính tổng), hai cách duyệt này cho ra kết quả giống hệt nhau. Nhưng thứ tự xử lý lại hoàn toàn khác nhau — điều này rất quan trọng khi bạn cần in dữ liệu theo một thứ tự cụ thể, hoặc khi cần tìm phần tử **cuối cùng** thỏa điều kiện (duyệt ngược sẽ tìm ra nó đầu tiên).

### 4.2. Khi Nào Nên Dừng Sớm (Dùng break)?

Khi bài toán chỉ cần tìm **một** kết quả duy nhất (ví dụ: "tìm phần tử đầu tiên bằng X"), việc dừng lại ngay khi tìm thấy sẽ tiết kiệm được thời gian xử lý — không cần lãng phí công sức kiểm tra các phần tử còn lại một khi mục tiêu đã đạt được. Đây chính là bản chất của tìm kiếm tuyến tính, minh họa cụ thể ở Ví dụ 2. Lưu ý: `break` chỉ thoát khỏi vòng lặp **trong cùng** chứa nó.

### 4.3. Khi Nào Bắt Buộc Phải Duyệt Hết?

Ngược lại, khi bài toán cần một kết quả **tổng hợp** dựa trên toàn bộ dữ liệu (ví dụ: "đếm có bao nhiêu phần tử chẵn"), bạn **không được phép** dừng sớm — vì dừng giữa chừng đồng nghĩa với việc bỏ sót một phần dữ liệu chưa được xét đến, dẫn đến kết quả sai hoàn toàn. Chi tiết minh chứng cụ thể (bao gồm cả trường hợp dùng sai) ở Ví dụ 3 và 4.

## 5. Ví Dụ

Toàn bộ output dưới đây đã được biên dịch và chạy thử thực tế để đảm bảo tính chính xác.

### Ví dụ 1: Duyệt xuôi và duyệt ngược trên cùng một mảng (Mục tiêu: nắm vững hai kỹ thuật duyệt cơ bản)

```cpp
#include <iostream>
using namespace std;

int main() {
    int arr[5] = {10, 20, 30, 40, 50};
    int n = 5;

    cout << "-- Duyet xuoi --" << endl;
    for (int i = 0; i < n; i++) {
        cout << "arr[" << i << "] = " << arr[i] << endl;
    }

    cout << "-- Duyet nguoc --" << endl;
    for (int i = n - 1; i >= 0; i--) {
        cout << "arr[" << i << "] = " << arr[i] << endl;
    }
    return 0;
}
```

**Output đã kiểm chứng:**

```
-- Duyet xuoi --
arr[0] = 10
arr[1] = 20
arr[2] = 30
arr[3] = 40
arr[4] = 50
-- Duyet nguoc --
arr[4] = 50
arr[3] = 40
arr[2] = 30
arr[1] = 20
arr[0] = 10
```

Lưu ý cú pháp duyệt ngược: khởi tạo `i = n - 1` (chỉ số cuối cùng hợp lệ, không phải `n`), điều kiện `i >= 0` (chạy đến khi `i` bằng 0 thì vẫn còn hợp lệ), và cập nhật `i--` (giảm dần).

### Ví dụ 2: Tìm kiếm tuyến tính — tìm phần tử đầu tiên bằng giá trị X (Mục tiêu: ứng dụng, biết dừng sớm đúng lúc)

```cpp
#include <iostream>
using namespace std;

int main() {
    int arr[6] = {5, 8, 2, 9, 1, 7};
    int target = 9;
    bool timThay = false;
    int viTri = -1;

    for (int i = 0; i < 6; i++) {
        if (arr[i] == target) {
            timThay = true;
            viTri = i;
            break;      // Tìm thấy rồi, dừng ngay không cần duyệt tiếp
        }
    }

    if (timThay)
        cout << "Tim thay: " << viTri << endl;
    else
        cout << "Khong tim thay" << endl;
    return 0;
}
```

**Output đã kiểm chứng khi `target = 9`:**

```
Tim thay: 3
```

**Output đã kiểm chứng khi đổi thành `target = 100`:**

```
Khong tim thay
```

Khi tìm `9`, chương trình dừng ngay tại chỉ số `3` — không cần kiểm tra tiếp `1` và `7` phía sau, dù chúng vẫn còn trong mảng. Khi tìm `100` (giá trị không tồn tại), vòng lặp buộc phải chạy hết toàn bộ mảng mà không bao giờ gặp `break`, kết thúc với `timThay` vẫn là `false`.

### Ví dụ 3: Đếm số phần tử chẵn — bắt buộc phải duyệt hết (Mục tiêu: phân biệt trường hợp không được dừng sớm)

```cpp
#include <iostream>
using namespace std;

int main() {
    int arr[8] = {3, 8, 15, 22, 7, 40, 11, 6};
    int n = 8;
    int demChan = 0;

    for (int i = 0; i < n; i++) {
        if (arr[i] % 2 == 0) {
            demChan++;
        }
    }
    cout << "So luong phan tu chan: " << demChan << endl;
    return 0;
}
```

**Output đã kiểm chứng:**

```
So luong phan tu chan: 4
```

Kết quả `4` là chính xác (các số chẵn trong mảng là `8, 22, 40, 6`). Ở đây **không hề có `break`** — vòng lặp bắt buộc phải xét đủ cả 8 phần tử, vì mỗi phần tử chẵn tìm được đều cần được cộng dồn vào biến đếm, không thể bỏ sót bất kỳ phần tử nào.

### Ví dụ 4: Minh chứng lỗi — đặt break nhầm chỗ trong bài toán đếm (Mục tiêu: khắc sâu sự phân biệt giữa dừng sớm và duyệt hết)

```cpp
#include <iostream>
using namespace std;

int main() {
    int arr[8] = {3, 8, 15, 22, 7, 40, 11, 6};
    int n = 8;
    int demSai = 0;

    for (int i = 0; i < n; i++) {
        if (arr[i] % 2 == 0) {
            demSai++;
            break;      // Lỗi: dừng luôn, không đếm hết được!
        }
    }
    cout << "Dem SAI (dung break nham): " << demSai << endl;
    return 0;
}
```

**Output đã kiểm chứng (trên cùng mảng `{3, 8, 15, 22, 7, 40, 11, 6}` như Ví dụ 3):**

```
Dem SAI (dung break nham): 1
```

Đây là bằng chứng rõ ràng nhất cho sự khác biệt đã nói ở phần lý thuyết: chỉ vì thêm nhầm một dòng `break` (thói quen mang từ bài tìm kiếm tuyến tính sang), kết quả đếm bị sai lệch nghiêm trọng — từ đáp án đúng là `4` tụt xuống chỉ còn `1`, vì chương trình dừng lại ngay khi gặp số chẵn **đầu tiên** (`8`) mà không hề biết đến `22, 40, 6` phía sau.

Điều rút ra: cần **một** kết quả thì được dừng sớm bằng `break`; cần kết quả **tổng hợp** (đếm, cộng tổng) thì phải duyệt hết, không `break`.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Mang thói quen dùng `break` từ bài toán tìm kiếm sang bài toán đếm/tổng hợp**: đây chính là lỗi đã minh chứng ở Ví dụ 4 — luôn tự hỏi "bài toán này cần MỘT kết quả (dừng được sớm) hay cần kết quả TỔNG HỢP từ toàn bộ mảng (phải duyệt hết)?" trước khi quyết định có dùng `break` hay không.
- **Nhầm lẫn cú pháp duyệt ngược**: quên đổi điều kiện thành `i >= 0` (thay vì `i > 0`, sẽ bỏ sót phần tử ở chỉ số 0), hoặc quên khởi tạo `i = n - 1` (thay vì `i = n`, sẽ gây lỗi truy cập ngoài phạm vi ngay từ vòng lặp đầu tiên). Ngoài ra, biến chạy của vòng duyệt ngược nên dùng kiểu `int`; nếu dùng kiểu không dấu như `size_t` thì `i >= 0` luôn đúng và vòng lặp không bao giờ dừng.
- **Không xử lý trường hợp "không tìm thấy" khi tìm kiếm tuyến tính**: như Ví dụ 2, luôn cần một biến cờ hiệu (`timThay`) để phân biệt rõ ràng giữa hai tình huống "tìm thấy ở chỉ số nào đó" và "duyệt hết mảng mà không thấy gì cả" — nếu chỉ dựa vào biến `viTri`, dễ nhầm lẫn giá trị mặc định ban đầu với một chỉ số hợp lệ thực sự.
- **Quên khởi tạo biến đếm về 0 trước khi duyệt**: nếu biến đếm (như `demChan`) không được khởi tạo `= 0` trước vòng lặp, giá trị ban đầu sẽ là rác không xác định, khiến kết quả đếm cuối cùng hoàn toàn sai lệch dù logic duyệt có đúng đến đâu.
- **Nghĩ rằng duyệt xuôi và duyệt ngược luôn cho cùng kết quả**: điều này chỉ đúng với các phép tính có tính giao hoán như tính tổng — nhưng với bài toán tìm kiếm (ví dụ tìm phần tử đầu tiên thỏa điều kiện), duyệt xuôi và duyệt ngược có thể trả về hai chỉ số hoàn toàn khác nhau nếu mảng có nhiều hơn một phần tử thỏa mãn.
