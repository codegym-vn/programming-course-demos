# Khai Báo Hàm (Function Declaration) Và Định Nghĩa Hàm (Function Definition)

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: **định nghĩa hàm** là viết đầy đủ phần thân hàm (code xử lý), còn **khai báo hàm** (prototype) chỉ là "báo trước" cho trình biên dịch biết hàm này tồn tại, tên gì, nhận tham số gì, trả về kiểu gì.
- Hiểu được lý do cần khai báo trước: C++ đọc code tuần tự từ trên xuống dưới, nên cần "biết trước" về một hàm nếu muốn gọi nó trước khi phần định nghĩa đầy đủ xuất hiện trong file.
- Nắm vững cú pháp khai báo: `int tinhTong(int a, int b);` — có dấu `;`, không có thân hàm.
- Biết được hai cách tổ chức code phổ biến, và hiểu vì sao cách tách riêng khai báo và định nghĩa thường được ưa chuộng hơn khi chương trình có nhiều hàm.
- Quan sát trình biên dịch đọc file và ghi nhớ các hàm bằng hoạt động mô phỏng.

## 2. Giới Thiệu

Ở bài "Cú pháp khai báo và gọi hàm", bạn đã quen với việc viết một hàm rồi gọi nó trong `main()`. Nhưng trong tất cả các ví dụ đó, hàm luôn được viết **trước** `main()` trong file — điều gì sẽ xảy ra nếu bạn muốn viết `main()` lên đầu file (để dễ đọc), còn các hàm chi tiết thì đặt ở phía dưới?

C++ đọc và biên dịch code theo đúng thứ tự từ trên xuống dưới, giống như đọc một cuốn sách. Nếu `main()` gọi đến một hàm mà trình biên dịch **chưa từng thấy qua** (vì hàm đó được định nghĩa ở dòng phía dưới), nó sẽ báo lỗi ngay lập tức — dù hàm đó thực sự có tồn tại trong file. Giải pháp cho vấn đề này chính là **khai báo hàm (function declaration)** — một lời "báo trước" ngắn gọn, giúp trình biên dịch yên tâm rằng hàm này sẽ được định nghĩa đầy đủ ở đâu đó phía sau.

## 3. Khái Niệm

- **Định nghĩa hàm (Function Definition)**: viết đầy đủ phần thân hàm, bao gồm toàn bộ logic xử lý bên trong dấu `{ }`.
- **Khai báo hàm (Function Declaration / Prototype)**: chỉ ghi tên hàm, kiểu trả về, và danh sách kiểu tham số, kết thúc bằng dấu `;` — hoàn toàn không có thân hàm.
- **Cú pháp khai báo**: `int tinhTong(int a, int b);` — lưu ý dấu chấm phẩy ở cuối, thay cho cặp dấu `{ }`.

## 4. Giải Thích

### 4.1. Vấn Đề: Gọi Hàm Trước Khi Được Định Nghĩa

```cpp
#include <iostream>
using namespace std;

int main() {
    int ketQua = tinhTong(3, 5);   // Goi ham nay...
    return 0;
}

int tinhTong(int a, int b) {   // ...nhung dinh nghia lai o DUOI!
    return a + b;
}
```

Vì trình biên dịch đọc từ trên xuống, khi gặp `tinhTong(3, 5)` trong `main()`, nó chưa hề "biết" đến sự tồn tại của hàm `tinhTong` — dù hàm này thực sự có mặt ở phía dưới trong cùng file.

### 4.2. Giải Pháp: Khai Báo Trước (Prototype)

```cpp
#include <iostream>
using namespace std;

int tinhTong(int a, int b);   // KHAI BAO - chi bao truoc, chua co than ham

int main() {
    int ketQua = tinhTong(3, 5);   // OK! Compiler da "biet" ham nay ton tai
    return 0;
}

int tinhTong(int a, int b) {   // DINH NGHIA day du, dat o duoi
    return a + b;
}
```

Dòng khai báo giống như một lời giới thiệu ngắn gọn: "sẽ có một hàm tên `tinhTong`, nhận vào hai số `int`, trả về một số `int` — chi tiết bên trong sẽ có sau". Nhờ vậy, `main()` có thể yên tâm gọi hàm này ngay, dù phần định nghĩa đầy đủ nằm ở phía dưới.

### 4.3. Hai Cách Tổ Chức Code Phổ Biến

**Cách 1**: Viết toàn bộ định nghĩa hàm đầy đủ trước `main()` — không cần khai báo riêng, vì đến khi `main()` gọi hàm, trình biên dịch đã đọc qua toàn bộ định nghĩa rồi.

**Cách 2**: Khai báo (prototype) tất cả các hàm ngay sau phần `#include`, rồi viết `main()`, và đặt phần định nghĩa đầy đủ của từng hàm ở phía dưới. Cách này thường gọn hơn khi chương trình có nhiều hàm — giúp `main()` luôn nằm ở gần đầu file, người đọc có thể nắm ngay được luồng chương trình tổng quát mà không cần cuộn qua hàng chục dòng định nghĩa hàm chi tiết trước.

## 5. Ví Dụ

Toàn bộ output và thông báo lỗi dưới đây đã được biên dịch, chạy thử thực tế (thông báo lỗi ghi theo g++) để đảm bảo tính chính xác.

### Ví dụ 1: Lỗi khi gọi hàm được định nghĩa ở dưới main() (Mục tiêu: thấy rõ vấn đề cần giải quyết)

```cpp
#include <iostream>
using namespace std;

int main() {
    int ketQua = tinhTong(3, 5);
    cout << "Tong: " << ketQua << endl;
}

int tinhTong(int a, int b) {
    return a + b;
}
```

**Thông báo lỗi biên dịch thực tế:**

```
error: 'tinhTong' was not declared in this scope
```

### Ví dụ 2: Giải pháp — khai báo (prototype) trước main() (Mục tiêu: nắm cú pháp khai báo cơ bản)

```cpp
#include <iostream>
using namespace std;

int tinhTong(int a, int b);   // KHAI BAO (prototype)

int main() {
    int ketQua = tinhTong(3, 5);
    cout << "Tong: " << ketQua << endl;
}

int tinhTong(int a, int b) {   // DINH NGHIA day du, dat sau main()
    return a + b;
}
```

**Output đã kiểm chứng:**

```
Tong: 8
```

Chỉ cần thêm đúng một dòng khai báo phía trên `main()`, lỗi ở Ví dụ 1 đã hoàn toàn biến mất.

### Ví dụ 3: Cách 1 — viết toàn bộ định nghĩa hàm trước main() (Mục tiêu: nắm cách tổ chức đơn giản nhất)

```cpp
#include <iostream>
using namespace std;

int tinhTong(int a, int b) {
    return a + b;
}

int tinhHieu(int a, int b) {
    return a - b;
}

void inKetQua(int tong, int hieu) {
    cout << "Tong: " << tong << ", Hieu: " << hieu << endl;
}

int main() {
    int a = 10, b = 4;
    inKetQua(tinhTong(a, b), tinhHieu(a, b));
}
```

**Output đã kiểm chứng:**

```
Tong: 14, Hieu: 6
```

Cách này không cần khai báo riêng — vì đến lúc `main()` được đọc, trình biên dịch đã "đi qua" toàn bộ định nghĩa của cả ba hàm rồi.

### Ví dụ 4: Cách 2 — khai báo nhiều hàm trước, định nghĩa đầy đủ đặt sau main() (Mục tiêu: thấy rõ lợi ích khi có nhiều hàm)

```cpp
#include <iostream>
using namespace std;

int tinhTong(int a, int b);
int tinhHieu(int a, int b);
void inKetQua(int tong, int hieu);

int main() {
    int a = 10, b = 4;
    inKetQua(tinhTong(a, b), tinhHieu(a, b));
}

int tinhTong(int a, int b) {
    return a + b;
}

int tinhHieu(int a, int b) {
    return a - b;
}

void inKetQua(int tong, int hieu) {
    cout << "Tong: " << tong << ", Hieu: " << hieu << endl;
}
```

**Output đã kiểm chứng:**

```
Tong: 14, Hieu: 6
```

Nhờ có phần khai báo ngay sau `#include`, `main()` được đặt ngay ở phần đầu file, dễ dàng nắm được luồng chương trình tổng quát trước khi đi vào chi tiết từng hàm ở phía dưới — đặc biệt hữu ích khi chương trình có nhiều hàm hơn. Hai ví dụ 3 và 4 là cùng một chương trình, chỉ khác cách sắp xếp.

### Ví dụ 5: Khai báo và định nghĩa lệch nhau — lỗi ở bước liên kết (Mục tiêu: tránh lỗi khó thấy)

```cpp
#include <iostream>
using namespace std;

int tinhTong(int a, int b);   // Khai bao: hai tham so int

int main() {
    cout << tinhTong(3, 5) << endl;
    return 0;
}

int tinhTong(double a, double b) {   // Dinh nghia: hai tham so double
    return a + b;
}
```

**Thông báo lỗi liên kết thực tế:**

```
undefined reference to `tinhTong(int, int)'
collect2: error: ld returned 1 exit status
```

Chương trình biên dịch qua được, vì `main()` chỉ cần lời báo trước `tinhTong(int, int)` là đủ. Nhưng đến bước **liên kết**, trình biên dịch phải nối lời báo trước đó với một thân hàm thật, mà thân hàm duy nhất trong file lại là `tinhTong(double, double)` — một hàm khác. Vì vậy báo lỗi `undefined reference`. (Với trình biên dịch khác, như clang, câu chữ thông báo có khác nhưng cùng loại lỗi.)

### Xem trình biên dịch ghi nhớ hàm, từng bước

Mô phỏng dưới đây đưa trình biên dịch vào vai người đọc file từ trên xuống, ghi các hàm đã biết vào một "danh bạ". Bấm **Bước tiếp** để chạy từng bước và để ý những điều mà chữ khó diễn tả:

- Tab **Gọi trước, định nghĩa sau**: mỗi nguyên mẫu thêm một thẻ "đã hứa" vào danh bạ, mỗi định nghĩa đóng dấu "có thân hàm". Khi gặp lời gọi, trình biên dịch tra danh bạ; sau khi đọc hết file còn có bước "Liên kết", kiểm tra mọi lời hứa đều có thân hàm.
- Tab **Cách 1 và Cách 2**: hai cột chạy song song, để thấy danh bạ ở Cách 1 đầy dần bằng thẻ "có thân hàm", còn ở Cách 2 đầy bằng thẻ "đã hứa" trước khi tới `main`, và `main` nằm ngay đầu file.
- Tab **Lỗi: khai báo lệch định nghĩa**: danh bạ có hai thẻ khác nhau vì kiểu tham số khác (`int` và `double`), thẻ "đã hứa" bị tô đỏ vì không có thân hàm, và lỗi chỉ hiện ở bước Liên kết chứ không phải lúc biên dịch.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Quên dấu chấm phẩy `;` ở cuối dòng khai báo**: khác với định nghĩa hàm (kết thúc bằng cặp `{ }`), khai báo hàm bắt buộc phải kết thúc bằng dấu `;` — quên dấu này sẽ khiến trình biên dịch hiểu nhầm đây là phần bắt đầu của một định nghĩa hàm.
- **Khai báo và định nghĩa không khớp nhau**: nếu phần khai báo và phần định nghĩa của cùng một hàm có kiểu tham số hoặc số lượng tham số khác nhau, chương trình sẽ gặp lỗi ở bước **liên kết (linking)**, không phải lỗi biên dịch thông thường — lỗi hiển thị dạng ``undefined reference to `tinhTong(int, int)'`` (xem Ví dụ 5). Đây là vì C++ coi hai chữ ký (signature) khác nhau là hai hàm khác nhau — trình biên dịch tìm mãi không thấy định nghĩa nào khớp chính xác với phần đã khai báo.
- **Không cần khai báo nếu đã tổ chức theo Cách 1**: nếu toàn bộ định nghĩa hàm đã được đặt trước `main()` (Ví dụ 3), việc thêm khai báo riêng là thừa và không cần thiết — chỉ cần khai báo khi định nghĩa đầy đủ nằm **sau** nơi hàm được gọi.
- **Tên tham số trong khai báo không cần trùng với định nghĩa**: về mặt kỹ thuật, C++ chỉ quan tâm đến **kiểu dữ liệu** của tham số trong phần khai báo, tên gọi cụ thể (`a`, `b` hay tên khác) không bắt buộc phải giống nhau giữa khai báo và định nghĩa, và có thể bỏ hẳn tên: `int tinhTong(int, int);` — dù vậy, giữ tên nhất quán vẫn là thói quen tốt, giúp code dễ đọc hơn.
- **Đặt phần khai báo ở vị trí không hợp lý**: khai báo hàm nên đặt ở một nơi mọi phần code cần gọi đến hàm đó đều có thể "nhìn thấy" được — thông thường là ngay sau phần `#include`, trước cả `main()`, để đảm bảo toàn bộ chương trình đều có thể gọi hàm này mà không gặp lỗi tương tự Ví dụ 1.
