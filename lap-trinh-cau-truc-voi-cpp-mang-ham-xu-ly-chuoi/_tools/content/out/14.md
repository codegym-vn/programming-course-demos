# Truyền Tham Số: Theo Giá Trị Và Theo Tham Chiếu

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: mặc định, C++ truyền tham số **theo giá trị (Pass by Value)** — hàm chỉ nhận được một **bản sao** của dữ liệu, không phải chính biến gốc.
- Nắm vững cú pháp: dùng dấu `&` để truyền tham số **theo tham chiếu (Pass by Reference)** — cho phép hàm làm việc trực tiếp trên biến gốc.
- Ứng dụng được vào bài toán kinh điển: viết hàm `swap` để đổi chỗ hai biến, và viết hàm "trả về" nhiều giá trị cùng lúc.
- Phân biệt được khi nào nên dùng truyền theo giá trị, khi nào nên dùng truyền theo tham chiếu.

## 2. Giới Thiệu

Ở bài "Sự khác biệt giữa Return và Print", bạn đã biết `return` chỉ có thể trả về **đúng một** giá trị mỗi lần gọi hàm. Nhưng nếu bạn cần một hàm làm được nhiều hơn thế — ví dụ đổi chỗ hai biến, hoặc tính ra cùng lúc cả giá trị nhỏ nhất lẫn lớn nhất — `return` một mình là không đủ.

Đây là lúc bạn cần hiểu một khái niệm rất đặc trưng của C++: theo mặc định, khi truyền một biến vào hàm, hàm đó chỉ nhận được một **bản sao** của giá trị — mọi thay đổi bên trong hàm hoàn toàn không ảnh hưởng gì đến biến gốc bên ngoài. Muốn hàm thực sự "chạm" được vào biến gốc, bạn cần dùng một cú pháp đặc biệt gọi là **tham chiếu (Reference)**, đánh dấu bằng ký hiệu `&`. Đây chính là "cánh cửa thứ hai" giúp hàm đưa dữ liệu ra ngoài, bên cạnh `return`.

## 3. Khái Niệm

- **Truyền theo giá trị (Pass by Value)**: cách truyền tham số mặc định trong C++ — hàm nhận được một **bản sao độc lập** của giá trị được truyền vào; mọi thay đổi trên bản sao đó không ảnh hưởng đến biến gốc.
- **Truyền theo tham chiếu (Pass by Reference)**: cách truyền tham số dùng ký hiệu `&` — hàm làm việc trực tiếp trên biến gốc, nên mọi thay đổi bên trong hàm sẽ tác động thực sự lên biến gốc đó.
- **Tham chiếu (Reference, `&`)**: một cách khác để "gọi tên" chính biến gốc, không phải là một bản sao riêng biệt.

## 4. Giải Thích

### 4.1. Truyền Theo Giá Trị — Mặc Định Của C++

```
void tenHam(int x) {   // Không có dấu &
    // x chỉ là BẢN SAO của biến được truyền vào
}
```

Khi gọi hàm này, giá trị của biến bên ngoài được "sao chép" vào tham số `x`. Mọi thay đổi trên `x` bên trong hàm chỉ ảnh hưởng đến bản sao đó — biến gốc bên ngoài hoàn toàn không hay biết gì.

### 4.2. Truyền Theo Tham Chiếu — Thêm Dấu &

```
void tenHam(int &x) {   // Có dấu & ngay sau kiểu dữ liệu
    // x bây giờ CHÍNH LÀ biến gốc, không phải bản sao
}
```

Chỉ cần thêm dấu `&` ngay sau kiểu dữ liệu của tham số, `x` bây giờ không còn là một bản sao nữa — nó trở thành một "cái tên khác" của chính biến gốc đã truyền vào. Mọi thay đổi trên `x` bên trong hàm sẽ phản ánh trực tiếp ra biến gốc ở nơi gọi hàm.

### 4.3. Khi Nào Nên Dùng Tham Chiếu?

Truyền theo tham chiếu đặc biệt hữu ích trong hai tình huống: (1) khi hàm cần **thực sự thay đổi** giá trị của biến gốc (như hàm `swap`), và (2) khi hàm cần "trả về" **nhiều hơn một** giá trị cùng lúc mà `return` không làm được.

## 5. Ví Dụ

Toàn bộ output dưới đây đã được biên dịch và chạy thử thực tế để đảm bảo tính chính xác.

### Ví dụ 1: Truyền theo giá trị — hàm không sửa được biến gốc (Mục tiêu: hiểu bản chất mặc định của C++)

```cpp
#include <iostream>
#include <string>
using namespace std;

void tangGap10(int x) {      // Không có dấu &
    x = x * 10;
    cout << "  Ben trong ham, x = " << x << endl;
}

int main() {
    int a = 5;
    cout << "Truoc khi goi ham, a = " << a << endl;
    tangGap10(a);
    cout << "Sau khi goi ham, a = " << a << " (KHONG doi!)" << endl;
}
```

**Output đã kiểm chứng:**

```
Truoc khi goi ham, a = 5
  Ben trong ham, x = 50
Sau khi goi ham, a = 5 (KHONG doi!)
```

Bên trong hàm, `x` đã được nhân lên `50`, nhưng biến `a` gốc ở `main()` vẫn giữ nguyên giá trị `5` — vì `x` chỉ là một bản sao độc lập, hoàn toàn tách biệt với `a`.

### Ví dụ 2: Truyền theo tham chiếu — hàm sửa được biến gốc (Mục tiêu: nắm cú pháp tham chiếu)

```cpp
#include <iostream>
#include <string>
using namespace std;

void tangGap10(int &x) {     // Có dấu &
    x = x * 10;
    cout << "  Ben trong ham, x = " << x << endl;
}

int main() {
    int a = 5;
    cout << "Truoc khi goi ham, a = " << a << endl;
    tangGap10(a);
    cout << "Sau khi goi ham, a = " << a << " (DA THAY DOI!)" << endl;
}
```

**Output đã kiểm chứng:**

```
Truoc khi goi ham, a = 5
  Ben trong ham, x = 50
Sau khi goi ham, a = 50 (DA THAY DOI!)
```

Chỉ khác duy nhất dấu `&` so với Ví dụ 1, nhưng kết quả hoàn toàn khác biệt: lần này biến `a` gốc thực sự bị thay đổi thành `50`, vì `x` bây giờ chính là một "cái tên khác" của `a`, không phải bản sao.

### Ví dụ 3: Hàm swap kinh điển — đổi chỗ hai biến (Mục tiêu: ứng dụng tham chiếu vào bài toán thực tế)

```cpp
#include <iostream>
#include <string>
using namespace std;

void swap(int &a, int &b) {
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int x = 10, y = 20;
    cout << "Truoc khi swap: x = " << x << ", y = " << y << endl;
    swap(x, y);
    cout << "Sau khi swap: x = " << x << ", y = " << y << endl;
}
```

**Output đã kiểm chứng:**

```
Truoc khi swap: x = 10, y = 20
Sau khi swap: x = 20, y = 10
```

Đây là ví dụ kinh điển nhất cho việc bắt buộc phải dùng tham chiếu: nếu `swap` dùng truyền theo giá trị thông thường, hàm sẽ chỉ đổi chỗ hai **bản sao** bên trong nó — hai biến `x`, `y` gốc ở `main()` sẽ không hề bị ảnh hưởng gì cả, và toàn bộ mục đích của hàm `swap` sẽ trở nên vô nghĩa.

### Ví dụ 4: Dùng tham chiếu để hàm "trả về" nhiều giá trị cùng lúc (Mục tiêu: ứng dụng khi return không đủ dùng)

```cpp
#include <iostream>
#include <string>
using namespace std;

void timMinMax(int arr[], int n, int &min, int &max) {
    min = arr[0];
    max = arr[0];
    for (int i = 1; i < n; i++) {
        if (arr[i] < min) min = arr[i];
        if (arr[i] > max) max = arr[i];
    }
}

int main() {
    int arr[6] = {8, 3, 9, 1, 7, 5};
    int giaTriMin, giaTriMax;

    timMinMax(arr, 6, giaTriMin, giaTriMax);

    cout << "Gia tri nho nhat: " << giaTriMin << endl;
    cout << "Gia tri lon nhat: " << giaTriMax << endl;
}
```

**Output đã kiểm chứng:**

```
Gia tri nho nhat: 1
Gia tri lon nhat: 9
```

Hàm `timMinMax` cần "trả về" cùng lúc cả hai kết quả (`min` và `max`) — điều mà `return` (chỉ trả về được một giá trị) không thể làm được. Bằng cách truyền `min` và `max` theo tham chiếu, hàm có thể ghi kết quả trực tiếp vào hai biến `giaTriMin` và `giaTriMax` ở `main()`, giải quyết gọn gàng bài toán "trả về nhiều giá trị". Riêng mảng `arr` thì không cần `&`: mảng không bị sao chép khi truyền vào hàm nên hàm vẫn làm việc trực tiếp trên mảng gốc (sẽ học kỹ ở Module sau).

### Ví dụ 5: So sánh trực tiếp cả hai cách trong cùng một chương trình (Mục tiêu: khắc sâu sự khác biệt)

```cpp
#include <iostream>
#include <string>
using namespace std;

void theoGiaTri(int x) {
    x += 100;
}

void theoThamChieu(int &x) {
    x += 100;
}

int main() {
    int a = 1, b = 1;

    theoGiaTri(a);
    theoThamChieu(b);

    cout << "Sau ham theo GIA TRI: a = " << a << endl;
    cout << "Sau ham theo THAM CHIEU: b = " << b << endl;
}
```

**Output đã kiểm chứng:**

```
Sau ham theo GIA TRI: a = 1
Sau ham theo THAM CHIEU: b = 101
```

Cả `a` và `b` đều bắt đầu bằng `1`, và cả hai hàm đều thực hiện chính xác cùng một phép tính (`+= 100`) — nhưng chỉ có `b` thực sự bị thay đổi thành `101`, vì hàm `theoThamChieu` nhận tham số theo tham chiếu. Đây là bằng chứng rõ ràng nhất, đặt cạnh nhau trong cùng một chương trình, cho sự khác biệt cốt lõi giữa hai cách truyền tham số.

### Xem truyền tham số từng bước

Mô phỏng dưới đây vẽ mỗi hàm đang chạy thành một khung riêng, cạnh khung `main()`. Bấm **Bước tiếp** để chạy từng dòng code và để ý những điều mà chữ khó diễn tả:

- Tab **Tham trị và tham chiếu**: với tham trị, khung hàm có thêm một hộp `x` mới (hộp này mất khi hàm kết thúc); với tham chiếu, khung hàm không có hộp nào, chỉ có nhãn cam "bí danh" dán lên hộp `b` của `main()`.
- Tab **Hoán đổi hai biến**: bản thiếu `&` đổi chỗ xong thì khung đóng và `x`, `y` vẫn như cũ; bản có `&` thì mỗi lệnh `a = b;` và `b = temp;` làm hộp `x`, `y` của `main()` đổi ngay.
- Tab **Trả về hai giá trị**: hai hộp `giaTriMin`, `giaTriMax` đang là "?" và được hàm cập nhật thẳng qua từng vòng lặp.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Quên dấu `&` khi cần hàm thay đổi biến gốc**: đây là lỗi phổ biến nhất — nếu mục đích của hàm là sửa đổi dữ liệu gốc (như `swap`), nhưng lại quên thêm `&` vào tham số, hàm sẽ chạy không báo lỗi gì cả, nhưng biến gốc sẽ **không hề thay đổi** như mong đợi (giống lỗi tương tự ở Ví dụ 1).
- **Dùng tham chiếu khi không thực sự cần thiết**: nếu hàm chỉ cần **đọc** giá trị để tính toán mà không cần sửa đổi gì (như hàm `tinhTong` ở các bài trước), truyền theo giá trị thông thường vẫn là lựa chọn an toàn và rõ ràng hơn — chỉ dùng tham chiếu khi thực sự cần hàm ghi dữ liệu ngược trở lại biến gốc.
- **Nhầm lẫn về "hai cách để hàm trả kết quả ra ngoài"**: `return` phù hợp khi hàm chỉ cần trả về đúng một giá trị làm "kết quả chính". Tham chiếu phù hợp khi cần trả về nhiều giá trị cùng lúc, hoặc khi cần thay đổi trực tiếp dữ liệu đã có sẵn (như `swap`) mà không tạo ra giá trị mới nào cả.
- **Quên rằng đối số truyền vào tham số tham chiếu bắt buộc phải là một biến**: khác với truyền theo giá trị (có thể truyền thẳng một con số như `tinhTong(5, 3)`), tham số tham chiếu `int &x` yêu cầu đối số phải là một **biến thực sự** có thể ghi đè được — gọi `tangGap10(5)` hoặc truyền một biểu thức như `tangGap10(a + 1)` sẽ gây lỗi biên dịch (g++ báo: `cannot bind non-const lvalue reference of type 'int&' to an rvalue of type 'int'`).
- **Không phân biệt được khi đọc code của người khác**: khi thấy dấu `&` trong danh sách tham số của một hàm, hãy luôn hiểu đó là tín hiệu cho biết hàm này có khả năng **thay đổi** dữ liệu bạn truyền vào — một điểm cần đặc biệt lưu ý khi gọi hàm đó, khác hẳn với các tham số thông thường chỉ được "đọc" mà không bị ảnh hưởng.
