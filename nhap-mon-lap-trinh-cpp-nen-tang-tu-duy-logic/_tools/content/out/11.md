# Câu Lệnh If Lồng Nhau Nested If

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: nhận ra khi nào một điều kiện thứ hai chỉ có ý nghĩa nếu điều kiện thứ nhất đã Đúng — đây chính là lúc cần đặt `if` bên trong `if`.
- Nắm vững cú pháp if lồng nhau (nested if) trong C++.
- Phân biệt rõ ràng if lồng nhau với if bậc thang (`else if`) — khi nào nên dùng cái nào.
- Tránh được lỗi sai kinh điển: **dangling else** (else bị gắn nhầm vào if gần nhất).
- Ứng dụng được vào các bài toán thực tế có nhiều lớp điều kiện phụ thuộc lẫn nhau: kiểm tra điều kiện chơi trò chơi, đăng nhập nhiều lớp, xét học bổng.

## 2. Giới Thiệu

Ở các bài trước, `if` và `if...else` giúp chương trình chọn đường theo một điều kiện. Nhưng có một dạng bài toán khác: đôi khi điều kiện thứ hai **chỉ có ý nghĩa** khi điều kiện thứ nhất đã được thỏa mãn trước.

Ví dụ: để được chơi tàu lượn siêu tốc, bạn cần đủ tuổi **và** đủ chiều cao — nhưng việc kiểm tra chiều cao chỉ thực sự cần thiết sau khi đã xác nhận đủ tuổi. Đây chính là lúc **if lồng nhau (Nested if)** phát huy tác dụng: đặt một câu lệnh `if` hoàn chỉnh bên trong khối lệnh của một câu lệnh `if` khác, tạo thành các lớp điều kiện phụ thuộc lẫn nhau.

## 3. Khái Niệm

- **If lồng nhau (Nested if)**: cấu trúc điều kiện trong đó một câu lệnh `if` (hoặc `if...else`) hoàn chỉnh được đặt bên trong khối lệnh của một câu lệnh `if` khác.
- **Điều kiện phụ thuộc (Dependent condition)**: điều kiện chỉ cần được kiểm tra khi một điều kiện khác trước đó đã Đúng — đặc trưng của bài toán cần dùng if lồng nhau.
- **Dangling else**: lỗi kinh điển xảy ra khi có nhiều `if` lồng nhau mà thiếu dấu ngoặc nhọn `{ }`, khiến `else` bị trình biên dịch gắn vào `if` gần nhất (thường không phải ý định ban đầu của người viết code).

## 4. Giải Thích

### 4.1. Cú Pháp If Lồng Nhau

```cpp
if (điều_kiện_1)
{
    // Chỉ vào được đây nếu điều_kiện_1 ĐÚNG
    if (điều_kiện_2)
    {
        // Chỉ chạy nếu CẢ điều_kiện_1 VÀ điều_kiện_2 đều ĐÚNG
    }
    else
    {
        // Chạy nếu điều_kiện_1 ĐÚNG nhưng điều_kiện_2 SAI
    }
}
else
{
    // Chạy nếu điều_kiện_1 đã SAI ngay từ đầu
    // (điều_kiện_2 không bao giờ được kiểm tra trong trường hợp này)
}
```

Điểm mấu chốt: khối lệnh bên trong `if (điều_kiện_1)` chứa một cấu trúc `if...else` hoàn chỉnh khác — đây chính là ý nghĩa của từ "lồng nhau".

### 4.2. Phân Biệt If Lồng Nhau Và If Bậc Thang

Đây là điểm nhiều người mới học hay nhầm lẫn:

| Tiêu chí | If bậc thang (else if) | If lồng nhau (Nested if) |
| --- | --- | --- |
| Bản chất điều kiện | Nhiều mức độ của cùng một điều kiện (ví dụ điểm số) | Nhiều điều kiện độc lập nhưng phụ thuộc lẫn nhau để kiểm tra |
| Số điều kiện được kiểm tra | Dừng lại ngay khi gặp điều kiện Đúng đầu tiên | Điều kiện sau chỉ được kiểm tra nếu điều kiện trước đã Đúng |
| Ví dụ điển hình | Xếp loại Giỏi/Khá/Trung bình/Yếu theo điểm | Đủ tuổi và đủ chiều cao để chơi trò chơi |

Nói ngắn gọn: dùng **if bậc thang** khi bạn đang phân loại một giá trị vào nhiều "khoảng" khác nhau; dùng **if lồng nhau** khi bạn cần kiểm tra điều kiện B chỉ sau khi điều kiện A đã xảy ra. (If bậc thang sẽ được học kỹ ở bài sau.)

### 4.3. Cạm Bẫy "Dangling Else"

Khi if lồng nhau mà thiếu dấu ngoặc nhọn `{ }`, một `else` có thể bị trình biên dịch gắn vào `if` gần nó nhất — dù cách bạn thụt đầu dòng khiến nó trông giống như đang thuộc về `if` phía ngoài. Đây là lý do quan trọng nhất khiến việc luôn dùng `{ }` với if lồng nhau trở thành bắt buộc, không chỉ là khuyến nghị. Chi tiết minh họa ở Ví dụ 2.

## 5. Ví Dụ

Toàn bộ output dưới đây là kết quả khi biên dịch và chạy thử bằng g++.

### Ví dụ 1: Kiểm tra điều kiện chơi tàu lượn siêu tốc (Mục tiêu: nắm cú pháp if lồng nhau)

```cpp
void kiemTra(int tuoi, int chieuCao) {
    if (tuoi >= 12) {
        if (chieuCao >= 140) {
            cout << "Duoc choi tau luon!" << endl;
        } else {
            cout << "Chua du chieu cao." << endl;
        }
    } else {
        cout << "Chua du tuoi." << endl;
    }
}
```

**Output với 3 trường hợp:**

```
Tuoi=15, ChieuCao=130 -> Chua du chieu cao.
Tuoi=10, ChieuCao=150 -> Chua du tuoi.
Tuoi=15, ChieuCao=150 -> Duoc choi tau luon!
```

Lưu ý quan trọng: khi `tuoi=10` (chưa đủ tuổi), chương trình **không hề kiểm tra** điều kiện chiều cao nữa — nó nhảy thẳng vào nhánh `else` ngoài cùng ngay lập tức. Đây chính là bản chất của "điều kiện phụ thuộc": chiều cao chỉ được xét đến khi tuổi đã đạt yêu cầu.

### Ví dụ 2: Dangling else — cạm bẫy nguy hiểm nhất của if lồng nhau (Mục tiêu: tránh lỗi sai)

```cpp
int a = -5, b = 3;
if (a > 0)
    if (b > 0)
        cout << "Ca hai duong" << endl;
else
    cout << "a khong duong" << endl;
```

**Output (với** `a = -5`**, tức điều kiện ngoài đã Sai):**

```
(không in ra dòng nào cả)
```

Đây chính là cái bẫy: nhìn vào cách thụt đầu dòng, người viết code có thể tưởng rằng `else` này thuộc về `if (a > 0)` — tức là mong đợi nó sẽ in ra "a khong duong" khi `a` không dương. Nhưng thực tế, C++ luôn gắn `else` vào `if` **gần nhất chưa có** `else` — trong trường hợp này là `if (b > 0)`. Vì vậy khi `a = -5` (điều kiện ngoài Sai), toàn bộ khối `if (b > 0) ... else ...` không bao giờ được chạy tới, nên không có gì được in ra cả — trái với kỳ vọng ban đầu của người viết code.

Đáng chú ý, khi biên dịch với cờ cảnh báo `-Wall`, g++ phát hiện và cảnh báo nguy cơ này:

```
warning: suggest explicit braces to avoid ambiguous 'else' [-Wdangling-else]
```

Nếu thêm dấu ngoặc nhọn `{ }` rõ ràng cho từng khối `if`, sự mơ hồ này sẽ hoàn toàn biến mất và code sẽ chạy đúng như ý định của người viết:

```cpp
if (a > 0) {
    if (b > 0) {
        cout << "Ca hai duong" << endl;
    }
} else {
    cout << "a khong duong" << endl;
}
```

Với `a = -5`, đoạn code này in ra `a khong duong`, đúng ý người viết.

### Ví dụ 3: Đăng nhập hai lớp — kiểm tra tên đăng nhập rồi mới đến mật khẩu (Mục tiêu: ứng dụng thực tế)

```cpp
void dangNhap(string username, string password) {
    if (username == "admin") {
        if (password == "1234") {
            cout << "Dang nhap thanh cong!" << endl;
        } else {
            cout << "Sai mat khau." << endl;
        }
    } else {
        cout << "Sai ten dang nhap." << endl;
    }
}
```

**Output với 3 trường hợp:**

```
user=guest pass=1234 -> Sai ten dang nhap.
user=admin pass=wrong -> Sai mat khau.
user=admin pass=1234 -> Dang nhap thanh cong!
```

Đây là ví dụ minh họa rất tự nhiên cho if lồng nhau: chỉ khi tên đăng nhập đã đúng (`admin`), chương trình mới cần bận tâm kiểm tra tiếp mật khẩu — nếu tên đăng nhập đã sai (`guest`), việc kiểm tra mật khẩu là hoàn toàn vô nghĩa và bị bỏ qua ngay lập tức.

### Ví dụ 4: Xét học bổng theo điểm trung bình và hạnh kiểm (Mục tiêu: ứng dụng thực tế)

```cpp
void xetHocBong(double diemTB, string hanhKiem) {
    if (diemTB >= 8.0) {
        if (hanhKiem == "Tot") {
            cout << "Hoc bong TOAN PHAN" << endl;
        } else {
            cout << "Hoc bong BAN PHAN" << endl;
        }
    } else {
        cout << "Khong du dieu kien hoc bong" << endl;
    }
}
```

**Output với 3 trường hợp:**

```
DiemTB=9 HanhKiem=Tot -> Hoc bong TOAN PHAN
DiemTB=8.5 HanhKiem=Kha -> Hoc bong BAN PHAN
DiemTB=7 HanhKiem=Tot -> Khong du dieu kien hoc bong
```

Ví dụ này cho thấy rõ: dù hạnh kiểm có "Tốt" đến đâu, nếu điểm trung bình chưa đạt 8.0, chương trình sẽ không bao giờ đi vào bước kiểm tra hạnh kiểm nữa (như trường hợp thứ ba) — hạnh kiểm chỉ thực sự được xét đến sau khi điều kiện điểm số đã được thỏa mãn.

### Xem hai cổng kiểm tra và dangling else chạy từng bước

Mô phỏng dưới đây chạy lại Ví dụ 1 và Ví dụ 2. Bấm **Bước tiếp**:

- Tab **Tàu lượn: 3 cặp (tuổi, chiều cao)**: chọn từng cặp gợi ý. Đèn cổng Tuổi và cổng Chiều cao sáng xanh hoặc đỏ; khi cổng Tuổi đỏ, cổng Chiều cao tắt hẳn với nhãn "không kiểm tra" và các dòng code bên trong hiện mờ.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Thiếu dấu ngoặc nhọn** `{ }` **khi if lồng nhau nhiều lớp**: đây là nguyên nhân trực tiếp gây ra lỗi dangling else (xem lại Ví dụ 2) — `else` sẽ tự động gắn vào `if` gần nhất chưa có `else`, có thể khác hoàn toàn với ý định của người viết code.
- **Nhầm lẫn if lồng nhau với if bậc thang**: nếu bạn đang cố xếp một giá trị vào nhiều "khoảng" khác nhau (ví dụ điểm số), hãy dùng if bậc thang; chỉ dùng if lồng nhau khi điều kiện thứ hai thực sự phụ thuộc vào việc điều kiện thứ nhất đã đúng hay chưa.
- **Lồng quá nhiều lớp if khiến code khó đọc**: nếu bạn thấy mình đang lồng từ 3-4 lớp `if` trở lên, đây thường là dấu hiệu nên cân nhắc kết hợp điều kiện bằng toán tử logic `&&` (ví dụ `if (tuoi >= 12 && chieuCao >= 140)`) để code gọn gàng hơn, thay vì lồng quá sâu.
- **Quên rằng điều kiện bên trong không bao giờ được kiểm tra nếu điều kiện bên ngoài đã Sai**: đây là bản chất cốt lõi của if lồng nhau (đã minh họa ở Ví dụ 1 và 3), nhưng người mới học đôi khi lầm tưởng rằng cả hai điều kiện luôn được kiểm tra độc lập với nhau.
- **Thụt đầu dòng sai khiến code trông đúng nhưng chạy sai**: giống như dangling else, cách trình bày thụt đầu dòng chỉ mang tính trực quan cho người đọc — nó không quyết định cách trình biên dịch thực sự gắn kết các khối lệnh với nhau. Luôn dùng `{ }` rõ ràng để đảm bảo ý định của bạn khớp với cách trình biên dịch hiểu.
