# Câu Lệnh điều kiện Switch Case

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: biết được khi nào nên dùng `switch` thay vì một chuỗi `if...else` dài dòng.
- Nắm vững cú pháp: hiểu rõ vai trò của 4 từ khóa `switch`, `case`, `break`, `default`.
- Tránh được lỗi sai phổ biến: hiểu cơ chế "trôi lệnh" (fall-through) xảy ra khi quên từ khóa `break`.
- Ứng dụng được vào các chương trình dạng menu thực tế (chọn món ăn, xác định ngày trong tuần...).

## 2. Giới Thiệu

Hãy tưởng tượng bạn viết một chương trình máy bán nước tự động. Nếu dùng `if...else`, code sẽ trông như sau:

```cpp
if (nut_bam == 1) { /* Ban Cafe */ }
else if (nut_bam == 2) { /* Ban Nuoc Cam */ }
else if (nut_bam == 3) { /* Ban Tra Sua */ }
else if (nut_bam == 4) { /* Ban Sting */ }
```

Nhìn rất rối mắt và lặp lại — bạn phải viết đi viết lại từ khóa `else if` cho từng lựa chọn, dù bản chất chỉ là so sánh xem `nut_bam` có **bằng** một con số cụ thể nào đó hay không.

**Switch-case** sinh ra để giải quyết đúng bài toán này. Nó hoạt động giống như một bảng điều khiển: bạn "bấm nút" nào, máy sẽ nhảy ngay lập tức đến chức năng tương ứng, không cần so sánh lòng vòng qua từng điều kiện một.

## 3. Khái Niệm

- `switch (biến_kiểm_tra)`: "công tắc" chính, mở ra cấu trúc rẽ nhánh dựa trên giá trị của một biến — biến này thường là số nguyên (`int`) hoặc ký tự (`char`).
- `case giá_trị:`: "trường hợp" — nếu biến kiểm tra bằng đúng giá trị này, code sẽ bắt đầu chạy từ đây.
- `break;`: "phanh" — lệnh báo cho máy tính biết đã xong việc, cần thoát ngay khỏi `switch`.
- `default:`: "mặc định" — nhánh chạy khi không có `case` nào khớp với giá trị của biến (tương tự `else` cuối cùng trong `if...else`).
- **Fall-through (trôi lệnh)**: hiện tượng chương trình "trượt" từ một `case` xuống thẳng `case` tiếp theo mà không dừng lại, xảy ra khi thiếu `break`.

## 4. Giải Thích

### 4.1. Cú Pháp Cơ Bản

```
switch (biến_kiểm_tra)
{
    case giá_trị_1:
        // Các lệnh thực hiện nếu biến == giá_trị_1
        break; // Dừng lại, thoát ra ngoài

    case giá_trị_2:
        // Các lệnh thực hiện nếu biến == giá_trị_2
        break;

    default:
        // Thực hiện nếu KHÔNG khớp với case nào cả (giống else)
        break;
}
```

**Lưu ý quan trọng về kiểu dữ liệu:** biến đưa vào `switch` chỉ được phép là kiểu số nguyên (`int`, `char`, `enum`...) — **không** dùng được cho số thực (`float`, `double`) hoặc chuỗi (`string`). Chi tiết minh chứng ở Ví dụ 4.

### 4.2. Cảnh Báo Quan Trọng: Lỗi Quên "break"

Nếu bạn quên viết `break` ở cuối một `case`, máy tính sẽ mắc lỗi "trôi lệnh" (fall-through): sau khi chạy xong lệnh của `case` đó, nó sẽ **tự động trượt xuống chạy tiếp** `case` **ngay bên dưới**, mà không hề kiểm tra lại điều kiện. Đây là lỗi cực kỳ phổ biến với người mới học `switch` — chi tiết minh họa cụ thể ở Ví dụ 2.

### 4.3. Khi Nào Dùng switch? Khi Nào Dùng if...else?

| Tiêu chí | Switch – Case | If – Else |
|---|---|---|
| Mục đích | So sánh bằng (==) với các giá trị cụ thể | So sánh khoảng (>, <, >=) hoặc logic phức tạp |
| Kiểu dữ liệu | Chỉ dùng cho kiểu số nguyên (int, char, enum...) | Dùng được cho tất cả (số thực, chuỗi...) |
| Thẩm mỹ | Code đẹp, rõ ràng khi có nhiều nhánh (trên 3 nhánh) | Linh hoạt nhưng dễ rối nếu quá nhiều else if |
| Ví dụ điển hình | Menu game, phím bấm bàn phím, mã tỉnh thành | Xếp loại điểm số, tính lương thuế, kiểm tra đăng nhập |

## 5. Ví Dụ

Toàn bộ output và thông báo lỗi dưới đây đã được biên dịch, chạy thử thực tế bằng g++ để đảm bảo tính chính xác.

### Ví dụ 1: Menu chọn món ăn nhà hàng (Mục tiêu: nắm cú pháp switch – case – break – default)

```cpp
int choice;
cout << "MENU:\n1. Pizza\n2. Burger\n3. Salad\nBan chon mon so may (1-3)? ";
cin >> choice;

switch (choice) {
    case 1:
        cout << "Ban da chon: PIZZA";
        break;
    case 2:
        cout << "Ban da chon: BURGER";
        break;
    case 3:
        cout << "Ban da chon: SALAD";
        break;
    default:
        cout << "Xin loi, nha hang khong co mon nay!";
        break;
}
```

**Output đã kiểm chứng với 4 lựa chọn khác nhau:**

```
choice=1 -> Ban da chon: PIZZA
choice=2 -> Ban da chon: BURGER
choice=3 -> Ban da chon: SALAD
choice=5 -> Xin loi, nha hang khong co mon nay!
```

Với `choice = 5` (không khớp bất kỳ `case` nào), chương trình tự động nhảy vào nhánh `default` — đúng như vai trò "else cuối cùng" của nó.

### Ví dụ 2: Lỗi quên break — hiện tượng trôi lệnh (Mục tiêu: tránh lỗi sai)

```cpp
int hang = 1;
switch (hang) {
    case 1:
        cout << "Vang ";
        // Quen break o day!
    case 2:
        cout << "Bac ";
        break;
}
```

**Output đã kiểm chứng (dù** `hang = 1`**, chỉ nên khớp** `case 1`**):**

```
Vang Bac
```

Vì thiếu `break` sau `case 1`, chương trình không dừng lại mà "trượt" thẳng xuống chạy luôn `case 2` — dù giá trị của `hang` không hề bằng 2. Đây chính là lỗi "trôi lệnh" (fall-through) đã nói ở phần lý thuyết.

Đáng chú ý, nếu biên dịch với cờ cảnh báo mở rộng `-Wextra` (bao gồm `-Wimplicit-fallthrough`), g++ thực sự phát hiện và cảnh báo chính xác nguy cơ này:

```
warning: this statement may fall through [-Wimplicit-fallthrough=]
```

### Ví dụ 3: Cố tình gộp nhiều case dùng chung một xử lý — fall-through có chủ đích (Mục tiêu: hiểu sâu cơ chế break/fall-through)

Không phải lúc nào thiếu `break` cũng là lỗi — đôi khi lập trình viên **cố tình** xếp chồng nhiều `case` liên tiếp không có `break` giữa chúng, để nhiều giá trị cùng dùng chung một khối xử lý:

```cpp
char ch = 'e';
switch (ch) {
    case 'a':
    case 'e':
    case 'i':
    case 'o':
    case 'u':
        cout << "La nguyen am";
        break;
    default:
        cout << "La phu am";
        break;
}
```

**Output đã kiểm chứng với 3 ký tự khác nhau:**

```
ch='e' -> La nguyen am
ch='b' -> La phu am
ch='u' -> La nguyen am
```

Ở đây, năm dòng `case 'a'` đến `case 'u'` không có `break` ở giữa — nhưng đây hoàn toàn là chủ đích: bất kỳ ký tự nào trong 5 nguyên âm đều "trôi" xuống cùng một dòng lệnh `cout` duy nhất, rồi mới `break`. Đây là cách dùng fall-through hợp lý và rất phổ biến trong thực tế. Các `case` rỗng như vậy không bị g++ cảnh báo, vì chúng không chứa lệnh nào.

### Ví dụ 4: Vì sao switch không dùng được cho string hoặc float (Mục tiêu: hiểu bản chất và giới hạn kiểu dữ liệu)

```cpp
string mau = "do";
switch (mau) { // Cố dùng string cho switch
    case "do":
        cout << "Mau do";
        break;
}
```

**Thông báo lỗi biên dịch thực tế:**

```
error: switch quantity not an integer
```

Thử tương tự với `float diem = 8.5;` cũng cho ra **đúng thông báo lỗi giống hệt**: `switch quantity not an integer`. Đây là bằng chứng xác thực cho quy tắc đã nêu ở phần lý thuyết: `switch` trong C++ chỉ chấp nhận kiểu số nguyên (và `char`, `enum`), tuyệt đối không dùng được cho `string` hay các kiểu số thực.

### Ví dụ 5: Xác định tên ngày trong tuần theo số thứ tự (Mục tiêu: ứng dụng thực tế)

```cpp
int thu;
cout << "Nhap thu (1-7): ";
cin >> thu;

switch (thu) {
    case 1: cout << "Thu Hai"; break;
    case 2: cout << "Thu Ba"; break;
    case 3: cout << "Thu Tu"; break;
    case 4: cout << "Thu Nam"; break;
    case 5: cout << "Thu Sau"; break;
    case 6: cout << "Thu Bay"; break;
    case 7: cout << "Chu Nhat"; break;
    default: cout << "Khong hop le (chi nhan 1-7)";
}
```

**Output đã kiểm chứng với 3 giá trị nhập khác nhau:**

```
thu=3 -> Thu Tu
thu=7 -> Chu Nhat
thu=9 -> Khong hop le (chi nhan 1-7)
```

Đây là một ứng dụng thực tế rất điển hình của `switch` — với 7 giá trị cố định cần so sánh bằng, `switch` cho ra code rõ ràng và dễ đọc hơn nhiều so với việc viết 7 lần `else if` liên tiếp. Chú ý dòng `cin >> thu;`: nếu quên nhập giá trị cho `thu`, biến này mang giá trị không xác định và kết quả của `switch` không thể đoán trước.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Quên** `break` **ở cuối mỗi** `case` **(lỗi phổ biến nhất)**: như minh họa ở Ví dụ 2, thiếu `break` khiến chương trình "trôi lệnh" xuống case tiếp theo một cách không mong muốn. Luôn kiểm tra kỹ từng `case` trước khi hoàn thiện code, hoặc bật cờ cảnh báo `-Wextra` khi biên dịch để được nhắc nhở.
- **Nhầm lẫn giữa fall-through vô tình và có chủ đích**: không phải lúc nào thiếu `break` cũng là lỗi (xem Ví dụ 3) — nhưng nếu là chủ đích và `case` đó có chứa lệnh, hãy để lại một dòng comment ghi rõ ý định (ví dụ `// co tinh khong break, gop chung voi case duoi`). Từ C++17 có thể viết `[[fallthrough]];` đúng vị trí đó để vừa ghi rõ ý định, vừa tắt cảnh báo của trình biên dịch.
- **Cố dùng** `switch` **với kiểu dữ liệu không được hỗ trợ**: như minh chứng ở Ví dụ 4, dùng `string` hoặc `float`/`double` cho `switch` sẽ gây lỗi biên dịch ngay lập tức (`switch quantity not an integer`). Nếu cần so sánh chuỗi hoặc số thực, hãy quay về dùng `if...else`.
- **Quên nhánh** `default`: nếu không có `default`, và giá trị của biến không khớp bất kỳ `case` nào, chương trình sẽ đơn giản không làm gì cả và chạy tiếp — điều này đôi khi là chủ ý, nhưng cũng có thể là lỗi bị bỏ sót không lường trước, đặc biệt với các chương trình có dữ liệu đầu vào từ người dùng.
- **Cố dùng** `switch` **để so sánh khoảng giá trị (**`>`**,** `<`**)**: `switch` chỉ so sánh được sự **bằng nhau tuyệt đối** với từng giá trị cụ thể — nếu bài toán của bạn cần so sánh khoảng (ví dụ xếp loại điểm số theo nhiều mức), hãy dùng if bậc thang thay vì cố ép vào `switch`.
