# Toán Tử Điều Kiện (Ternary Operator)

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: biết "Toán tử 3 ngôi" là gì và tại sao nó lại có tên gọi như vậy.
- Nắm vững cú pháp: biết cách chuyển đổi từ `if...else` dài dòng sang dạng `?:` ngắn gọn.
- Ứng dụng được vào các bài toán đơn giản: kiểm tra chẵn/lẻ, đậu/rớt, chọn món ăn.
- Phân biệt được khi nào NÊN và khi nào KHÔNG NÊN dùng cách viết tắt này.

## 2. Giới Thiệu

Ở các bài trước, để đưa ra một quyết định đơn giản như "nếu trời mưa thì nghỉ, ngược lại thì đi học", bạn cần viết cả một khối `if...else` tốn từ 4-6 dòng code. Với những quyết định thực sự đơn giản — chỉ để gán một trong hai giá trị cho một biến — cách viết này có phần hơi "cồng kềnh".

C++ cung cấp một công cụ viết tắt cho đúng những tình huống này: **Toán tử điều kiện (Ternary Operator)**, thường được viết bằng ký hiệu `?:`. Nó cho phép bạn gói gọn toàn bộ logic "nếu đúng thì lấy A, nếu sai thì lấy B" chỉ trong đúng một dòng code duy nhất.

## 3. Khái Niệm

- **Toán tử điều kiện (Ternary Operator / Conditional Operator)**: toán tử duy nhất trong C++ cần đến 3 thành phần (toán hạng) để hoạt động — đây cũng chính là lý do nó được gọi là "toán tử 3 ngôi".
- **Ba thành phần của toán tử 3 ngôi**: (1) Điều kiện (câu hỏi Đúng/Sai), (2) Giá trị trả về nếu Đúng, (3) Giá trị trả về nếu Sai.
- **Dấu** `?`: đặt ngay sau điều kiện, mang ý nghĩa "có đúng không?".
- **Dấu** `:`: dùng để ngăn cách giữa phương án Đúng và phương án Sai, mang ý nghĩa "hoặc là".

## 4. Giải Thích

### 4.1. Cú Pháp Toán Tử 3 Ngôi

```
(Điều_kiện) ? Giá_trị_Đúng : Giá_trị_Sai;
```

Cách đọc: "Điều kiện này có đúng không? Nếu đúng, lấy Giá_trị_Đúng; nếu sai, lấy Giá_trị_Sai." Toàn bộ biểu thức này trả về **một giá trị duy nhất**, nên nó thường được dùng ngay trong phép gán, hoặc thậm chí đặt trực tiếp bên trong `cout`.

### 4.2. So Sánh: Khi Nào Nên Dùng Toán Tử 3 Ngôi?

Tuy viết ngắn gọn trông có vẻ "gọn gàng", nhưng không phải lúc nào toán tử 3 ngôi cũng là lựa chọn tốt:

| Tiêu chí | if...else (truyền thống) | Toán tử 3 ngôi (?:) |
|---|---|---|
| Độ dài code | Dài dòng (nhiều dòng) | Ngắn gọn (1 dòng) |
| Mức độ phức tạp | Xử lý được logic phức tạp, nhiều lệnh, lồng nhau | Chỉ nên dùng cho logic đơn giản, gán giá trị |
| Độ dễ đọc | Dễ đọc, rõ ràng luồng chạy | Khó đọc nếu điều kiện quá dài hoặc lồng nhiều lớp |
| Khi nào dùng | Khi cần thực hiện nhiều hành động (in màn hình, tính toán nhiều bước) | Khi chỉ cần gán nhanh một giá trị cho biến |

**Kết luận:** hãy dùng toán tử 3 ngôi khi bạn chỉ cần gán giá trị dựa trên MỘT điều kiện đơn giản. Với logic phức tạp hơn hoặc có nhiều bước xử lý, hãy quay về dùng `if...else` hoặc if bậc thang để code dễ đọc hơn.

## 5. Ví Dụ

Toàn bộ output dưới đây đã được biên dịch và chạy thử thực tế bằng g++ để đảm bảo tính chính xác.

### Ví dụ 1: Kiểm tra số Chẵn hay Lẻ — so sánh trực tiếp 2 cách viết (Mục tiêu: nắm cú pháp, chuyển đổi if-else sang ?:)

**Cách cũ (dùng if-else, tốn 6 dòng):**

```cpp
string result;
if (number % 2 == 0) {
    result = "So Chan";
} else {
    result = "So Le";
}
```

**Cách mới (dùng toán tử 3 ngôi, chỉ 1 dòng):**

```cpp
string result = (number % 2 == 0) ? "So Chan" : "So Le";
```

**Output đã kiểm chứng với 2 trường hợp:**

```
number=7 -> So Le
number2=8 -> So Chan
```

Cả hai cách viết cho ra kết quả giống hệt nhau, nhưng cách viết bằng `?:` rút gọn từ 6 dòng xuống còn đúng 1 dòng — minh chứng rõ ràng nhất cho lý do toán tử này được gọi là "phiên bản thu nhỏ của if-else".

### Ví dụ 2: Kiểm tra Đậu hay Rớt (Mục tiêu: ứng dụng thực tế)

```cpp
int diem = 8;
string xepLoai = (diem >= 5) ? "DAU" : "ROT";
cout << "Ket qua: " << xepLoai << endl;
```

**Output đã kiểm chứng:**

```
Ket qua: DAU
```

### Ví dụ 3: Chọn món ăn — kết hợp với toán tử logic || (Mục tiêu: ứng dụng thực tế)

```cpp
char luaChon;
cout << "Ban chon Salad (S) hay Pizza (P)? ";
cin >> luaChon;
// Nếu chọn 'S' hoặc 's' thì lấy "Salad", còn lại mặc định lấy "Pizza"
string monAn = (luaChon == 'S' || luaChon == 's') ? "Salad" : "Pizza";
cout << "Mon an: " << monAn << endl;
```

**Output đã kiểm chứng với 2 trường hợp nhập:**

```
luaChon='s' -> Mon an: Salad
luaChon='x' -> Mon an: Pizza
```

Ví dụ này cho thấy điều kiện bên trong dấu ngoặc `( )` của toán tử 3 ngôi có thể là bất kỳ biểu thức logic nào, kể cả khi nó kết hợp nhiều điều kiện bằng `&&` hoặc `||` — miễn là toàn bộ biểu thức đó vẫn trả về Đúng/Sai.

### Ví dụ 4: Dùng toán tử 3 ngôi ngay trong cout, không cần biến trung gian (Mục tiêu: ứng dụng thực tế)

```cpp
int tuoi = 10;
cout << "Gia ve: " << (tuoi < 12 ? 50000 : 100000) << " VND" << endl;
```

**Output đã kiểm chứng với 2 độ tuổi khác nhau:**

```
Tuoi 10 -> Gia ve: 50000 VND
Tuoi 25 -> Gia ve: 100000 VND
```

Đây là một cách dùng rất phổ biến: bạn không cần khai báo biến trung gian để lưu kết quả, mà có thể đặt cả biểu thức `?:` trực tiếp bên trong `cout`. Chú ý dấu ngoặc bao quanh biểu thức: `?:` có độ ưu tiên thấp, nên nếu thiếu ngoặc, trình biên dịch sẽ hiểu sai thứ tự và báo lỗi hoặc cho kết quả không như ý.

### Ví dụ 5: Toán tử 3 ngôi lồng nhau — trường hợp KHÔNG NÊN dùng (Mục tiêu: phân biệt khi nào nên và không nên dùng)

```cpp
int diem = 6;
(diem >= 8) ? cout << "Gioi" : (diem >= 5) ? cout << "Kha" : cout << "Yeu";
```

**Output đã kiểm chứng (biên dịch thành công, chạy đúng logic):**

```
Kha
```

Điều đáng chú ý: dòng code này **thực sự biên dịch và chạy đúng** (với `diem = 6`, kết quả `"Kha"` là chính xác vì `6 >= 5` nhưng `6 < 8`). Tuy nhiên, đây chính là ví dụ điển hình cho việc "chạy đúng không có nghĩa là nên viết như vậy" — chỉ cần nhìn thoáng qua, người đọc rất khó đoán được ngay luồng logic thực sự của dòng lệnh này. Với từ 3 mức phân loại trở lên, hãy luôn ưu tiên dùng if bậc thang (`if...else if...else`) để code rõ ràng và dễ bảo trì hơn nhiều.

### Xem if...else và ?: chạy cạnh nhau

Mô phỏng dưới đây chia hai cột: bên trái là `if...else`, bên phải là `?:`, cùng giải một bài toán. Chọn tab rồi bấm **Bước tiếp**:

- Tab **Chẵn/lẻ**: ở cột `?:`, ba phần của biểu thức được tô ba màu, và phần được chọn đi thẳng vào hộp `result` trong bộ nhớ. Hãy thử `number` = 7 và 8.
- Tab **Giá vé trong cout**: cột `if...else` phải tạo thêm biến `giaVe`, còn cột `?:` đặt giá trị thẳng vào `cout` mà không có biến trung gian nào trong bộ nhớ. Thử `tuoi` = 10 và 25.
- Tab **?: lồng nhau**: `?:` đánh giá từ trái sang phải, còn cột if bậc thang bên cạnh cho cùng kết quả "Kha" nhưng dễ đọc hơn. Mô phỏng dùng `string xepLoai = ...` thay vì `cout` để thấy rõ giá trị được chọn.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Lạm dụng toán tử 3 ngôi cho logic phức tạp**: như đã minh họa ở Ví dụ 5, việc lồng nhiều toán tử `?:` vào nhau tuy vẫn chạy đúng, nhưng khiến code cực kỳ khó đọc. Đây là lỗi phổ biến của những người mới học muốn code trông "ngầu" hơn là dễ hiểu.
- **Cố nhét nhiều hành động vào một nhánh của toán tử 3 ngôi**: toán tử 3 ngôi được thiết kế để **trả về một giá trị**, không phải để thực hiện nhiều lệnh liên tiếp. Nếu bạn cần làm nhiều việc trong một nhánh (ví dụ vừa tính toán vừa in ra nhiều dòng), hãy dùng `if...else` thay vì cố ép vào `?:`.
- **Quên rằng cả hai nhánh (Đúng/Sai) cần trả về kiểu dữ liệu tương thích nhau**: ví dụ nếu nhánh Đúng trả về một `string` còn nhánh Sai trả về một số nguyên, trình biên dịch có thể báo lỗi hoặc tự động ép kiểu theo cách không như ý muốn. Luôn đảm bảo cả hai nhánh trả về cùng một kiểu dữ liệu, hoặc các kiểu có thể tự động chuyển đổi qua lại một cách an toàn (ví dụ chuỗi ký tự và `std::string`).
- **Quên dấu ngoặc khi đặt** `?:` **trong** `cout`: `cout << (tuoi < 12 ? 50000 : 100000);` cần có ngoặc bao quanh biểu thức, vì `?:` có độ ưu tiên thấp hơn toán tử `<<`.
- **Nhầm lẫn thứ tự các thành phần trong cú pháp**: nhớ đúng thứ tự `(Điều_kiện) ? Giá_trị_Đúng : Giá_trị_Sai` — viết ngược thứ tự Đúng/Sai là lỗi logic khó phát hiện, vì chương trình vẫn biên dịch bình thường nhưng cho ra kết quả sai hoàn toàn.
- **Dùng toán tử 3 ngôi khi không cần gán giá trị**: nếu mục đích của bạn chỉ đơn thuần là thực hiện một hành động có điều kiện (ví dụ chỉ in ra một dòng chữ, không cần gán vào biến), `if` đơn giản vẫn thường là lựa chọn rõ ràng và dễ đọc hơn so với việc cố ép vào toán tử 3 ngôi.
