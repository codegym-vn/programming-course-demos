# Câu Lệnh If Bậc Thang if...else if...else

## 1. Mục Tiêu Bài Học

- Hiểu bản chất: nhận ra khi nào `if...else` 2 nhánh là không đủ, và cần một chuỗi điều kiện nối tiếp nhau như bậc thang.
- Nắm vững cú pháp `if...else if...else` chuẩn trong C++.
- Hiểu được tầm quan trọng của **thứ tự kiểm tra điều kiện** — máy tính luôn kiểm tra từ trên xuống dưới, và dừng lại ngay khi gặp điều kiện Đúng đầu tiên.
- Ứng dụng được vào các bài toán thực tế có nhiều mức phân loại: xếp loại học lực, phân loại chỉ số BMI, tính tiền theo bậc thang.

## 2. Giới Thiệu

Ở bài trước, bạn đã biết `if...else` giúp chương trình chọn giữa đúng 2 con đường: Đúng hoặc Sai. Nhưng cuộc sống không phải lúc nào cũng chỉ có 2 lựa chọn — hãy nghĩ đến việc xếp loại học lực: Giỏi, Khá, Trung bình, Yếu — đó là 4 mức, không phải 2.

Nếu chỉ dùng `if...else`, bạn sẽ phải viết những khối lệnh `if` lồng nhau rất rối rắm. Thay vào đó, C++ cho phép bạn nối tiếp nhiều điều kiện lại với nhau bằng `else if`, tạo thành một chuỗi kiểm tra giống như những **bậc thang** — máy tính sẽ bước qua từng bậc, kiểm tra điều kiện tại bậc đó, và dừng lại ngay khi tìm được bậc thang đầu tiên thỏa mãn.

## 3. Khái Niệm

- **If bậc thang (if...else if...else)**: cấu trúc điều kiện gồm nhiều nhánh liên tiếp, cho phép xử lý nhiều hơn 2 khả năng xảy ra — không chỉ là Đúng/Sai đơn thuần.
- `else if`: từ khóa kết hợp, cho phép kiểm tra thêm một điều kiện khác ngay sau khi điều kiện `if` (hoặc `else if`) trước đó bị Sai.
- **Kiểm tra tuần tự (Sequential evaluation)**: nguyên tắc hoạt động cốt lõi của if bậc thang — các điều kiện được kiểm tra lần lượt từ trên xuống dưới, và ngay khi một điều kiện Đúng được tìm thấy, toàn bộ các điều kiện phía sau sẽ **không còn được kiểm tra nữa**.
- **Nhánh** `else` **cuối cùng**: nhánh dự phòng, chỉ chạy khi tất cả các điều kiện `if` và `else if` phía trên đều Sai.

## 4. Giải Thích

### 4.1. Cú Pháp Cấu Trúc If Bậc Thang

```
if (điều_kiện_1)
{
    // Chạy nếu điều_kiện_1 ĐÚNG
}
else if (điều_kiện_2)
{
    // Chỉ kiểm tra điều_kiện_2 nếu điều_kiện_1 đã SAI
    // Chạy nếu điều_kiện_2 ĐÚNG
}
else if (điều_kiện_3)
{
    // Chỉ kiểm tra điều_kiện_3 nếu cả điều_kiện_1 và điều_kiện_2 đều SAI
}
else
{
    // Chạy khi TẤT CẢ các điều kiện phía trên đều SAI
}
```

Bạn có thể nối bao nhiêu `else if` tùy ý, nhưng chỉ được có **duy nhất một** `if` ở đầu và **tối đa một** `else` ở cuối cùng.

### 4.2. Nguyên Tắc Vàng: Thứ Tự Kiểm Tra Quyết Định Kết Quả

Đây là điểm khác biệt quan trọng nhất so với các cấu trúc điều kiện độc lập: máy tính kiểm tra các điều kiện **theo đúng thứ tự bạn viết**, từ trên xuống dưới. Ngay khi tìm thấy điều kiện đầu tiên là Đúng, nó sẽ chạy khối lệnh tương ứng và **bỏ qua hoàn toàn** tất cả các điều kiện còn lại — kể cả khi một điều kiện phía sau cũng đúng.

Điều này có nghĩa là: nếu bạn đặt các điều kiện sai thứ tự (ví dụ điều kiện "lỏng" đặt trước điều kiện "chặt"), chương trình có thể cho ra kết quả sai hoàn toàn dù cú pháp không hề có lỗi. Chi tiết minh họa ở Ví dụ 2.

## 5. Ví Dụ

Toàn bộ output dưới đây đã được biên dịch và chạy thử thực tế bằng g++ để đảm bảo tính chính xác.

### Ví dụ 1: Xếp loại học lực theo điểm số (Mục tiêu: nắm cú pháp if bậc thang)

```cpp
void xepLoai(double diem) {
    if (diem >= 8.0) {
        cout << diem << " -> Gioi" << endl;
    } else if (diem >= 6.5) {
        cout << diem << " -> Kha" << endl;
    } else if (diem >= 5.0) {
        cout << diem << " -> Trung binh" << endl;
    } else {
        cout << diem << " -> Yeu" << endl;
    }
}
```

**Output đã kiểm chứng với 4 trường hợp điểm khác nhau:**

```
9 -> Gioi
7.5 -> Kha
5.5 -> Trung binh
4 -> Yeu
```

Mỗi điểm dừng ở đúng một nhánh: ví dụ `7.5` dừng ở nhánh "Kha" và không xét thêm bậc nào bên dưới.

### Ví dụ 2: Lỗi đặt sai thứ tự điều kiện — cạm bẫy nguy hiểm nhất (Mục tiêu: hiểu tầm quan trọng của thứ tự kiểm tra)

```cpp
double diem = 9.0;
// Viết SAI thứ tự: điều kiện lỏng hơn đặt trước điều kiện chặt hơn
if (diem >= 5.0) {
    cout << "Dat" << endl;
} else if (diem >= 8.0) {
    cout << "Xuat sac" << endl;
}
```

**Output đã kiểm chứng (dù** `diem = 9.0`**, đáng lẽ phải in "Xuat sac"):**

```
Dat
```

Đây là lỗi cực kỳ nguy hiểm vì **không hề có lỗi biên dịch** — chương trình chạy hoàn toàn bình thường nhưng logic lại sai. Vì điều kiện `diem >= 5.0` đã Đúng ngay từ đầu, máy tính chạy vào nhánh "Dat" và không bao giờ có cơ hội kiểm tra điều kiện `diem >= 8.0` ở phía sau nữa — dù bản thân điều kiện đó cũng đúng. **Quy tắc rút ra:** khi xếp loại theo mức độ, luôn đặt điều kiện chặt nhất (khó thỏa mãn nhất) lên trước, như đã làm đúng ở Ví dụ 1.

### Ví dụ 3: Phân loại chỉ số khối cơ thể — BMI (Mục tiêu: ứng dụng thực tế)

```cpp
void xepLoaiBMI(double bmi) {
    if (bmi < 18.5) {
        cout << bmi << " -> Thieu can" << endl;
    } else if (bmi < 25.0) {
        cout << bmi << " -> Binh thuong" << endl;
    } else if (bmi < 30.0) {
        cout << bmi << " -> Thua can" << endl;
    } else {
        cout << bmi << " -> Beo phi" << endl;
    }
}
```

**Output đã kiểm chứng với 4 mức BMI khác nhau:**

```
17 -> Thieu can
22 -> Binh thuong
27.5 -> Thua can
32 -> Beo phi
```

Đây là ví dụ thực tế phổ biến trong các ứng dụng sức khỏe — với 4 mức phân loại rõ ràng, if bậc thang là công cụ tự nhiên và gọn gàng nhất để triển khai logic này.

### Ví dụ 4: Tính tiền điện theo bậc thang (Mục tiêu: ứng dụng thực tế, đúng nghĩa đen của "bậc thang")

Lưu ý: đây là bảng giá đơn giản hóa cho mục đích học tập, không phải biểu giá điện thực tế.

```cpp
double soKwh = 120;
double tienDien;

if (soKwh <= 50) {
    tienDien = soKwh * 1500;
} else if (soKwh <= 100) {
    tienDien = 50 * 1500 + (soKwh - 50) * 1800;
} else {
    tienDien = 50 * 1500 + 50 * 1800 + (soKwh - 100) * 2200;
}
cout << "Tien dien: " << tienDien << " VND" << endl;
```

**Output đã kiểm chứng với** `soKwh = 120`**:**

```
Tien dien: 209000 VND
```

50 số điện đầu tính giá 1500đ/kWh, 50 số tiếp theo tính giá 1800đ/kWh, phần còn lại tính giá 2200đ/kWh. Với 120 kWh, kết quả `209.000 VND` (= 50×1500 + 50×1800 + 20×2200) khác với việc tính đồng giá 2200đ cho toàn bộ 120 số.

### Xem if bậc thang chạy từng bước

Mô phỏng dưới đây cho giá trị cần xét "rơi" qua các điều kiện xếp chồng như những cửa lọc. Bấm **Bước tiếp** để xem máy dừng ở cửa nào:

- Tab **Xếp loại đúng thứ tự**: cửa sai hiện ✗, cửa đúng hiện ✓, các cửa bên dưới mờ đi với nhãn "không xét". Hãy thử các điểm 9, 5.5, 4 và hai giá trị biên 8.0, 6.5 để thấy dấu `>=` tính cả chính mốc đó.
- Tab **Sai thứ tự**: cửa `diem >= 8.0` bị đánh dấu "không bao giờ xét" dù 9 >= 8; sau đó cửa chặt được đưa lên trên và kết quả đúng.

## 6. Phần Chú Ý Và Lỗi Hay Gặp

- **Đặt sai thứ tự các điều kiện (lỗi nghiêm trọng nhất)**: như đã minh họa ở Ví dụ 2, đặt điều kiện "lỏng" trước điều kiện "chặt" sẽ khiến các nhánh phía sau không bao giờ được chạy tới, dù không hề có lỗi biên dịch. Luôn kiểm tra kỹ thứ tự logic trước khi chạy thử.
- **Quên rằng chỉ một nhánh duy nhất được thực thi**: nhiều người mới học nhầm tưởng if bậc thang sẽ kiểm tra và chạy tất cả các điều kiện đúng — thực ra chỉ có **đúng một nhánh** (nhánh đầu tiên thỏa mãn) được chạy, các nhánh còn lại bị bỏ qua hoàn toàn, kể cả khi chúng cũng đúng.
- **Thiếu nhánh** `else` **cuối cùng khi cần xử lý "trường hợp còn lại"**: nếu bạn không thêm `else` ở cuối, và không có điều kiện nào ở trên đúng, chương trình sẽ không làm gì cả và tiếp tục chạy các dòng phía sau — điều này đôi khi là chủ ý, nhưng đôi khi lại là lỗi bị bỏ sót không lường trước.
- **Viết quá nhiều bậc thang thay vì cân nhắc** `switch case`: khi số lượng nhánh quá nhiều (ví dụ trên 5-6 nhánh) và các điều kiện là so sánh bằng nhau với các giá trị cụ thể (không phải khoảng giá trị), cấu trúc `switch case` (sẽ học ở các bài sau) thường sẽ gọn gàng và dễ đọc hơn if bậc thang.
- **Nhầm lẫn giữa if bậc thang và if lồng nhau (nested if)**: if bậc thang dùng để kiểm tra nhiều mức độ của **cùng một loại điều kiện** (ví dụ nhiều mức điểm số), trong khi if lồng nhau (đã học ở bài trước) dùng khi điều kiện thứ hai chỉ cần xét sau khi điều kiện thứ nhất đã đúng.
